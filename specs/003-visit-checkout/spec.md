# 离店结算与下次安排

**阶段计划 · 2026-11-25**　目标是让前台和患者打开同一笔已结束的就诊，就能核对本次实际处置、已收和待付或应退金额，以及下次预约是否成立。范围包括前台网页、患者网页和患者小程序。实施项与检查见[验收任务](tasks.md)，字段和动作见[离店接口](contracts/checkout.md)。下表保留隔离库的预期金额。

## 为什么先做这件事

| 已有实现 | 离店时仍然遇到的问题 |
| --- | --- |
| [就诊回查](../../portal/visit_review.py)已有已发布处置、账单版本、待付、应退和复诊指示。[账单详情](../../care/invoice_queries.py)已有实际收退和当前余额。 | 患者在就诊页看到待付金额，要另开账单才能知道这次收了多少、退了多少、是否用过预收款抵扣。 |
| [前台预约详情](../../templates/visit_detail.html)可以打开结算单。[复诊指示](../../clinical/next_visits.py)与预约有明确关联。 | 前台在同一笔就诊上还看不到结算结果与下次安排的并列摘要，难以当面和患者逐项核对。 |
| [患者网页](../../templates/portal/visit_review.html)和[小程序](../../clients/wechat/miniprogram/utils/visit-review.js)都能显示有关联的预约。服务端在没有有效预约时也可以返回上一笔历史记录。 | 一笔已取消的预约仍有编号并可打开。界面需要让患者一眼分清“这次还要重新安排”和“下次已约好”。 |

## 一笔就诊的产品要求

| 编号 | 要回答的问题 | 可观察的结果 |
| --- | --- | --- |
| LC1 | 这次究竟做了什么？ | 患者看到已发布的实际处置，阶段治疗列明“本阶段已处理，本次不另收费”。只发药时单列实际发退药。账单尚未发布时显示“结算单待发布”，金额保持空缺。前台仅取已获授权的结算和安排信息。 |
| LC2 | 已收、已退、待付分别是多少？ | 同屏显示当前账单编号、版本、总额、已记账收款、已记账退款及待付或应退。有预收抵扣、已核对的医保承担或待复核事项时分别说明。待审核退款保留“待复核”，直到正式记账才更新已退金额。历史版本显示当版项目和金额，余额标明所属当前版本。 |
| LC3 | 我下次什么时候来？ | 按每一条明确的医师指示分别展示。已约显示日期、时间、门店和有效预约号，改期打开后继。取消且无后继显示“待重新安排”，原编号放在历史。仅有有效建议时展示建议窗口，服务端允许自助才提供查号。未约且窗口已过，或依据已变化时，提供原门店联系方式。依据变化时仍可回查已有的有效预约。目标已核对或指示已撤回时提供历史回查。没有指示时只写“本次未记录复诊安排”。 |
| LC4 | 谁能查、能办到哪一步？ | 患者本人看自己的账单和安排。本店前台沿用现有权限和收退款申请入口，沿用独立审核。预约代办保留其获授权的预约，医疗代理回到既有医疗授权范围，两者均不取得本人离店账务。跨门店、其他患者和撤权后重新打开均按原权限拒绝。刷新、返回、切换就诊人时清除旧姓名、编号和金额。 |

业务规则复用[余额计算](../../finance/cash_selectors.py)、[已记账收退款](../../finance/patient_cash.py)及[报告复诊动作](../../portal/report_followup.py)。后端在同一读取时点汇总。网页和小程序直接显示服务端给出的金额、动作和编号。患者接口优先给现有 `review.settlement`、`review.followups` 增加可选字段，具体字段名在候选版本冻结。老客户端可继续读取原字段，新客户端遇到缺项沿用现有账单详情。预计沿用现有数据表、预约和资金命令。

## 工作顺序

| 顺序与负责人 | 任务 | 完成这个环节的依据 |
| --- | --- | --- |

| 2 · Codex，和 18547 并行 | 实现并冻结两种权限下的只读数据。前台从“本店就诊记录”查看“离店核对”，患者从原就诊详情查看“本次费用与下次安排”。复用现有账单、预约详情和原门店联系入口。 | 前台网页、患者网页、患者接口按相同的就诊编号对账。用 PostgreSQL 检查并发更正、拒绝访问及查阅前后的业务记录，用浏览器走完实际返回路径。 |
| 3 · WorkBuddy，下批交接后开始 | 在患者现有“就诊”页接入摘要。与 18547 的“这次复诊为什么来”区分方向，将下次安排放在已结束的原就诊下。保留既有导航、角色选择及手动登录。 | Codex 先提供接上 18547 原生改动的准确提交、可运行地址、带校验的包、接口例子、样本和包外私有账号指南。WorkBuddy 直接从本人、预约代办、医疗代理和另一患者四个账号复测，只查阅已备样本。 |
| 4 · Codex 集成，双端复验 | 对同一发布候选检查账单、更正后版本、改期后继、角色切换与返回。真实手机关闭调试，从扫码、登录、查阅到返回逐项取证。 | 记录浏览器、开发者工具、真机和准确提交 CI 各自的结果。通过双端和关闭调试的真机验收后，才更新共享试用入口。 |

## 隔离库样本与验收

以下是拟造的合成样本及预期数值，金额单位为元。准备样本时由 Codex 记录真实生成的编号。前台、患者网页和小程序用同一份清单。

| 样本 | 费用预期 | 复诊或界面预期 |
| --- | --- | --- |
| A · 已结清、已改期 | 账单 100.00，已收 100.00，已退 0.00，待付和应退均为 0.00。 | 打开有效后继预约，一次返回原就诊。旧预约标记为已改期。 |
| B · 部分付款、尚待安排 | 账单 300.00，已收 100.00，已抵扣预收 50.00，待付 150.00。 | 只有日期窗口时显示“尚未预约”。窗口内可查号的样本只做到预览。 |
| C · 账单更正、退款待复核与已记账 | V1 为 200.00，已收 200.00。V2 为 160.00。退款申请待复核时，已退 0.00、应退 40.00。另备已记账状态，已退 40.00、应退 0.00。 | 从 V1 查历史仍见 200.00，余额明确对应 V2。两种退款状态分别预置，WorkBuddy 无需操作资金。 |
| D · 已实施分阶段治疗／尚无已发布账单 | 两条独立样本。一条已实施且本阶段不另收费，已发布账单为 0.00。另一条尚在诊，尚无已发布账单。 | 前者显示实际处置与 0.00，后者显示“结算单待发布”。就诊状态与已发布账单分别核对。 |
| E · 取消、超窗、依据变化 | 预约变化不触发资金记账。 | 取消无后继可读历史，超窗或依据变化给原门店。保留有效预约的样本可同时查原预约。同一原就诊的两条指示分别核对。 |
| F · 非现金承担与药费 | 账单 300.00，已核对基金承担 60.00、个人账户 20.00、预收抵扣 50.00、已收 100.00，预期待付 70.00。另用仅发药、部分退药样本核对净药费。 | 现金、预收抵扣、医保承担各有明确标签。仅发药的就诊正确列出药费。 |

**权限和操作验收。** 用 B 或 C 切换四种患者身份，再用另一门店前台打开同号。授权身份只见允许的项目，其他患者获得通用拒绝。打开、刷新和返回后，预约、医嘱、账单、收退款及提醒读态均无业务写入。正常登录和查阅审计另计。

**可用性验收。** 从原就诊详情各一次点击能到当前账单或已约的下次预约，再一次返回同一原就诊。核对 375、390、430 宽和放大字号，长金额、版本号、时间与操作均可读。请首次使用的人直接回答“还要付多少”和“下次约好了吗”，记录答案、耗时与误入页数。所有样本的三端金额精确到分、编号及版本一致，发现错账、错人、错预约或越权显示即先修复再交付。

**排在其后的工作。** 离店信息稳定后，再完善超建议期仍未约的门店随访，沿用已有认领、期限和联系历史。微信订阅送达单独以平台和实机回执验收。
