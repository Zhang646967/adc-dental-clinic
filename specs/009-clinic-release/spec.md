# 门诊交付与岗位验收

| 编号 | 业务结果与失败情形 | 数据影响与复核 |
| --- | --- | --- |
| RC-01 | 患者及获准代办从任意一笔改期查看其直接前驱与后继。中间记录可双向追溯，终态不提示到店；其他患者访问受限。 | 使用 Visit.replaces_visit 与独立状态。只读不改预约。冲突保留原约；回执不明只查结果，不重复提交。前台按同号回查。 |
| RC-02 | 仓库首页有系统与 PDF 两个主要入口。持私有邀请者选择分配的岗位，经普通登录与授权检查进入。 | 公开资料无凭据、无患者身份。患者、前台、医师沿同一就诊交接；同名不同人、不同门店、无权人员分别复核。 |
| RC-03 | 安装人员使用空库建档并建立可追责的首位管理员。可恢复到另一空库，升级失败能识别切换期间写入。 | 验收样本与生产初始化隔离。保留源库、备份及迁移历史；校验恢复的状态和回执。 |
| RC-04 | 验收者按正式报告的入口、用例、图和业务编号独立复核。 | PDF、可编辑模型、客户端和部署包以发布记录定位。图中岗位分别标明组织边界或软件边界。 |
| RC-05 | 网页在紧凑、标准及宽屏下可操作；iPhone 在固定 HTTPS、域名校验开启及调试关闭时可独立办理。 | 浏览器检查键盘、焦点与放大。iPhone 记录可用屏宽、系统及微信大字、VoiceOver、原生日期选择和扫码。用户指定此次手机验收范围为 iPhone。 |
| RC-06 | 一位首次使用者独立完成患者改期、前台同名核对和医师确认版查阅，并从 PDF 定位结果。 | 记录首次阻碍、改动、复验结果。临床、支付与医保等现场启用另行签收。 |

原只读样本 #2 为独立预约，已保存链为 #3 → #4。新增业务写入限独立副本。

RC-01、RC-05 的患者入口按当前就诊与会话共同决定。未来已预约、服务端允许调整且当前可办理时，患者可从就诊清单或服务中心找到改期。只读时仍可查安排；已替代记录应指向后继的当前状态。微信字号调整后，就诊、预约详情、选时段与确认页均需重新读取设置，保留已选事实。开发者工具的屏宽和字号组合、iPhone 原生选择与实际播报分别记录。
