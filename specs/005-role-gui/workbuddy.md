# WorkBuddy 18550 · 患者常用页面

请在现有原生小程序改三处：患者服务中心（pages/discovery）、就诊清单（pages/home）、就诊详情（pages/visit）。本批围绕已有数据调整排版、文字和展开交互。前台办到诊、医师写病历仍使用各自的网页工作台。

## 在同一台 Mac 开始

1. 解压 ZIP 后，在含 VERSION.json 的目录运行 `python3 检查环境.py`。它检查工程、31 页、独立合成后端、数据库和私有指南位置。
2. 运行 `python3 准备源码.py`。在目录内的 WorkBuddy源码 开发，分支为 workbuddy/role-gui-18550。先提交源码，再运行 `python3 同步小程序.py`。导入“微信小程序”并在官方工具编译。保持仓库默认连接设置。
3. 在 VERSION.json 的 private_guide 读取本批合成账号，按样本索引定位。私人截图放 guide.evidence_dir。样本和原就诊已备齐，所有验收均可只读完成。教师入口不参加本机测试。

## 页面交付

- 患者服务中心首屏显示当前就诊人及身份、服务端主行动。患者首先能判断去哪里、何时到店或需联系谁；沿用正确就诊、报告版本及复诊指示的跳转。预约、就诊、报告、费用用患者熟悉的短名称。低频工具收进「更多服务与帮助」。仍可公开浏览门店；只有已有权限的入口可展开。
- 就诊清单优先显示状态、预约日期时间、门店、医师和本条记录的动作。说明及长编号可展开，编号要能完整换行。区分预约、到诊、已结束和已改期。详情返回保留原来的清单范围；不同记录的展开状态互不影响。
- 就诊详情直接显示状态、门店、实际到诊、当前账单应付或应退、待发布／待复核，以及每条后续安排。已确认到店时间、建议窗口、已取消或改期历史各用其原有标签。仍保留「联系原门店」「查看复诊预约」「查看历史预约」「返回原就诊」和所有有效入口。收款、退款、预收抵扣、医保分项及完整编号可展开核对，保留原版账单和原有金额口径。本人填写的需求可在详情内查看；代约、医疗代理只显示授权内容。
- 优先复用现有布局；每个任务区只突出一个下一步。建议移动端页面标题 24、分节 18、正文 16、辅助至少 14 个逻辑像素，控件至少 44×44；长内容自然换行。使用有名称、可聚焦的原生按钮展开／收起，读屏能区分展开状态。默认关闭说明，切换就诊人、退出、重进其他记录时清除私有状态；重新读取出错仍使用原错误和返回路径。
- 只改相应原生页面、必要的共享样式与定向检查。沿用现有接口、权限和主行动选择。打开／关闭详情是本地操作。预约预览、确认、已读、收费、撤权和治疗均无需操作。

## 按真实入口复测

| 用例 | 正常操作 | 通过标准 |
| --- | --- | --- |
| G1 访客和本人 | 访客打开首页，再正常登录 A 账号 | 访客可找门店，私有内容为空；本人出现当前就诊人和服务端主行动。更多服务默认收起，展开与收回时主行动不变。 |
| G2 已约、建议和历史 | 用 D 账号从历史进入指定原就诊，打开已确认复诊，再返回。对比另一条未约安排与历史预约 | 首次进入就能读出实际日期、时间、门店。建议窗口、已改期及已取消预约不会替代有效预约。直接从主行动进入仍能定位同一条安排。 |
| G3 账单和编号 | 用私有指南的本人和记录查看结算及相关说明 | 默认看得到当前总额、状态、应付或应退及复核提示。展开后逐项核对与本次结算单一致；收起后关键金额仍可读。首开清单可辨认具体记录，完整编号可查。 |
| G4 代约、医疗代理和另一患者 | 正常切换到指南指定的代约、代理及另一患者。用已公布的合成样本路径核对 | 代约可办自身预约范围但无款项、报告、临床内容。医疗代理回到适用的医疗授权页。另一患者不可见原记录。切换前后的姓名、金额、展开状态不串用。 |
| G5 到诊与空清单 | 用 F 账号查到指定“已到诊”样本，用无预约账号浏览清单 | 前台登记和医师接诊有清楚的文案。空清单显示对应状态和可行的下一步。只读浏览后，预约、款项、随访与报告读态均未变化。 |
| G6 显示与操作 | 官方开发者工具编译并按正常点击录入记录；截图首页、清单和详情各一组，含展开和收起 | 记录实测尺寸、字号、触达、长文本及返回位置。具备设备时测试 375／390／430、大字、读屏与原生返回；工具无法复现的按项记录。关闭调试的真实手机单独验收。 |
