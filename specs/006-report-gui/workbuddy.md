# WorkBuddy 18551 · 患者报告提醒与报告详情

请在本包准确版本上修改患者小程序，完成官方开发者工具回归并回传候选。网页、医师与前台页面由 Codex 负责。用户负责转交此包。实机验收在客户端回传、与网页核对一致后使用同版本独立 HTTPS 预览。

## 开始

1. 解压到新的可写目录，运行 `python3 检查环境.py`。该脚本检查全部交接文件、工程树、31 页、候选版本、独立服务、数据库健康及私有指南的可读性。如服务已停，按包内《运行说明》启动既有 18551。
2. 运行 `python3 准备源码.py`，在生成的 WorkBuddy源码 的 `workbuddy/report-gui-18551` 分支开发。导入包内「微信小程序」。仓库保留默认地址、AppID 和域名校验设置。修改提交后运行 `python3 同步小程序.py`，重新编译并记录官方工具、基础库、实际设备、页面数。交回完整提交和 Git bundle。
3. 使用 VERSION.json 的 private_guide 按敏感读取流程一次读取本批账号、就诊及报告编号、明确的已知路径、对应角色和证据目录。浏览全程可用现成样本。截图仅放在私有目录；公开回传仅写版本、状态、查验编号与缺项。

## 修改范围

- 就诊 → 报告与复诊（pages/report-notices）。每行优先展示接口新增的 project、原有 published/corrected/withdrawn 对应的服务端标题、明确的读态、门店和北京时间。缺 project 时沿用已有 title。清除重复标签和操作说明，当前版可打开该版本。撤回的行保留联系门店与原就诊。保留主动标记已读、分页、访客/授权/换人后的清理和返回行为。
- 报告详情（pages/examination）。项目、第几版、发布时间、完整报告正文、复诊结论和下一步直接可读。BOOK 的建议日期、VIEW_APPOINTMENT 的实际时间/状态、CONTACT 的门店、NONE 的原结论取服务端字段；已取消/已改期的历史记录保留准确状态。检查时间、检查编号及原就诊编号放入默认收起的「查看检查时间与编号」。关闭、换报告、换身份和授权失效时清除展开内容及迟到响应。保留从原就诊或复诊等实际来源的返回。
- 沿用现有 patient-flow 字阶和按钮。长正文、项目名、门店、长编号自然换行，正文不缩略。可操作项有可理解的名称，读屏能区分每条提醒的项目、状态和动作。原生可操作控件表达展开/收起；按焦点顺序朗读，折起后焦点回到触发项。页面必须在关闭调试且启用域名检查时可使用。

## 本机验收

| 用例 | 正常路径与样本 | 判断 |
| --- | --- | --- |
| W1 提醒 | owner 正常登录 → 就诊 → 报告与复诊，查看 corrected、withdrawn 与 booked | 标题具体，现行版本、已读和未读明确。withdrawn 能联系原门店，返回原就诊；每条链接属于本条记录。对照私有指南的 id 或路径区分同名项目。打开或返回不改未读数。 |
| W2 长文及收起 | 打开 corrected 的现行第 2 版 → 展开编号 → 收起 → 返回 | 全文可逐段读；折叠按钮有名称和状态，折起后正文、版本仍可读。医师待审核的第 3 版只在医师页面出现。 |
| W3 复诊 | 打开 booked / available / contact / corrected | booked 显示现行预约号、准确日期时间和门店；available 在窗口内给查号入口；contact 指向原门店；corrected 仅查阅。允许从普通点击进入下一页后返回，停在任何提交之前。样本窗口的具体日期见私有指南。若届时已过，保留服务端的当前结果，由 Codex 在另一独立库备新样本。 |
| W4 拒绝与旧版本 | 样本 paths 中的旧版、待发布、已撤回、另一患者、两种代理；随后正常返回 | 旧版/待发布/撤回及他人常规 404，两种代理走已有本人专属拒绝和各自返回路径。旧项目、号码、内容、展开态、前一版信息均清空。 |
| W5 兼容与设备 | 旧数据缺 project、缺后续安排，分页与刷新（用受控响应验证缺字段及迟到响应）；普通工具回归 | 缺字段时有正常标题、结果仍可读，零条、加载与失败各有实际下一步。节点/映射测试与官方 IDE 分开。记录实际宽度、字体、滚动、控件与遍历顺序。 |

本机业务写入预算为零。样本已准备好已读和未读，已读动作的写入/幂等由后端独立测试库覆盖；小程序用受控传输测一次显式点击。约号、发布、撤回、联系登记均保留原样。用 `node scripts/verify_wechat.cjs` 加本次纯映射/页面定向回归。提交与基线、包校验、替代动作用实际值回报。

## 关闭调试的实机验收

Codex 准备集成提交的私有 HTTPS 预览与合成样本，协调真机；WorkBuddy 有实际设备时可按同一表记录。开发者工具尺寸、桌面键盘和无障碍树各自单列。使用手机微信从普通扫码进入，记录关闭调试、合法域名开、无绿色 vConsole，普通路径登录并打开同一报告。

| 设备覆盖 | 实际操作 | 通过标准 |
| --- | --- | --- |
| 紧凑、标准、大屏 | 目标逻辑宽约 375 / 390 / 430，每档一台实际设备；记录实际 windowWidth、机型、系统和微信版本、方向和字号 | 各档均从提醒读到报告尾、核对复诊、展开/收起、返回同一来源。长文换行、控件可达，金额/时间与编号不截断、无横向溢出或按钮遮挡。相邻机型按实值标注，未覆盖的档单列。 |
| 大字号 | 紧凑屏和大屏分别从常规调至系统可用最大或辅助大字，并记录微信内调节档；重新进入 | 标题、状态、实际预约时间、长门店名和正文跟随实际设置可读；展开按钮不叠字，底部动作可滚动到达。系统大字与微信字号分别记实际生效情况。 |
| iOS VoiceOver | 逐项右划、双击，听一条更新提醒，读第 2 版正文，展开编号再折起，返回 | 朗读项目、更新/未读、版本；按钮说明动作与状态，折起后跳过隐藏项，焦点回到触发项；返回能继续同一条提醒。 |
| Android TalkBack | 同一路径读已约样本和撤回样本；逐项滑动、双击，退出再进入 | 能听出实际复诊日期、时间、门店及撤回状态；没有可读正文的撤回样本无打开报告动作；顺序合理，无重复导航或焦点陷阱。 |

所有可用设备同时检查真实点击与纵向滚动。记录每格 PASS / 发现问题 / 待设备，写实际设置和第一处阻碍；私有证据可用脱敏截图或逐手势观察，正文、密码、令牌及录屏不对外。网页回归、工具回归和关闭调试的实机矩阵通过后，再更新老师的试用入口。
