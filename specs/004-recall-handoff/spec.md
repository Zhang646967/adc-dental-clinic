# 离店后的复诊随访

阶段规划，以已交付的 `bd9223a` 为基线。医师建议患者回来，到了建议日期却还没有约上。门店该由谁跟进？患者下次打开系统时该做什么？实施顺序和合成样本见[任务与验收](tasks.md)。

## 优先做这件事的依据

- 上轮真机已核对待付 70 元、账单第 1 版和改期后的有效复诊时间。首次查找时，用列表上的就诊时间比让患者找内部编号更顺手。本轮继续用患者认识的日期、服务和门店定位。[离店规格](../003-visit-checkout/spec.md)
- 前台已经可以认领随访、登记联系、设下次期限和核对完成依据。目前「超建议期未约」允许选出“本人暂不继续，转医师核对”的事项，详情页才拦住继续对外联系。工作台显示本店待认领和内部逾期的总数。交班时还需要知道哪些轮到自己办、哪些只能内部核对。[现有随访筛选](../../clinical/continuity_selectors.py) · [联系命令](../../clinical/recall.py) · [前台工作台](../../templates/workspaces/frontdesk.html)
- 患者首页只有在当前主行动为普通预约时才查找待办复诊，查找源是已发布报告。普通诊后指示已能在原就诊里回查。两类指示都应当有清楚的回查路径，同一条指示只提示一次。[患者首页](../../portal/patient_dashboard.py) · [报告待办](../../portal/report_followup.py) · [离店安排](../../care/checkout.py)

## 这一批要达到的结果

| 编号 | 使用者 | 页面与办理结果 |
| --- | --- | --- |
| R1 | 本店前台交班 | 从现有「复诊随访」进入「今天我应跟进」，查看当前负责人、最近一次联系结果、内部跟进时间和合适的下一步。单列待认领和待医师核对。医师建议的起止日期、前台内部跟进期限、已确认的到店时间分别标注。跨过建议最晚日按北京时间计算，当日仍在建议期内。 |
| R2 | 前台与原负责医师 | 未接通可登记下次跟进时间。患者明确暂缓后退出待外联清单，进入内部核对。原负责医师从本人工作台找到对应原就诊，在权限范围内明确处理意见，留存处理人、时间、指示版本与依据。临床指示的调整或撤回由有权限的医师办理。前台据实际情况明确接续。医师作出决定、前台已接通、患者同意另约分别记录。 |
| R3 | 患者本人 | 官网与小程序使用同一组当前事实。普通指示从首页直达原就诊的「下次安排」，报告指示仍可直达准确发布版本。尚未约和超窗时说明可做什么，实际有可自助办理的依据和有效窗口才展示查号。患者暂缓时，在原就诊保留说明和主动联系原门店的入口，首页停止催约。已约时优先显示有效预约的日期、时间与门店。改期前的预约在历史中回查。 |
| R4 | 患者、前台和医师 | 按原就诊和具体复诊指示逐条核对。同一指示的报告入口和普通就诊入口合并计算。同一就诊下不同指示分别保留。只有明确关联的正式预约及其改期后继才算约上。患者另挂同店同服务的号，需要核实关联。复诊目标只在核对到符合原目标的实际完成依据后结案。 |

患者首页保留一个主行动，沿用已到诊、待答复的候补邀约、有效预约等现有优先顺序。普通复诊指示只接在原本会显示「预约就诊」的位置。先沿用符合条件的报告待办，保留医师只要求门店联系且没有建议日期的既有流程。再从已进入或已过建议期、仍需本人处理的普通指示中选择最早到期的一条，同日按指示编号排序。还没到建议期的普通指示在原就诊可查。有效预约与需要门店核对可以同时存在，仍显示原预约事实。

患者能看到的措辞随事实变化。例如，超窗无预约时显示「您尚未预约复诊。建议日期已过，可联系原门店核对时间。」本人已明确暂缓时显示「复诊安排已暂缓。需要继续安排时，可联系原门店。」只有有效预约显示具体到店时间。

前台按当前门店办理。医师读取和办理分别复核本人负责的就诊、门店、服务和专业权限。负责人授权失效时保留历史，交由同店有权人员明确接续。患者侧展示就诊与安排所需的最少信息。前台责任人、内部跟进期限、电话记录和医师内部说明留在相应工作台。预约代办与医疗代理沿用现有授权边界。

## 业务数据与后续范围

沿用现有复诊指示、随访责任、联系历史、正式预约关联和完成依据。只读查询的业务写入应为零。认领、联系、医师决定、另约、完成各自需要明确操作。医师处理结果优先引用现有带版本的指示或决定。如需新增独立的医师核对事件，先写明谁能确认、如何审计及如何兼容历史记录，再评审持久化方案。[随访与完成规则](../../docs/C23_RECALL_LAB_CONTRACT.md) · [复诊预约关联](../../clinical/next_visits.py)
