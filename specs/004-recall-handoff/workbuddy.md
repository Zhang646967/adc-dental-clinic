# WorkBuddy · 18549 复诊随访与原就诊定位

本次交付由 Codex 提供后端、网页和六组已预置的合成数据。请在本机隔离实例使用包外指南的身份，只做登录、切换、浏览、返回。所有预约、联系、暂缓、医师核对和结案事实均已准备好。

1. 解压交接包。在包目录依次运行 `python3 检查环境.py`、`python3 准备源码.py`。导入“微信小程序”。在 WorkBuddy源码 的指定分支改动，提交后执行 `python3 同步小程序.py`，然后在微信开发者工具普通编译。版本、实例、镜像、工程校验和、私有指南与证据路径均以包内 VERSION.json 为准。
2. 在 utils/primary-action.js 与就诊、患者服务中心两处入口支持 VISIT_FOLLOWUP。只认数值 visit_id 与 instruction_id，自行组装本项目原生详情页。两处主按钮应给出相同结果。编制正常导航，不接受任意服务端 URL。详情加载完成后定位当前就诊返回的那条指示；列表有多条时必须能辨别选中项，按钮和滚动不遮住标题。旧接口、缺字段和无法定位要保留已有回查入口。
3. 离店“下次安排”分清建议日期、已确认的到店时间和历史预约，显示服务端暂缓文案和可选 message。已约情况下显示真实后继。暂缓时保留患者主动联系原门店的入口。切换身份、退出、撤权和迟到响应沿用私有数据清理机制。
4. 保持现有字级和大字模式，优先显示诊所名、服务、患者要做的事。按日期和服务走正常点击。工具内能做的字号、返回和布局逐项记实，工具无法操作的原生手势或真机能力单列。
5. 仅改 clients/wechat 与必要的既有原生核验。仓库默认地址和 AppID 保留。运行 `node scripts/verify_wechat.cjs`，复核旧接口。回传提交、可导入的 Git bundle、正常操作路径和私有证据位置。用户转交回传。
