# 复诊随访实施计划

前台沿用同店复诊指示、责任记录、认领与联系命令。交班清单从当前责任和北京时间筛选，列表按页读取。患者暂缓的指示转入内部核对。建议期、责任期限和正式预约分别投影。

原负责医师在本人专业权限内阅读暂缓事项，预览并确认处理意见。意见留在既有不可覆盖的随访事件中，关联本次暂缓事件和指示版本。权限、当前就诊、指示与随访修订在写事务内重新核对。处理意见不代替患者重新同意，也不自动恢复联系。前台只看办理需要的结果，患者只看自己的安排。

患者首页沿用既有优先级。普通诊后指示使用新增的主行动类型与原就诊、指示编号；报告沿用准确发布版本。网页及原生端回到同一条安排。现有预约、改期后继、已完成的临床依据继续由业务模块投影。完整接口与样本随验证后的交接包冻结。

先在独立 PostgreSQL 用 A 至 F 核对角色、并发、读写与预约关系，再改进交班、医师核对和患者回查的页面布局。浏览器、开发者工具和关闭调试的实机验收各自记录。WorkBuddy 接收同版工程、样本和包外私有指南。正式业务数据和教师入口在本阶段验收通过前沿用既有交付。
