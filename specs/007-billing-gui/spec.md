# 费用清单、离店交接与医师开单核对（18552）

承接 006 的第二优先级。患者从「费用查询」看到现在还要付或应退多少，前台按同一账单查到下一项办理，负责医师核对实际处置和发布金额。浏览、切版、展开、收起、返回均为只读。

| 编号 | 可观察结果 |
| --- | --- |
| B1 患者清单 | 一单一行，先呈现门店、就诊时间、当前版与尚需支付／应退余额。二者为零且仍有待复核或预收抵扣超额时，显示待处理事项。两者均已解决才显示已结清。 |
| B2 患者结算单 | 已选版本的开单金额和收费项目属于该版本。当前余额、版次和待复核事项常显。患者可展开已记账收退款、医保与预收抵扣，收起后仍看得到应付或应退。保留分页、打印和回到进入时的费用清单页或原就诊。 |
| B3 前台 | 本店前台由就诊详情识别待收、待退、待审核、待发布、已结清。医保未决先核对原申请。已发起的收退款先核对原申请；独立审核与记账沿用原有权限。 |
| B4 医师 | 本次负责医师在结束接诊前看到已实施处置、数量、发退药和开单金额。未满足的关闭条件、原表单及错误直接可见。已发布版本保留只读金额及结算单入口。实际阶段治疗本次不另计费、仅发药、无治疗分别说明。 |
| B5 访问与旧版本 | 本人从现有接口读取，代约或医疗代理沿用原拒绝，其他患者看不到本人的单。新字段为可选项。缺少余额的旧响应保留未知，人民币金额使用服务端十进制值。 |
| B6 可达性 | 网页在 Chrome、WebKit 的 375、390、430、1280 逻辑宽及 100%、200% 字号核对排版、键盘展开及返回。小程序单列工具及关闭调试的真机，记录系统和微信大字、iOS VoiceOver、Android TalkBack 各自的真实表现。 |

沿用已发布账单、同一读事务中的资金投影与原权限。本人清单和离店投影增加可选的 `insurance_pending`、`advance_excess`，前者是未决医保原请求数，后者是待核对的超额预收抵扣；`review_pending` 包括未决收退款和医保。待审核金额不计入已记账金额。保留已有版本查询、收退款明细及分页。未引入写接口或数据迁移。
