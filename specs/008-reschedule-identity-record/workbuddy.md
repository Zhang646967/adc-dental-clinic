# WorkBuddy · 18553 患者改期时间核对

患者需要在选时段和最终确认时知道原来何时到店、准备改到何时。接续现有患者小程序的改期流程。

## 开工

解压同名 ZIP。在根目录依次运行 `python3 检查环境.py`、`python3 核对样本.py`、`python3 准备源码.py`。在 WorkBuddy源码 的本批分支上实现，执行 `python3 同步小程序.py` 后，把「微信小程序」导入官方工具。具体提交、工程树、服务、样本有效期与私有指南位置见 VERSION.json 和运行说明。私有指南在 ZIP 外，请按敏感读取流程使用。回传分支提交、Git bundle、校验、实际点击、设备与查询编号；密码、会话、提案和私人截图只保存在指南指定目录。

## 实现

- 入口为「就诊」中一笔可改期的预约。选择前突出原预约的日期、起止、门店和医师。拟选新时间只在选中具体时段后出现；选中和最终确认两处让两组事实相邻。逐组展示北京时间，能核对不同日期、医师和结束时间。旧服务取保留的快照，新安排用本次候选或预览的服务。接口缺少的事实留空。
- 在确认页明确写「待确认，原预约仍保留」。主操作为确认改期；返回重选保留来源、筛选并重查。已有预约、候补邀约、明确冲突和提交后结果暂未确认分别沿用原有动作。查看回执时按实际保存的后继预约打开；始终由患者明确提交。切换就诊人、退出或授权变化时清除旧数据和迟到响应。
- 在现有 pages/booking、pages/confirm、pages/visit 和必要的映射与定向校验内完成。保留当前正常预约、复诊与候补路径。参考同版网页的时间对照，不在患者小程序增加前台患者搜索或医师病历入口。

## 验收

| 编号 | 普通操作 | 需要记录 |
| --- | --- | --- |
| W1 原约 | owner 从就诊清单打开 source，点改期；尚未选中时段 | 原约编号与时间准确，可以说出当前应到店时间。无成功提示或结果查询。 |
| W2 选时段、返回 | 选择指南 target.day 的 target.start，填写合成原因，停在核对页。返回重选，再进入一次 | 选时段与核对页上，原约和拟选的新日期、时长、门店、医师与网页一致。原预约仍在，筛选可继续使用。 |
| W3 已改期样本 | 打开 old，按改期后的预约入口查看 saved，再返回原记录 | 原记录和后继各自编号、实际状态、时间一致。原约与当前预约容易区分。 |
| W4 失败与身份 | 本人换为预约代办，选指南内的授权；再退出并用 other 打开 source | 代办只看本次授权预约资料。其他患者不能查看原约信息。用受控传输分别测 409、响应丢失、已保存回执、换人后迟到响应，保留现有明确确认和查回机制。 |
| W5 可读性 | 用可用的工具或真机检查 375、390、430 宽和大字；选日期、输入原因、查看两组时间、返回 | 日期与标签仍在同一组、无横向遮挡、按钮可达。读屏按原约、新时间、原因、确认顺序，分别记录 iOS VoiceOver、Android TalkBack、微信字号和系统字号。 |
| W6 真机 | 固定 HTTPS 且域名校验启用的同版本预览，关闭调试重新进入 | 记录机型、微信版本、是否有绿色 vConsole、原生日期选择、大字及实际播报；未取得的条件单列。模拟器本机地址只用于工具回归。 |

共享库仅查阅与预览，W2 停在确认前。W3 使用已经准备好的原记录与后继，勿新建预约、确认改期、占位或撤权。浏览器验证和测试副本中的真实确认由 Codex 负责。收工再运行样本对账，若有差异记录发生在哪一步。无需等待另一批任务完成。
