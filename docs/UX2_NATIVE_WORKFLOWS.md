# UX2 预约清单与业务表单

办理目标 → 当前范围和筛选 → 分组录入 → 错误定位 → 原预览和确认 → 真实浏览器验证。

## 本轮问题与实现合同

现有预约页能筛选，但缺少直接办理清单、已用条件和逐项清除入口；就诊编号可搜索却未显示在清单。接诊页有多个独立表单，提交错误可能留在页面下方。财务申请按字段平铺，金额、渠道凭据与独立审核的关系不够清楚。这些是页面检查发现的操作问题，尚不是用户访谈或效率实验结果。

| 页面 | 本轮改进 | 保留的业务保证 |
|---|---|---|
| 预约清单 | 快捷清单、筛选摘要、逐项清除、显示就诊编号、窄屏卡片排列 | 原服务端查询、20条分页、身份/诊所作用域；主管和总部不获得患者身份 |
| 接诊 | 锚点定位、复核/草稿/治疗分组、错误摘要与输入关联 | 四个独立表单、原版本和确认字段；草稿不发布、不计费，治疗仍由负责牙医确认 |
| 财务 | 资金事实、渠道凭据、依据及复核分组，错误定位 | 先预览后确认、服务端金额和当前状态、不同账号审核；日结仍区分四类总额 |

预约筛选继续由GET地址保存，分页和逐项清除保留其他有效条件。快捷办理清单明确重设日期和状态，保留搜索词；不把旧条件悄悄混进“今日”视图。无效参数仍返回400且不展示未筛选数据，不接收URL中的权限范围。

## 界面与成本

沿用一个Django工作台壳层，每页只渲染一份真实业务内容。新增样式和少量错误定位脚本；无前端框架、统计接口、患者数据缓存、自动提交或新数据库结构。桌面保留紧凑表格，窄屏按相同记录纵向排列；原生标签、表格标题、键盘焦点与大字模式保留。

表单字段名称、CSRF、工作上下文、版本、签名和服务端验证不变；隐藏状态与可见字段分开渲染。脚本只展开错误所在区域并定位摘要/输入，不改字段值或业务状态。无脚本仍有可点击摘要、内联错误和原生表单。查询导航不新增数据库查询，清单仍限定20条；长备注和金额不依赖悬浮才能阅读。

## 验证门槛

验证特殊字符搜索、分页/后退/清除、无效条件及跨店拒绝；检查接诊和财务错误时输入保留、标签/帮助关联、键盘及320/390像素大字布局。真实浏览器执行接诊、四类收支和独立审核，再执行五店二十账号三十分钟读写负载，加入有界CSV导入与复核。容量、浏览器、资金核对、Mac保护和课程报告各留证据；不把局部无障碍检查当成完整认证。

思维导图：清单 → {范围，快捷视图，条件，编号，分页}；表单 → {分组，标签，错误，原值} → 原确认与复核 → 浏览器/负载/事实核对。
