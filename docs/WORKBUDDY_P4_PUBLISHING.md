## 正常操作

1. 在业务测试小程序使用患者账号，新登记一条广州越秀候补，选择该店支持的服务及实际未来可出诊的时间范围；范围须能容纳服务完整时长。
2. 前台打开上述发布入口，勾选确认后点击“生成候选安排”。生成建议不占位、不创建邀约。
3. 跳转具体方案页，核对候补编号、医师、起止时间。若没有建议，页面不会显示发布表单；检查候补仍在等待、日期与服务匹配、出诊和设备可用。
4. 勾选确认，点击“发布限时邀约”。只有这一步创建邀约与临时资源占用；并发或配置变化会重新检查，不能用旧表单强行发布。
5. 小程序进入“就诊→候补”，刷新后打开邀约。明确接受才形成预约，拒绝不形成预约。发布后15分钟或预约开始时点两者取早为截止时间。

不需要先暂停接收。已暂停／停用的出诊不能发布新邀约；既有有效邀约仍按原规则处理。也不需要管理员、隐藏接口、SQL或改数据库状态。

## 本轮三条阻塞用例

| 用例 | 操作与预期 |
|---|---|
| 接受 | 新登记→前台生成并发布→患者接受；同一邀约只关联一条正式预约，重复确认不多造预约。核对后如需清理，通过正常取消保留历史。 |
| 拒绝 | 新登记并发布→患者拒绝；不新建预约，候补继续等待，资源临时占用释放。结束测试可正常退出候补。 |
| 过期 | 新登记并发布，记录实际截止时刻，不接受；等待真实时间到期后刷新，禁止接受且不能生成预约。前台在候补清单勾选“回收过期邀约”，再核对需求可重新安排。不要修改数据库过期字段、修改系统时钟或伪造客户端结果。 |
