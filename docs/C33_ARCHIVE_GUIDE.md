# 病历归档、独立医务审核与追加补正

文书完成 → 准确清单 → 指定独立审核 → 固定文件 → 有依据的追加补正。

本批为员工侧软件业务流程，继续使用课程合成资料。患者副本申请、医疗用途材料核验和受控下载属于下一批C3.3B；当前归档权限不会沿用到患者或代理账号。真实机构专业制度、可靠电子签名与云端验收分别进行。

## 办理入口与职责

- 负责医师：医师工作台的“病历归档与独立审核待办”，或本次病历页“病历归档与补正审批”。
- 另一名医务审核医师：同一归档待办页的指定审核清单。需既有有效机构委任、明确的归档审核职责和对应诊所及服务读取范围；不能审核本人记录。
- 前台：工作台“归档办理协调”，只看本店就诊业务编号、责任、期限和进度，不看临床正文。
- 主管和总部：归档汇总数量，不审批医疗内容，不下载临床包。
- 技术管理员：按机构已经明确的委任，在账号治理中登记或撤回专项归档审核职责。新职责默认关闭，登记不代替专业资格核验，也不自动授予具体服务权限。

员工入口为`/accounts/login/`，医师待办为`/clinical/archives/`，协调汇总为`/clinical/archives/summary/`。账号指南私下提供，公开仓库不列密码。

## 正常归档

1. 如实结束接诊，确认检查及完整初诊或复诊文书。接诊结束、付款结清和归档分别表达；未付款不阻止合格文书归档，归档不新增治疗、账单或资金。
2. 打开本次归档工作台，处理缺项提示。旧记录不会被批量补造归档事实；首次新确认或明确提交才建立责任事项，原期限保留。
3. 选择完整归档、准确的已发布收费版本及独立审核人，说明本次依据；预览服务器清单后明确确认。没有已发布费用单时如实标记，不伪造零费用单。
4. 指定审核人核对准确文书、临床来源与完整性，预览后选择通过、退回或不通过。已通过仍显示待生成。
5. 现有通知工作进程自动分批生成。固定PDF、清单、摘要和独立审核全部就绪才显示“固定文件已生成”。医师可下载文件与来源清单；文件保存在数据库，随加密备份恢复，不在公开静态目录。

摘要用于检查字节一致性，不证明可靠电子签名。账号确认和纸质原件引用分别保留；文件仍明确原件手续状态。固定包中的姓名、原单位与收费版本使用原快照，不跟随目录或当前资金余额变化。

## 缺项、退回与生成失败

检查草稿、完整文书草稿、方案草稿、来源变化、未答疑问和已发生治疗的事前材料缺口均明确列出责任及继续入口。不能补齐时可由独立医务审核“缺项资料保全”；它保留现有资料及标记的未确认草稿，不能标成完整归档或补造事前手续。

退回后完善资料并提交新申请，原清单和审核意见保留。生成失败只记录安全错误分类，不把临床正文写入运行日志；负责医师排除故障后明确重试原任务。审核或生成期间来源、职责发生变化，撤回旧申请后重新核对提交。重复确认或重复生成不产生第二份业务结果。

部署使用现有`dispatch_notifications --watch`自动处理，每轮至多生成一份。另有`generate_clinical_archives --limit 1`供受控运维办理；它只处理已获独立批准的申请，不能代替批准或绕过读取权限。

## 归档后追加补正

1. 在原文书或检查页创建有原因的更正草稿，并保存准确内容。此时旧文书和固定包仍可读。
2. 归档工作台选择完整文书或检查牙位记录，提交具体差异、依据和独立审核人。
3. 另一名医务审核医师核对更正前后及来源，批准准确草稿。
4. 负责医师返回原临床入口预览并确认追加版本。批准不代替医师确认；修改草稿、来源或适用职责后须重新核对。检查和完整文书是不同对象，分别按各自准确内容审核。
5. 新文书确认后另行提交补充归档包。旧包、旧版本和旧审核保留；后续资金更正和新的就诊继续由原模块办理。

思维导图：实际文书 → {完整性、准确版本、原责任期限} → 独立医务审核 → {文件生成、失败重试、资料保全} → {原包留存、准确补正、追加版本、补充包}。
