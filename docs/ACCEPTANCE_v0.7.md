期望版本0.7-candidate，无待迁移。备份文件存在且可读仅是备份格式验证，不是恢复成功。

## 2. 身份与门店
1. front_a登录：即使一个身份也先到选择页；选前台后进入前台诊所选择，不出现医生/财务菜单。
2. multi_demo登录：可选医生、主管；角色卡片不是“甲店主管/乙店主管”。
3. 选主管后选择甲店；顶部身份=主管、诊所=甲店。切乙店时数据与入口跟随；医生/患者治疗资料不应出现在主管首页。
4. 切医生后诊所清除；只显示本人负责接诊，不继承主管任意访问。
5. 在旧甲店标签页保留POST表单，新标签切乙店，再回旧页提交：拒绝，提示刷新，不产生甲/乙店误写。
6. 直接访问其他工作台URL：服务端拒绝或引导选择，无额外授权。关闭/撤销授权后的旧页面同样不得提交。

## 3. 操作指南
在任一业务工作台打开“操作帮助”；选一个本角色任务。查看明确步骤和“打开相关页面”，手动打开真实页面；下一步只改变指南步骤，不提交。
从患者助手输入“我明天去不了了”：应给出本人预约取消步骤，不能显示管理排程动作或声称已取消。输入含义不明的问题应提供帮助目录/澄清，不编造链接。切身份或诊所后旧guide不继续误指。
键盘完成打开指南、表单、取消引导；标准/大字切换，320/390像素手机宽度局部表格可横向滚动，页面不能整体溢出。设备实际键盘、读屏、语音可用性仍需手测。

## 4. 候补—排程—预约
1. patient_demo_a在患者台登记甲店未来14天内的时间范围（连续至少30分钟；不能使用已经过去的seed日期）。无治疗诊断输入。
2. front_a可代表另一个已存在患者登记，但不能代表其他店的患者业务越范围；同一患者已有有效候补时拒绝重复。
3. manager_a选甲店→排程建议→勾选并生成。核对候补ID、牙医、具体时段和未安排ID；图范围上限必须显示，不自动创建预约。
4. 主管明确确认发布，出现最多15分钟的待确认邀约。普通预约尝试抢同牙医/同患者同时间应拒绝；患者或前台可查看并确认。
5. patient_demo_a在本人候补中打开邀约，核对时间后勾选并接受。只产生一条正式预约；刷新/重试不能重复创建。
6. 另条邀约测试拒绝、退出及过期：无正式预约；过期后正常预约不受占位阻塞，主管/前台明确回收后需求可再匹配。没有真实短信/邮件通知。

## 5. 原有完整业务
正式预约→front_a到诊→对应doctor复核过敏并录入合成治疗→完成→患者查看账单。无治疗分支不编造治疗记录。finance_demo按已选季度纳入牙医、录入确认成本再测算；独立审核数字更正后只累计当前账单版本。不可通过同账号切换身份自批。
