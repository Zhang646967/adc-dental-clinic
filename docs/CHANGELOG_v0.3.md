# v0.2 → v0.3 变更登记

所有本轮新增决定均为项目设计[D]。没有教师批准、真实访谈或真实机构适用性认证。

| 决定 | 变化 | 影响与回归要求 |
|---|---|---|
| D31 | Patient新增created_in_clinic外键 | 解决首次预约前的建档可见性；不能限制跨店就诊；需测试同绑定范围 |
| D32 | 明确仅本地候选，生产配置阻断 | 最终公网目标保留；先通过运行/安全/恢复门槛 |
| D33 | 被Visit引用的Slot身份与时间在本轮冻结 | 本轮没有排班编辑界面；后续受控编辑需要单独变更设计 |
| D34 | 自动新建的改期后继ID须大于前驱ID | 辅助无环约束；不把ID当业务时间；历史导入不在本轮 |
| D35 | UNKNOWN不与有效过敏项同时存在 | 已记录某种过敏时应是KNOWN；KNOWN不代表完整医学调查 |

保留：七状态、到诊布尔、零治疗零金额的设计、唯一逻辑账单、多内容版本、历史不覆盖、成本NULL/确认态、前台与诊所范围同一绑定、数据库非公开暴露。

没有实现的功能不删除需求：UC-06/07/08/09/11/12仍在后续增量。特别是无治疗关闭和更正政策已经在v0.2定义，但v0.3没有对应业务服务，不能把模型字段当已完成的功能。
