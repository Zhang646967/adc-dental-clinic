# C6 患者预收款与账单抵扣

门店登记 → 财务独立审核 → 日结与渠道对账。

前台在当前门店打开患者档案，选择「登记患者预收款」，填写金额、业务日期、渠道和凭据编号。确认预览后可查看申请回执。财务从「待审核预收款」进入，核对患者、门店、金额和原始凭据，再确认记账或拒绝。申请账号与审核账号必须不同。患者预收余额按收款门店和患者归集。

| 业务规则 | 核对口径 |
| --- | --- |
| 待审与拒绝 | 待审金额单独显示，拒绝保留理由与历史。两者均不计入实收。 |
| 已记账 | 同时确认现金账和原始凭据，实际资金计入收款业务日。直接收退款及账单待付仍取自原账单。 |
| 凭据争用 | 同一渠道与凭据不能同时支持预收和第二笔有效收款。并发确认按渠道加锁后重查，同一确认重放返回原回执。 |
| 日结与渠道对账 | 日结的四类金额口径保持一致，实收中单列患者预收。渠道流水可在既有对账入口匹配已记账预收。 |
| 岗位与可见范围 | 前台使用当前门店且在该店可办理的患者。财务独立审核，总部查看预收汇总。 |

预收款复用 `adc_cash_entry`，新增可空患者外键 `advance_patient_id`。患者预收、账单收退款及设备费用各有唯一来源。原始凭据和更正版本继续由 `adc_cash_evidence` 保存。 [预收款 ER](database/er_patient_advances.svg)

验收在隔离课程合成库进行。线上课程入口对应已部署版本。 [运行版本](../README.md#访问与登录)

## 同店账单抵扣

前台从「患者档案 → 查看本店预收款 → 已记账预收 → 申请预收款抵扣」办理。每次选择一笔原预收，填写同店同一患者的一至五张账单及各自金额。预览列出当时的账单版本、患者责任、待付和抵扣后余额。确认后进入「待财务复核」。财务从工作台进入，核对原款和账单后预览并确认批准或拒绝。

| 业务规则 | 核对口径 |
| --- | --- |
| 待审及拒绝 | 保留原申请与决定。预收可用余额、账单待付、直接收退款及日结保持原值。 |
| 复核通过 | 当笔预收可用余额按抵扣总额减少，各账单待付按对应抵扣减少。原现金账及渠道流水继续作为唯一实际收款。 |
| 重查与并发 | 确认时重查当前授权、已发布版本、医保状态、患者责任及余额。同一确认返回原回执，争用余额时仅符合余额的决定可通过。 |
| 后续账单更正 | 已抵扣历史保留。若更正使抵扣超出患者责任，在应收中单列待核对的预收超额。直接现金应退额按实际净收款另算。 |
| 本人结算 | 患者网页单列抵扣金额。小程序既有本人结算接口返回相同的汇总口径，小程序页面展示待单独验收。 |

预收可用 = 已记账预收 − 已批准抵扣。账单待付 = max（max（患者责任 − 已抵扣，0）− 直接净收款，0）。患者责任采用当前有效的账单和医保结果。 [抵扣和账单版本 ER](database/er_advance_allocations.svg)

## 抵扣验证

- Chrome 以 390 和 1024 像素宽完成前台申请、财务独立复核和回查。合成预收 ¥300.00 分别抵扣 ¥120.00 和 ¥80.00，两张账单待付变为 ¥79.98 和 ¥119.98，原预收尚可使用 ¥100.00。日结仍为一笔实收 ¥300.00。
- PostgreSQL 17.11 以 95 份迁移安装空库。94 → 95 升级前后，179 张原业务表的 88 条记录逐行一致，原 94 份迁移字节一致。
- 加密备份恢复到按同版本迁移建立的独立空库。187 张 SQL 表的结构元数据及 181 张业务表的 73 条记录一致。复核后逐张账单的准确版本、金额、原实收及渠道凭据均一致。

- 应用提交 `cc96406` 通过 1,184 项源码检查、2,367 项 PostgreSQL 回归及 342 项小程序源码与传输检查。两项历史迁移用例由本机测试进程连接隔离 PostgreSQL 复测通过。
