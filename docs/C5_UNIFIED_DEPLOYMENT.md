## 专项复审

| 风险 | 修复与复测 |
| --- | --- |
| 过敏资料变化后继续使用旧审方 | 新处方绑定医师复核版本。审方、划价和新增发药重验，旧记录、退回、撤回、停止余量与实际退药保留各自办理路径。PostgreSQL 验证复核变更与历史处方。 |
| 调配职责直达未获通过的处方 | 队列、详情和确认使用同一份本店已通过范围。定向用例核对仅调配角色、待审与拒绝结果。 |
| 实际给药归档缺少批号 | 新归档从原发药关联取得品名、计量单位和批号。定向回归同时核对给药、耗材和无菌包。 |
| 代约撤权后确认页保留个人信息 | 清除就诊人、代理身份、预览和勾选，阻止再次提交，按新会话提供核对入口。小程序页面逻辑回归覆盖会话变化与恢复。历史账单返回历史清单。 |
| 恢复与部署竞态 | 两种恢复入口共用项目发布锁，导入前复核目标存储和写入进程。实际独立恢复时同时尝试部署，确认竞争命令在初始化前拒绝。 |
| 网关发布端口偏离计划 | 对照计划核对实际宿主端口、容器端口和绑定地址，覆盖直连与本机演练。 |

已经通过的旧处方在依据失效时可停止剩余调配，实际退药和历史对账依原规则办理。同次接诊替换已通过处方由后续临床流程专项验收。保留原归档内容及账单历史。

## 使用部署包

统一包的 `artifacts` 目录包含准确 Git 归档、amd64 应用镜像、镜像标识和构建清单。按包内校验清单核对归档。服务器按实际固定域名及独立端口生成私有配置，使用已确认 SSH 指纹和专用数据库。准备、首次发布、加密备份和恢复的命令见[统一部署计划](SERVER_DEPLOYMENT_PLAN.md)与[独立运行说明](D23_INDEPENDENT_OPERATIONS.md)。

在既有 80 迁移项目升级时，以目标包和升级前完整提交执行 `g4_course.py upgrade` 或 `g4_remote.py upgrade`，加 `--allow-additive-migrations`。迁移前保存加密检查点。中断后依据私有发布记录继续同一候选。恢复时准备不同项目、空库和与该备份相符的版本，使用 `--trusted-synthetic-copy --schema-mode migration-built`。数据库原件与恢复副本各自保留。 [追加迁移操作](D22_ADDITIVE_UPGRADE.md)

标准二十店安装使用合成资料。C4/C5 专项演练按受控配置显式启用，职责按人、门店、期限配置。与本轮部署验证分开的单店业务证据见 [C5 业务验收](evidence_c5/README.md)。

## 目标服务器验收

首次 SSH 发布使用当前 Mac 发布控制器。完整传输且证书文件就绪后，可以用原部署目录、同一 C5 包和同一加密接收方执行 `resume-publish`。已有初始化与备份记录按实际版本核对，匹配的交付文件和备份直接复用。传输或证书阶段中断时保留现场，确认原项目卷、容器和证书状态后续办。 [首次发布与续接命令](COURSE_ONLINE.md#first-cloud-deployment首次云部署)

本机使用本批固定 C5 镜像和实际 PostgreSQL。注入首份加密备份生成后的应答丢失，续接复用该备份和私有交付文件。185 张表的 10,016 条记录、数据卷和初始化记录比对一致。SSH 应答与定时任务安装采用本机替身，目标服务器另验。 [续接演练回执](evidence_c5_deploy/first-publish-resume-local.json)

可信 HTTPS、证书续期、独立对象存储的回读恢复、目标机容量与 24 小时观察在实际服务器验收。小程序修复版的开发者工具与真机分别复测。网页扫码使用与实际小程序版本相符的配置。真实诊所试点由责任岗位单独验收。

思维导图　专项复审 → 临床证据与患者权限 → 确定版本与统一部署包 → 空库、升级、加密恢复 → 目标服务器与真机。
