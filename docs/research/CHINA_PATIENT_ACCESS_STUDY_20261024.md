# 中国口腔连锁患者入口与医保业务研究

附近门店 → 公开服务信息 → 按需登录 → 就诊身份 → 资源预约 → 实际诊疗 → 医保及自费结算。

**下一阶段先完善患者找到合适门店并完成预约的入口，同时把中国医保作为独立的业务和财务能力设计。** 默认距离排序采用用户已确认的“由近到远”。小程序面向患者及其合法代约人，员工继续使用独立网站工作入口。

研究日期：2026年10月24日。连锁规模以各来源披露日期为准。门店布局和医保结算方案属于待实施设计；当前实际数据库结构见[数据库设计](../database/README.md)。实施安排见[患者入口与医保开发计划](../PATIENT_DISCOVERY_AND_INSURANCE_PLAN.md)，外部依据见[来源登记](china_patient_access_sources.json)。

## 患者入口与当前系统差距

患者首先需要判断“哪家店适合我、能否方便到达、什么时候接诊”，再决定预约。账号是保存和办理个人业务的手段，首次浏览没有必要以登录为前提。

| 业务问题 | 当前源码表现 | 下一阶段行为 |
|---|---|---|
| 首次打开小程序即要求账号 | 首个页面是 `pages/login/index`；首页未登录时返回登录页 | 首页先展示城市、附近门店和服务；预约确认、个人记录等功能按需登录 |
| 网站登录如何真正分流 | 已有公开首页、服务和 `/clinics/`；两个登录页使用不同URL，但共用通用角色激活逻辑 | 患者通道仅激活PATIENT；员工通道仅选择已授权员工岗位；小程序不提供员工工作台 |

## 定位与门店推荐

首页提供“使用当前位置”和“手动选择城市或区域”。患者主动使用定位后，说明用途并请求相应授权；拒绝定位、定位失败或暂时无本地门店时，仍可浏览、搜索和联系门店。无需持续定位，也不把找店的位置写入患者病历或默认保存为住址。个人信息保护法要求目的明确、范围必要，并对敏感个人信息另作规定。[个人信息保护法](https://www.stats.gov.cn/gk/tjfg/xgfxfg/202503/t20250310_1958923.html)

门店卡片包含对外名称、距离、完整地址及楼层入口、联系电话、每周营业时间、当日临时调整、开放服务、可约日期，以及联系和导航操作。当前营业与存在可约号源分别显示；未确认的营业信息不能显示为“正在营业”。公开医生信息使用经过批准的执业展示资料，员工家庭地址、私人联系方式和患者信息不进入公开目录。

按距离排序时保持规则清楚：默认由近到远；相同距离使用稳定的门店顺序。患者可筛选服务、日期和营业状态，系统说明筛选条件。手动选择的区域中心不能伪装成患者精确位置；直线距离不标成驾车时间。所在城市无门店时提示其他城市选择，不把远处门店展示为附近。

网站定位与小程序地图可能使用不同坐标系。门店坐标应记录来源和坐标系，使用地图厂商支持的转换后再计算距离；小程序地图的 GCJ-02 与 GPS WGS-84 不可直接混用。[腾讯位置服务开发说明](https://github.com/TencentLBS/tencentmap-miniprogram-skill/blob/main/quick_start_and_best_practices.md) 首批二十家门店可以在客户端对公开坐标计算距离，不需要保存患者位置轨迹或引入复杂地理服务。

思维导图：位置选择 → {授权定位、手动区域、失败回退} → 同一坐标系 → 距离排序 → {电话、导航、营业、可约服务}。

## 微信账号与就诊身份

**微信普通登录不能直接提供用户的居民身份证号。** 微信登录取得临时凭证，服务端据此识别微信账号；OpenID、UnionID 与真实就诊人身份是不同概念。手机号需要相应的单独授权流程，不能从一次普通登录中推定已经取得。[腾讯微信小程序登录接入文档](https://cloud.tencent.com.cn/document/product/1441/68677)

微信生态中存在独立的实名核验产品，但需要另行接入、符合具体产品资质并完成用户核验。例如腾讯云小程序核身包含身份证识别、活体检测和比对，其特定接入模式还限定了可申请的医疗主体。普通口腔诊所不能据此假设自己自动具备接口资格。[腾讯云微信小程序核身指引](https://cloud.tencent.com/document/product/1007/112653)

建议把身份分为四层，按办理事项逐步完成：

| 层次 | 用途 | 授权与边界 |
|---|---|---|
| 微信账号 | 识别登录账号并与 ADC 账号绑定 | 不因此获得任何既有患者档案或员工权限 |
| 核验手机号 | 联络、账号恢复及必要通知 | 用户主动授权；共享或变更手机号不自动合并患者 |
| 就诊人身份 | 确认本次为本人、儿童或其他授权患者办理 | 沿用本人绑定、前台核验和限定代约授权；代约不授予病历、账单或临床同意权限 |
| 法定实名或医保身份 | 必要的实名就诊、医保待遇及结算核验 | 由前台或具备准入条件的核验服务办理，保存必要依据；浏览门店不要求身份证或刷脸 |

首次使用时，患者可先浏览和查询公开服务；准备预约时引导登录、绑定联系电话和选择就诊人。已有患者通过明确核验关联原档案，新患者通过建档申请完成现有建档流程后办理正式预约。仅姓名、手机号或微信昵称相同，不足以打开原档案。建档申请的自述资料与已核验身份分别记录，不用占位值补齐必填字段。

原患者表目前要求出生日期、账单地址及紧急联系人等资料。微信登录不应被迫收集全部档案字段；下一批需逐项明确哪些用于账号、哪些在正式建档时必需、哪些在接诊时补充。放宽字段需要独立的业务决定及追加迁移，不能通过虚构地址和紧急联系人完成“自动注册”。

获取手机号还受小程序主体与接口资格约束。腾讯微搭的官方接入文档明确采用非个人且已认证的小程序；实际开通能力以注册后的平台后台和现行规则为准。[腾讯手机号接入说明](https://cloud.tencent.com/document/product/1301/90227) 账号尚未注册时可做本地流程和接口替身；这些结果与真实微信授权验收分开。

思维导图：微信账号 → 联系方式 → 就诊人及办理权限 → 必要实名或医保核验；四者分别留存依据，不互相替代。

## 医保适用范围与商业接入

**口腔诊所可以成为医保定点机构，但需要逐机构满足准入和协议要求。** 国家办法列有门诊部、诊所等申请主体，要求信息系统有效对接及使用统一医保编码；以种植牙等非基本医疗服务为主要执业范围的机构不受理定点申请。[国家医保定点管理办法第5至6及12条](https://www.nhsa.gov.cn/art/2021/1/8/art_37_4243.html) 常州2026年公开答复披露当地已有211家医保定点民营口腔医疗机构，提供了民营口腔实际参与的例子；当地准入规划不能直接套用长沙。[常州市政府答复](https://www.changzhou.gov.cn/gi_news/25178399693317)

疾病治疗性质的口腔项目存在医保支付范围，例如阻生牙拔除、牙周疾病治疗；正畸、美白等项目不能因此一并承诺统筹基金报销。具体到患者，还需核对参保类型、统筹地区、待遇状态、定点协议、项目限制和限额。[福建医保2026年说明](https://ybj.fj.gov.cn/bsfw/syldylbzfw/ybbnx/202604/t20260401_7118262.htm)

长沙方案必须使用湖南当前政策。湖南《湘医保发〔2026〕12号》明确口腔项目医保支付政策自**2026年6月1日**起执行。甲类、乙类项目的分类及先行自付比例，还需结合基本医保分担规则；“甲类”不能在患者页面直接翻译为“全部免费”。实施时应取得通知所附口腔支付表及长沙适用文件，核验具体项目和有效日期，不沿用旧答复中的项目数量或比例。[湖南医保支付通知](https://ybj.hunan.gov.cn/ybj/first113541/firstF/f3113607/202603/t20260331_33945644.html) 本次依据为通知正文，附件逐项编码尚未校验。

医保个人账户支付、统筹基金报销和医疗服务价格治理分别处理。种植牙集采或价格降低，并不自动成为统筹基金支付承诺；价格治理通知规范的是收费与采购。[国家种植收费和耗材价格治理通知](https://www.nhsa.gov.cn/art/2022/9/8/art_104_9041.html?type=bgxz) 患者所在位置、就诊地和参保地也须分别记录，不能用定位城市决定医保待遇。

建议将医保纳入商用财务范围，先做湖南一地的目录与合成结算，再与具备定点协议的具体机构完成真实接入。系统需要明确以下责任：

| 业务环节 | 系统需要保留的事实 |
|---|---|
| 机构与目录准备 | 机构医保代码、协议范围及有效期；国家及地方项目映射、价格与支付政策版本 |
| 就诊与费用准备 | 已核验就诊人、诊断及实际执行项目；收费依据与适用目录版本；医保外费用告知与必要同意 |
| 预结算及正式结算 | 真实接口返回的待遇和分担结果、请求编号与外部结算号；超时结果待核实，先查询原请求 |
| 退费与撤销 | 原医保结算的撤销或更正结果及患者退款依据；保留原收费和资金历史 |
| 到账与核对 | 患者自付、个人账户、统筹基金应收、实际到账分别核对；批量拨付与多笔申报之间保留明细分配 |

例如，一张1000元账单已确认基金承担700元、患者承担300元。患者支付300元后，其个人应付可以结清；700元仍是基金应收，直到实际到账核对。收入不能因基金到账再次增加700元，也不能把基金应收挂成患者欠款。该金额仅用于说明模型，不代表实际报销比例。

现有 R1 对账是一条流水对应一笔现金记录，不能直接覆盖医保批量拨付、扣减和多笔申报核销。新增核销规则继续保留独立财务审核，禁止自动生成平账收款。真实接口的字段、签名与接入网络以机构取得的当地接口规范为准。

思维导图：定点协议 → 地区与版本目录 → 身份及实际费用 → 预结算 → 正式结算 → {患者自付、基金应收} → 到账核销与退费撤销。

## 下一阶段顺序

| 顺序 | 业务交付 | 完成门槛 |
|---|---|---|
| C0.4 | 访客首页、附近门店、电话位置营业信息、拟真门店名称、网站与小程序入口衔接 | 无登录可找店；拒绝定位可继续；按已确认距离顺序展示；登录后回到原服务和正确就诊人 |
| C1-WX | 微信账号绑定、手机号核验、渐进建档与原患者关系衔接 | 不按手机号或 OpenID 打开既有病历；患者渠道不激活员工角色；真实授权另行验收 |
| C6.1 | 湖南目录版本与合成医保结算、应收、退费和批量到账模型 | 逐笔业务事实与独立金额核算相符；页面清楚标识合成结果 |
