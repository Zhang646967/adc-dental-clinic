# UX1 页面美观与实用性调研

官方工作流学习 → 当前页面观察 → 明确操作层级 → 保留业务合同 → 浏览器验证。

## 研究方法与发现

本轮采用官方产品文档调研、现有系统启发式评估和真实浏览器检查。尚未组织教师、前台或财务人员的可用性访谈，不把工程检查解释成用户满意度或效率提升百分比。

| 参考 | 可学习的做法 | ADC 本轮落实 |
|---|---|---|
| [Open Dental Appointment Views](https://www.opendental.com/manual/appointmentviews.html) | 工作视图跟随诊所、医生和任务范围；切换入口清楚。 | 始终显示当前身份与诊所；公共导航保留现有授权范围，不合并多店权限。 |
| [Odoo 搜索与筛选](https://www.odoo.com/documentation/19.0/applications/essentials/search.html) | 把相关记录和筛选作为操作入口，保留条件含义。 | 财务首页增加“待审核资金”直达既有服务端筛选；不在浏览器制造账内金额或改变筛选语义。高级筛选及保存视图列入 UX2。 |
| [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) | 窄屏与放大文字时，主要内容仍按清楚顺序阅读。 | 移动端优先登录表单；导航可展开为纵向列表，表格保留自己的横向滚动区域。 |
| [W3C Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | 点击目标足够大或有足够间隔。规范的24px最低要求含例外。 | 本轮主要导航和新增控件以至少44px为内部设计目标；不把局部检查称作完整WCAG通过。 |
| [W3C Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) | 键盘焦点不能被界面遮住。 | 明确焦点边框、原生按钮、跳转主要内容；缩窄页面时将导航内焦点转回展开按钮，避免焦点留在隐藏项。 |

改版前在1440px真实前台页面中，“创建预约”业务卡入口位于页面约1577px处；390px页面导航可见宽354px，内容宽1074px，需要横向寻找功能。这是当前合成场景的观察，不代表所有用户任务的时间测量。

## 首批设计与实现合同

一套 Django 工作台公共壳层，使用原生HTML、CSS和少量JavaScript，不新增前端框架、图表、指标接口、数据库表或业务角色。

阅读顺序为“当前工作范围 → 常用操作 → 实际待办 → 完整模块”。登录页使用一致品牌、清楚表单及员工/患者分流；保留大字简明模式，并增加显式密码显示按钮。按钮只在用户点击时改变显示，提交时恢复密码遮蔽，不保存密码。

中性浅底用于页面、深绿色用于导航、绿色用于主要动作；警示仍有明确文字，不依赖颜色区分财务或诊疗状态。前台快捷入口为创建预约、预约与到诊、查询患者；财务入口为待审核资金、渠道对账和日结核对。所有入口进入原有授权页面。

移动导航的展开状态只存在当前页面，不保存业务数据、患者资料或身份。显示模式沿用既有本机偏好。预约/财务筛选继续由GET地址表达；预览、签名、工作上下文、CSRF、独立复核及原子确认由原服务端操作持有。脚本不可用时，导航和表单仍可操作。

## 验证与后续

使用真实Chrome检查员工/患者登录、七个工作台、当前诊所、快捷入口、键盘操作、密码显示、退出和无脚本路径；覆盖桌面、390px及320px、大字模式和200%文字放大。检查页面溢出、实际输入焦点、新控件点击尺寸及主要文字对比度；记录执行结果，不以截图代替业务测试。

本轮不推测患者年龄、不自动提交业务、不引入未经核实的经营图表。UX2 将细化复杂筛选、长清单密度、接诊和财务表单的分组，再通过真实使用反馈排序。连续治疗、资源排班和容量门槛仍按原路线推进。

思维导图：研究来源 → {视图范围，相关记录，无障碍} → {登录，导航，快捷动作，信息层级} → 原业务授权与确认 → 多尺寸浏览器证据 → 后续用户反馈。
