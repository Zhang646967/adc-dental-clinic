从 `4c29ed4` 建立小程序分支 `workbuddy/patient-service-loop`。本轮小程序实现和微信开发者工具验收由 WorkBuddy 负责，改动范围为 `clients/wechat/`。Codex 负责网页、前台、后端、数据库、隔离环境、合并和发布。本机地址、冻结版本和私有账号指南路径随联调包提供。

## 接口契约

`GET /api/mini/v1/overview/` 保留既有字段，新增 `data.primary_action`。对象始终带 `kind`、`visit` 和 `offer`。`visit` 为现有预约摘要或 `null`。`offer` 为 `{id, expires_at}` 或 `null`。时间为带时区的 ISO 8601，界面显示北京时间。服务端按以下顺序选一项，其他业务仍从原清单进入。

| kind | 内容与页面入口 |
|---|---|
| `CHECKED_IN` | `visit`。查看正在就诊的预约。 |
| `CONFIRM_OFFER` | `offer`。显示截止时间，打开指定邀约。 |
| `UPCOMING_VISIT` | `visit`。打开安排与到诊提示。 |
| `CONTACT_CLINIC` | `visit`。显示「请联系门店核实」，打开指定预约的前台联系方式。 |
| `WAITLIST` | 两个对象为空。打开候补进度清单。 |
| `BOOK` | 两个对象为空。打开服务目录。 |

```json
{"primary_action":{"kind":"CONFIRM_OFFER","visit":null,"offer":{"id":12,"expires_at":"2026-11-05T02:45:00+00:00"}}}
```

```json
{"primary_action":{"kind":"BOOK","visit":null,"offer":null}}
```

旧后端缺少 `primary_action` 时，沿用现有「待确认邀约」「下一次就诊」入口。优先复用已有页面与 `arrangement`，按类型和编号组装本地路径。预约摘要新增 `needs_outcome_review` 布尔值。为真时提示「请联系门店核实」，预约业务状态仍为 `SCHEDULED`。权限或就诊人变化时清空旧数据并重新读取。

候补卡片与详情直接展示后端 `status_label`。`active` 控制接受或拒绝入口，`can_withdraw` 控制退出入口。保留现有到期行补正作为旧后端兼容。预约、改期、接受邀约成功后用回执的正式预约编号进入详情；拒绝和退出查询候补结果，取消查询已取消记录。结果不明确时提供查询入口，并沿用原确认与去重流程。

## 工具验收

1. Codex 从网页提交新预约后，小程序读取同一编号、门店和时间。小程序完成一次改期，回传新旧编号。Codex 通过前台核实到诊，小程序刷新验证同一新约显示在诊。
2. Codex 由前台发布一条合成邀约。小程序核对首页的指定入口及北京时间截止，再按任务提示确认一次。两端对照正式预约编号。另用到期样本核对卡片、详情、关闭答复和仍可退出。
3. 单独样本覆盖取消后查询、时段被抢占、就诊人授权撤销及读取异常恢复。等待前台操作期间保留当前样本；失败后先查结果。

回传小程序提交 SHA、后端提交和镜像、工具版本、操作路径、记录编号、结果和截图。只记录执行过的场景。真机、平台与真实断网分别验收，原 18473 历史证据可继续引用。
