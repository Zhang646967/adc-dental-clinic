# 教师试用交付安排

患者原生小程序 → 共用预约业务 → 教师网站 → 独立云服务 → 分项验收。

目标是课程展示与有限账号试用。保留员工网站，让教师按不同岗位查看完整业务；患者小程序承担查询、预约、普通／邀约改期、候补、取消及结果核对。二者连接同一后端、同一排班及业务数据，不复制患者或预约数据库。

## 当前实施与后续门槛

| 批次 | 可交付结果 | 完成条件 |
|---|---|---|
| B1.5.1 本地患者主链 | 原生工程、分配账号登录、服务时段、预约／改期／取消、历史及人工协助 | 客户端源代码、真实接口、权限与并发、网站兼容及报告分别核对 |
| B1.5.2 微信平台试用 | 可导入的工程、真机检查、教师体验版 | 注册AppID、开发者工具实际编译、合适请求域名、真机运行、教师体验成员扫码通过 |
| G4 教师云端演示 | 固定HTTPS网站、独立数据、通知进程、备份与恢复 | 服务器及SSH信息、域名和证书到位后，按已验证版本部署并实测；电脑关闭后仍可用 |
| B1.5.3 渠道补全及页面体验（本地已实现） | 原生候补登记／邀约、替代改期及患者服务中心 | 五店跨端联调、明确决定和原约保护已验证；微信平台仍按B1.5.2验收 |

小程序渠道复用SU-04、SU-05和SU-40，不按页面重复增加业务用例。微信平台未验证前，报告分别说明已实现的客户端／接口与未完成的平台试用。

## 账号及数据

- 只分配课程合成患者与岗位账号，不开放公共注册。患者身份由已有PatientAccess确定，不按手机、业务编号或微信请求头自动匹配。
- 小程序采用标准会话、CSRF及签名工作身份；每次业务写入重查本人范围。密码和会话不写入客户端持久存储或版本库。AppSecret、SSH密钥和备份密钥不进入前端。
- 云端数据保存在服务端持久卷，网站与小程序使用同一版本。继续使用迁移owner／运行账号分离、HTTPS、入口限速、安全日志、通知与监测、加密备份和独立恢复工具。
- 教师可以浏览业务，也可在课程可写实例按分配身份试办。默认只读部署仍保留；可写只在独立HTTPS部署明确开启，不将本机演示端口直接开放公网。

## 部署条件和成本判断

服务器尚未购买，先不要求购买或发送SSH信息。之后才需要公网IPv4、SSH用户名、本地私钥路径、服务器指纹、实际域名及DNS管理方式；密码、私钥内容、域名Token不发到聊天或GitHub。

以前计划的香港服务器和免费子域名可继续作为网页演示候选，但不能直接承诺用于微信体验版。微信[官方网络文档](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)要求服务器域名经过ICP备案；应优先确认学校已有域名能否用于API，并在微信后台配置成功，再选服务器地区和套餐。这里不自动采购、不承诺未核实的价格或域名适用性。

## 分开的验收清单

1. 本地：分配账号、同一患者两端查询、预约唯一性、重复提交、普通改期、取消跟进、无时段与人工协助；不产生临床或资金事实。
2. 平台：开发者工具编译、手机真机、字体与返回操作、关闭调试后网络、退出和过期、教师体验成员扫码。只有通过后才标记“小程序可在微信试用”。
3. 云端：真实HTTPS、限定账号、静态资源和API、通知进程、证书续期、重启、电脑离线、备份下载及空库恢复；长期观察保留实际时长。
4. 交付：固定网站地址、体验码、私密账号指南、业务演示路线、恢复与期满备份。源代码和正式报告同步GitHub，敏感配置私下保存。

原五店容量与恢复保留原证据，不因增加客户端直接变成云端或微信平台通过；历史Windows数据恢复仍未解决。

思维导图：课程交付 → {患者微信端、员工网站} → {统一账号、业务服务、持久数据} → {本地、平台、云端分别验收} → 教师试用与报告。
