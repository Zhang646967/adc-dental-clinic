# C1-WX 本地账号与渐进身份合同

本地凭证 → 患者渠道账号 → 联络核验 → 建档申请 → 本店前台核验 → 本人档案关联 → 原预约权限。

这是正在实施的本地候选，不是已安装功能。当前交付仍见[C0.4](evidence_c04/release.json)。无注册AppID及真实接口，本批使用明确标注的本地替身；真实微信登录、手机号及平台运行单独验收。

## 账号、手机与患者分别办理

本地维护命令签发五分钟、一次性、分用途的随机凭证，服务器仅存摘要。浏览器和小程序提交凭证，不能自报OpenID或手机号取得身份。合成登录身份按provider、app与subject唯一；首登建立没有员工角色、PatientAccess或临床权限的患者渠道账号。旧账号经原账号密码核对后绑定，换绑、解除及联络变化追加事件；不按同名或手机号合并。

手机号凭证绑定当前账号，模拟来源始终标为LOCAL_SIMULATION，仅接受合成号码。手机号改变不修改患者档案、代约授权或原预约。没有手机授权仍可浏览；正式建档可以沿用前台人工核对路线。账号密码及凭证不进入日志或客户端持久存储。

未关联患者的账号只能查看自身办理状态，提交新档或旧档关联申请。申请不产生正式患者、预约、病历或账单。必要就诊资料由患者提交、前台核对；过敏保持未知至原接诊复核。旧患者须由有本店核验职责的前台明确选择本店可见档案并记录内部依据号，不向申请人透露检索到的其他档案。

前台以当前诊所及核验职责办理，原技术管理员不代替业务身份核验。创建完整新患者、PatientAccess及批准事件在同一事务；旧档关联不重写患者资料。原本人关联暂停后，只能申请复核同一档案，由另一名有本店职责的前台审核恢复原PatientAccess行；不更换患者或另造档案，账号安全停用仍须先完成技术恢复。一个账号／患者保留原一对一本人关系，重复或并发审批返回唯一结果，撤权和旧预览不产生部分记录。已有本人关系不能通过申请换绑。

批准后须由患者明确激活患者上下文；GET不会自动选患者或生成预约。原网站、小程序的PatientAccess、代约期限与版本、统一预约／改期／候补继续负责业务权限。登录身份和手机核验不授予预约代办、临床同意或员工角色。

## 模块与验收

账户模块拥有外部身份、一次性替身凭证、账号联络及追加事件；患者门户拥有建档／关联申请与前台决定，患者模块继续拥有完整档案。追加迁移保留现有52份，物理ER只纳入实际PostgreSQL观察结果。

验收覆盖：首登无患者权、旧账号显式绑定、重放／错用途／过期凭证、共享号码及换号不合并、解绑历史与恢复入口、旧档不泄露、新档原子审批、旧预览与撤权、并发唯一结果、七角色与跨店拒绝、网站／小程序完整旅程及原预约权限。准确CI、独立恢复、正式ER／报告及保护更新分别归档；候选不能替代执行结果。

官方依据：[登录流程](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)、[服务端校验](https://developers.weixin.qq.com/miniprogram/dev/server/API/user-login/api_code2session.html)、[手机号组件](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/getPhoneNumber.html)。普通微信登录返回平台身份标识与会话材料，不能据此填写居民身份证；手机号能力及使用资格以实际主体开通结果为准。

思维导图：凭证及账号 → 联络来源 → {新档申请、旧档核验} → 前台本店决定 → 本人关联 → 原患者／代约与资源规则。
