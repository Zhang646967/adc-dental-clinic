# P1.5 完整画像与小程序患者入口

门店能力核对 → 资料审核 → 两端选诊 → 就诊人核验 → 统一预约 → 本人就诊与结算。

患者主要使用微信小程序，网站保持同一服务、授权及资金口径。当前使用课程合成资料，真实微信身份与短信仍等待平台配置。

## 能力与职责

八城二十店逐项补齐初诊检查、洁牙与牙龈护理、牙痛评估与基础修复、复诊四类基础服务；正畸、缺牙修复按既有差异配置，长沙星沙增加前台核验监护关系后的儿童服务。医师介绍、适配服务、独立专业授权、营业、排班、椅位和必要设备分别核对。医师本人提交，主管审核采用，前台继续负责排班。旧介绍、图片、预约、审核及财务历史保留。

每店三幅自有课程插画分别表示门头、接待和诊室；六十名医师按实际方向、沟通、经历和任职改写介绍，使用可区分的插画头像。资料标明合成来源，不显示真实资格认证。配置通过 `scripts/course_profile_alignment.py` 调用既有版本化业务命令办理，不能用资料更新制造治疗和收费。

## 患者办理

小程序四个主入口为主页、预约、就诊、我的。主页匿名找店选医；预约按服务、门店、医师与实际出诊日办理；就诊集中原预约、候补、自述、方案、转诊和本人结算；我的管理账号与就诊人。员工使用独立网站入口。

门店、服务、医师和日期贯通登录与就诊人选择；意向十分钟有效，不携带权限。未选日期使用当前组合首个真实出诊日；改期保留原服务并先显示原预约日。撤权或配置变化清除旧候选，由患者重新核对。一般代约不能办理仅限监护人的儿童服务，也不能查临床或账单。

不支持特色服务时推荐实际支持的同城门店；本市没有时明确说明。无排班与该日无可用组合分别提示。查询从不占位；正式预约、改期、取消及候补接受仍使用原事务、锁与占用约束。

本人结算单为原生只读页面，支持发布版本、项目、金额与当前已记账收退款余额。旧版本金额不变，当前余额适用版本单独标明；待审款不计为已收，未开单不显示为免费。访问失败清除旧页面，代约无账单入口且后端拒绝编号猜测。

## 接口与读取

- `/api/mini/v1/discovery/index/`：完整轻量索引，未压缩JSON不超过100KiB。坐标留在客户端，先对完整索引筛选排序，再分批展示。
- `/api/mini/v1/discovery/services/`：分页服务、数量及真实替代方案；网站复用同一筛选查询。
- 门店、医师详情按需读取介绍、图片和出诊，不在首屏重复下载全团队与日历。
- `/api/mini/v1/invoices/<id>/`：本人只读，重用发布账单与财务余额投影，记录既有敏感读取审计。

旧接口兼容，64份迁移不变，ER与观察到的PostgreSQL结构一致。

## 需求与验收追踪

| 业务问题 | 岗位及规则 | 可观察结果与测试 |
| --- | --- | --- |
| 门店有介绍却无法办理基础服务 | 主管配置能力，前台排班，独立专业核验 | 二十店四类矩阵；广州越秀基础修复回归；逐店实际成约 |
| 空筛选结果无法继续 | 两端共用服务选择查询 | 分类数量一致；实际同城替代；无同城明确说明 |
| 选医后日期丢失 | 短时意向保留医师、服务、门店与日期 | 登录恢复、患者切换、首个真实出诊日、旧配置拒绝 |
| 任意委托误作儿童监护 | 本店前台核验PARENT/GUARDIAN关系 | 一般委托拒绝；有效监护代约；跨店、撤权及旧预览拒绝 |
| 小程序无法看本人账单 | 复用只读结算发布与资金口径 | `tests/test_patient_alignment.py` 本人、代约、跨患者、撤权、历史、待审资金及审计 |
| 首屏过大 | 完整小索引，列表批量读取 | 100KiB上限及二十店查询增长检查；列表与详情分离 |
| 页面检查不能证明实际可用 | 工具连接真实后端，手机单独操作 | 工具控件、手机机型/微信版本分别归档；不以模拟响应替代 |
| 更新损坏原历史 | 加密备份、同版本空库恢复及保护更新 | 图片字节、版本和全部事实比对，准确提交CI及两套实例核对 |

工程记录见 [P1.5验收](evidence_p15/README.md)。历史Windows恢复状态与既有UNKNOWN/UNDETERMINED事件继续保留。
