# C3.2B2 与 C3.2C 医疗代理与治疗前核对

本增量处理指定步骤的医疗代理和实际治疗前核对。课程合成资料用于验证软件业务，专业适用性、纸质原件和可靠电子签名分别验收。归档、处方、真实平台和云部署继续按后续计划办理。

## 责任与业务合同

1. 本店前台先取得单独的 `can_verify_medical_proxy_identity` 职责，默认关闭。受理患者、实际代理人、材料及原件编号、具体情形、诊所、方案步骤和期限，不读取临床正文。
2. 负责医师核对当前临床适用性；疑难事项转另一名具有既有专业审核职责的医师。代理人、资料整理人和身份核验人不能切换岗位审核自己的办理，主管不审批医疗适用性。
3. 未成年监护和适用成年书面委托分别记录。年龄、亲属关系、微信登录、联系人及预约代办均不能单独建立医疗决定权限。材料修订追加版本；暂停、撤销、到期及患者身份变化停止新增办理。
4. 患者选择就诊人时分别显示医疗与代约权限。仅有医疗权限可进入指定步骤的方案及医疗问答，不能预约、读取完整健康自述或账单。未生效或结束的账号只能查其相关办理状态，不暴露未核验患者身份和材料。
5. 代理的方案选择保存 `PROXY` / `MANUAL_PROXY` 来源与确切代理版本；具体医疗同意另行告知和决定。告知指定本人或代理，账号事件保留实际提交人，纸件仍由负责医师登记。
6. 未答疑问、本人拒绝和签署人冲突进入负责医师核对；换版不继承旧同意。不同代理在重叠期限内不得同时覆盖同一步骤。不按最后一次提交自动选择代理人。
7. 专业审核医师逐实际项目发布版本规则：具体同意、沟通记录、需专业判断。启用前完成当前在用项目规则；未知项目保持待专业判断。已有医疗决定办理不能切换为沟通类以跳过待答疑问或撤回。
8. 负责医师保存开治核对，绑定准确患者、位置、检查、方案、规则、医疗决定、代理和资源依据。核对不生成治疗、费用或资金。真实执行再检查；每份核对最多引用一次，其他步骤的普通执行不机械重签。
9. 真实已发生但缺事前资料的治疗通过独立补记路径记录实际时间及缺口，仍使用原实际与唯一收费来源。另一名有职责且具有具体读取范围的医师复核；原缺口保留，不倒签或补造事前通过。

## 事务与数据

保留67份原迁移文件，追加8份；新增4张代理材料及范围表、5张临床规则／核对／复核表。方案选择和医疗事件追加准确代理来源，实际执行追加一对一核对引用。原记录保持原语义，未知材料不补造。

签名预览绑定当前工作区和授权版本；确认重新核验账号、岗位、患者、方案和依据，保留统一参与账号及既有患者／方案锁序。正常开治和撤回、授权撤销与决定、同一请求重试通过独立PostgreSQL连接验证。数据库保留版本、作者及一对一实际来源；任意DB管理员绕过业务命令不构成岗位授权承诺。

结构图来自独立PostgreSQL只读核对，当前158张SQL表、157张ORM表、451条外键和128项业务触发器。38幅ER中新增医疗代理、开治和缺口视图，原医疗告知视图扩展代理来源；全字段、可空性和唯一关系另见数据库目录。具体发布状态以验收记录为准。

## 设计来源

《病历书写基本规范》第十条将本人、法定代理人与患者因病无法签字时的授权人员区别规定，本功能用独立材料与医师确认表达适用责任，不将账号点击当作资质认定。[国家卫生健康委员会原文](https://www.nhc.gov.cn/wjw/c100175/201002/b1bec53d90f243e0861529723f00221a.shtml)

《医疗纠纷预防和处理条例》要求据实书写保管并禁止伪造病历。这里保留真实发生和缺口，紧急抢救相关资格与时限另行核验，不由普通补记自动推定。[国家行政法规库原文](https://xzfg.moj.gov.cn/front/law/detail?LawID=438)
