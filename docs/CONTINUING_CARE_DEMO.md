# 连续诊疗与复诊协同演示

实际到诊 → 确认检查 → 方案与本人决定 → 加工准备 → 分阶段实际治疗 → 后续资源预约 → 收退款与逐笔对账。

此路线使用分配的合成账号和课程资料。员工使用网站，患者本人可使用网站或匹配的原生小程序。账号凭据从本机私有交付材料读取，不放入仓库。原系统升级不自动制造新临床记录；需要新案例时按下列正常业务办理。

| 岗位 | 办理步骤 | 核对结果 |
|---|---|---|
| 前台 | 从本店日周排班核对服务、医师、椅位与设备，选择已建档合成患者正式预约，再进行到诊登记 | 正式成约与实际到诊分别记录；未到诊不能生成检查 |
| 患者本人 | 在“我的健康自述”明确提交已知／未知事项 | 本人自述保留独立版本，不直接成为医师确认事实 |
| 负责医师 | 从“临床检查”打开本人负责的实际就诊；记录面谈、牙位牙面及检查，预览并明确确认 | 未知保持未知；原确认版本与后续更正可查 |
| 负责医师 | 建立治疗方案，配置具体服务、步骤、预计费用、计费时点、互斥选项及加工依赖，再发布确认版本 | 估算不收费；未知金额不是零元；目录定义随版本保留 |
| 患者本人 | 网站“我的治疗计划”或小程序打开确切步骤，选择认可／暂缓／不选择，预览后确认 | 新版本重新决定；预约代办不能读取或决定临床方案；讨论决定不等于专业知情同意签署 |
| 医师、前台 | 需要加工时，医师从确认检查登记要求；前台在“加工送返”认领责任，手工登记送出、延误、返回 | 原需要日期和原预约保留；返回不等于临床就绪；前台不读取临床规格 |
| 负责医师 | 在“加工验收”核对当前物理周期与确切步骤，明确通过或返工；返工后重新送返验收 | 只有全部有效依赖满足才允许实际执行；新版复用也须明确核对 |
| 负责医师 | 登记本次实际项目、数量、位置、时间和部分／完成状态，确认后按实际关闭接诊 | 完成时计费步骤的中间阶段可以明确不另收费，但仍为已治疗；完成阶段只有一条原收费来源 |
| 医师、前台 | 医师明确下次服务、日期窗口和完成标准；前台在“复诊联系”认领责任与期限、记录联系、关联正式预约 | 预约和接通电话不算复诊完成；本人暂不继续转医师核对，不自动取消原约 |
| 前台 | 遇到改期或设备故障时，进入原排班／资源协调办理；同时间同医师可明确替换兼容资源，改变安排须核对患者同意 | 原预约关联和唯一后继保留；故障阻止重复接诊，不静默挪动患者 |
| 医师、前台 | 后续真实接诊达到原标准并关闭后，前台选择实际检查或指定步骤完成依据 | 部分治疗不提前结束目标；迟到照实保留原建议窗口 |
| 前台、财务 | 对实际结算单申请收款或退款，由不同财务账号审核；主管导入合成渠道CSV并提议逐笔匹配，再由不同财务账号确认 | 临床、开单、净收款、未收及渠道证据各自一致；匹配和退款均不重写原治疗 |
| 主管、总部 | 查看复诊及加工状态、未承接与逾期数量 | 不出现患者联系文字、临床规格、本人决定或医师验收详情；状态数量不是临床结果率 |

关键异常：旧预览、患者切换、权限撤销、重复确认、并发争用、加工延误／返工及预约取消，都应返回当前事实和继续办理入口。成功提交断网后使用原提交核实，不另建一次业务。

思维导图：同一患者 → {本人自述、医师检查、方案版本、实际执行} → {前台资源预约、复诊责任、加工就绪} → 独立开单／资金／渠道核对。
