# P1 医师、门店与月度经营核算

患者先了解门店和医师，再选择实际服务；员工按职责提交和核对资料；经营核算从原始业务事实追踪到保留的月报版本。

## 责任与界面

| 岗位 | 办理范围 |
|---|---|
| 医师 | `/profiles/` 提交本人介绍；查看本人工作及经营汇总 |
| 门店主管 | 当前门店画像、医师版本采用与任职；提交本店月度成本 |
| 前台 | 继续负责日周排班、调班、原承诺协调；查看本店履约，不读取经营成本 |
| 财务 | 独立复核成本、确认完整性、留存月报；总部费用由另一财务账号复核 |
| 总部 | 全链聚合经营投影，不取得患者或画像内部来源 |
| 技术管理 | 原目录与账号职责；无画像发布、诊疗或成本复核权限 |
| 患者／代约人 | 匿名浏览公开资料；登录并核验就诊人后按原权限预约、改期及候补 |

网站入口为 `/clinics/`、`/clinics/<id>/`、`/dentists/`、`/dentists/<id>/`；原生微信客户端新增门店、医师目录及医师详情。两端使用同一公开投影。内部核算入口为 `/operations/management/`，全链汇总为其 `chain/` 子路径。没有新增外部业务写入 REST API。

## 资料与任职

- 医师统一身份跨店复用；每对医师—门店任职唯一，保存常驻／轮诊、起止日期、状态和所采用版本。任职不授予专业权限，公开介绍也不代替资格核验。
- 草稿可一次保存；提交版本、审核决定与发布历史保留。主管只采用本店版本，其他门店不自动替换；新草稿和退回保持旧发布，撤回介绍只隐藏展示。
- 本人不能通过换岗自审。确认重核账号、当前门店、提交版本与授权；重复操作返回已保存结果。
- 启用任职控制前核对原未来出诊、预约、在诊及有效邀约。退出阻止新增出诊和成约，原承诺进入前台协调，不自动取消、搬迁或变更治疗。
- 头像与每店最多三图采用项目自制插画。上传最多5MiB，经像素检查、EXIF旋转及重新编码后保存JPEG字节、摘要、尺寸和说明；发布前只限相应岗位读取。图片、版本和采用历史随加密数据库恢复。

## 选诊与原预约合同

城市、区域、服务及线上预约条件可筛选；主动定位后由近到远排列。门店地址与电话分别呈现一次。营业、服务、设备及医保状态从原所属模块读取，未知值保留。

医师／服务意向可跨普通登录恢复，但它只表达选择。具体就诊人、代约关系、医师专业范围、任职、出诊和椅位设备在原成约事务重新核验。改期与候补仍调用原业务命令，不自动替患者选人、改时间或接受邀约。无可用时间时提供同店医师、同城门店和候补入口。

公开读取批量准备团队、服务、营业与近期出诊；图片和详细排班按需读取。内部证据、家庭地址、联系方式和患者资料不进入公开投影或总部汇总。

## 指标字典

| 指标 | 时间／粒度与来源 | 分子分母、缺失与解释 |
|---|---|---|
| 到期履约 | 预约计划结束时间已到；原就诊状态与取消发起方 | 沿用取消分析的到期分母；改期原单不重复计数；未核实单独显示 |
| 排班负荷 | 本月计划预约与有效已发布出诊区间 | 保留预约分钟 ÷ 出诊分钟；暂停接单仍是已发布工时；零工时显示未知 |
| 候补暂占 | 未到期PENDING邀约 | 单列分钟；过期不计入，不能当正式预约或实际治疗 |
| 完成诊疗产值 | 完成时间属于本月的逻辑账单 | 每账单只取当前发布版本；改版重算当前月报，新月报保留差异 |
| 患者净收款 | 已POSTED患者资金的业务日 | 收款减退款；跨月分别入期，不增加产值 |
| 基金净到账 | 已CONFIRMED银行凭据的业务日 | 到账减退回；医师归属仅取已确认分配，不重复汇总银行与分配 |
| 已确认成本 | 归属月份、当前已确认成本版本 | 包含直接与公共成本；登记不付款，旧季度台账不自动导入 |
| 管理利润 | 完成本月诊疗产值减已确认成本 | 全部8类完整或明确为零，且无待审和来源金额差异时才给出 |
| 现金余额 | 需要已核实期初与账户范围 | 当前未建立期初余额核验；明确标为待核对，净收款不能充当余额 |

履约支持门店、医师、服务与月份筛选；财务按完整门店月份归集，医师只查看本人贡献。服务筛选不虚构公共成本的服务级分摊。页面说明统计截至时间、到期分母、计划时长和缺口。

## 成本与版本

类别为耗材、人工、租金、水电物业、维修、折旧、营销及其他。主管提交本店，财务独立核对；总部提交与复核账号不同。金额、来源和归属不可覆写，修订另记并引用上一笔。维修／保养来源不得重复跨月入账，设备采购不冒充维修或折旧；设备来源更正后，当前利润先回到待核算，补充成本修订后再确认。

直接成本归属医师。店内公共成本按该月已发布出诊分钟分配，先向下取分，再按稳定医师编号分配尾差；分摊加未分摊严格守恒。无工时保留在门店，总部成本默认留总部。

每一成本类别需明确核实完整或为零，新记录使旧完整性依据失效。月报在一致快照上确认，保留账单版本、资金事实、成本、设备费用版本、工时及分摊政策。后续更正形成修订版，旧报告可读。此为管理核算，不自动发薪、缴税或建立完整财务总账。

## 结构与验证

保留原62份迁移，追加注册画像和月度核算两份迁移。实际PostgreSQL17结构为142表、388条外键、110项业务触发器。四个新视图位于[数据库文档](database/README.md)：身份任职、公开画像、预约资源、经营核算。JSON来源快照是逻辑追踪，不伪画SQL外键。

[需求到测试追踪](evidence_p1/requirement_trace.md)与[执行证据](evidence_p1/README.md)区分规则、PostgreSQL、真实Chrome、原生离线编译、容量、恢复及安装结果。微信真机、真实短信与独立云端仍单独验收。

思维导图：公开画像 → 版本审核与任职 → 患者选诊 → 原授权与资源核验 → 履约 → 产值／回款／成本 → 工时分摊与月报修订。
