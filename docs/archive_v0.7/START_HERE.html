ADC v0.7 — 独立工作台、手动操作引导、候补与有限排程

逻辑链：登录 → 选择身份 → 进入角色工作台 → 主管/前台再选诊所 → 完成获授权的业务。

这是供本地 Docker 集成验收的候选源码，不是已在用户机器升级、通过全部验收或已部署公网的版本。以 v0.5 原源码为基础，累计包含 v0.4/v0.5；v0.6 只有规划，不需要安装。保留全部原迁移，新增2份迁移、4个对象。

本轮源码

  • 七个独立工作台：患者、前台、牙医、诊所主管、总部、财务、技术。登录总是先选有效身份，即使只有一个。
  • 主管/前台先进入工作台再选择诊所，顶部可切换身份和诊所。角色和诊所不合并成一个选项。
  • 服务端工作上下文、签名表单令牌和修订号。切换后旧标签页提交被拒绝；授权仍需数据库重查。
  • 19份维护过的任务指南（准确数量见目录与证据文件）：在哪个页面、点哪里、填什么、怎样核对。步骤按钮仅推进说明，不点击业务按钮，不提交表单。普通帮助无需外部API。
  • 双端助手沿用可选服务端模型接口；模型只识别受限意图，回答采用当前角色的已维护页面/按钮目录；无钥模式明确不是远程AI。
  • 候补登记/退出、有限建议、主管发布限时邀约、本人患者/前台明确接受或拒绝、主管/前台明确回收过期邀约。
  • 排程是固定30分钟的有限二部图最大匹配，不是通用医疗排班。最多60条需求、80个出诊块、200个候选单元；页面显示达到上限的提示。只对枚举范围最大化安排数。
  • 既有建档、预约、接诊、账单、有限数字更正、季度核对与运营分析保留。

不声称完成

没有诊疗椅/设备容量、跨店通勤优化、医学资格适配、短信/邮件推送、自动后台候补派送、支付/退款、完整账号目录维护、全部终态纠错、真实模型评估或公网发布。不得将技术工作台的有限说明页当成完整后台管理。

重要行为变化

  • 原来多角色导航按所有绑定合并；现在HTTP上下文只激活一个角色，主管/前台只激活一家店。
  • 原员工跨店改期服务仍保留，但当前工作台只允许同一已选诊所内的普通改期。不能偷偷借另一家店授权；跨店重新就诊可以切店后新建，未来可单独设计显式跨店改期用例。

  • 过期邀约时间一到即不再阻塞新预约；其状态需主管/前台明确回收后重入匹配。本版不是自动后台通知系统。

v0.7 实现合同与发布边界

状态机

工作身份：登录 → 未选身份 → 已选身份 → 主管/前台未选店 → 已选店。切角色清clinic并增revision；切店保留role并增revision。HTTP读取重查有效身份；写入在事务中锁用户和数据库上下文再比较版本。一个账号的不同浏览器会话可独立工作；同一会话多标签切换会使旧表单失效。

候补：WAITING → OFFERED → BOOKED；拒绝/明确回收过期 → WAITING；退出 → WITHDRAWN并撤回未确认邀约。BOOKED后的预约取消走原预约流程，不逆向删除候补历史。

建议：DRAFT只保存建议，不占位；PUBLISHED在事务中建立限时WaitOffer并更新等待状态。建议超过15分钟须重算。邀约有效期为发布后15分钟与预约开始时间的较早者。到期严格拒绝确认，时间过后不再计有效保留。

优化合同

输入仅当前选中诊所的未来等待请求、已安排出诊块、全链同患者/牙医的预约和有效邀约冲突。枚举固定30分钟单元；相邻半开区间不重叠。由于出诊块本身对牙医不重叠，每个候选单元可视为一个容量1节点；一位患者最多一条有效候补，形成二部匹配。

目标只最大化枚举图中的匹配数，算法为确定性增广路。先处理登记较早的请求，后请求可重排前请求的可行单元，但不删除其已经获得的匹配。不是临床优先级，不含车程/椅位/设备/可变时长/病情/价格/个人年龄权重。不改变已确认预约。

发布前重新锁住相关资源、检查授权、状态、修订号、时间和占用；一批全部发布或全部撤销。普通创建也检查保留，接受时在同事务释放自己的保留并创建预约。跨表占用依赖公共服务的advisory锁协议；不是声称任意SQL绕过服务也由排斥约束保护。

操作引导合同

指南目录版本NAV07.1。指南拥有角色、固定route名称、真实字段selector、解释与核对条件。动态记录必须先由用户从已授权列表选择；助手不从模型提供的URL选患者。当前页面已是详情时保持原对象。换角色/店后目录与步骤重置。

“下一步”只推进说明；永远不能代表业务成功。不自动点击或提交。目标控件找不到时仍显示文字说明，不伪造成功定位。原Chat Completions适配器继续可选；无key有本地指南；demo/fallback均明确标签。没有实际模型准确率或费用证据。

规模和生命周期限制

默认一次最多60条需求/80出诊块/200单元。不是承诺百万行数据下的速度；本版没有压测。数据库会保留历史上下文、建议、调用元数据；生产前应确定保留策略及受控清理。普通维护暂不提供长期自动worker或事件投递服务。

发布条件

须运行所有迁移、197项真实PG方法、多角色浏览器主流程、并发预约/邀约竞争、真实备份恢复，随后才能评估公网配置。仍保留production.py阻断，不自动开放公网，不调用真实患者/支付/消息服务。

  1. patient_demo_a在患者台登记甲店未来14天内的时间范围（连续至少30分钟；不能使用已经过去的seed日期）。无治疗诊断输入。
