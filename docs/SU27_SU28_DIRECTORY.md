# SU-27／SU-28：基础目录与资格关联增量规约

需求基线：R4.4 + SU-26。候选实现：v0.9.0-alpha.5。
本文件是新增项目需求及设计决定，不替换既有临床/财务用例；Mac迁移暂停。

## SU-27 登记基础目录资料

**主执行者：** 当前激活SYSADMIN的技术维护人员。无外部模型/短信平台作为辅执行者。

**涉众利益：** 运营人员希望新诊所和新牙医可供后续业务使用；牙医希望身份和联系资料准确且不被过度公开；原有患者/牙医不希望登记动作改写既有预约、治疗或账单；维护人员需要可核对的失败反馈和责任记录。

**触发：** 技术维护人员依据已经人工核对的合成资料请求登记诊所、牙医或资格类别。

**前置条件：** 会话有效且已激活技术身份；凭据、授权、编码唯一性和输入合法性由本用例检查，不提前假定全部成立。

**基本路径：**
1. 技术维护人员提交目录类别、编码、基础字段和登记依据，请求核对。
2. 系统验证当前权限、字段范围和模型约束，核对现有编码；反馈拟登记内容及影响，尚不保存。
3. 技术维护人员核对目标和资料，提供自己的技术管理密码并明确请求保存。
4. 系统重新核验当前身份、工作上下文、确认期限、密码和唯一性；同步保存目录资料及审计。
5. 系统反馈稳定的业务对象和后续人工入口；账号授权、资格关联及出诊安排分别办理。

**扩展路径：**
- 2a 字段缺失、隐藏字符、编码不合格式、未来出生日期、非法面积或邮箱：系统指出问题，不登记。
- 2b 已有相同编码或员工编号（含停用记录）：系统拒绝重复，不覆盖、不恢复，不凭同名自动合并。
- 3a 维护人员放弃：不保存。
- 4a 密码错误、未明确确认、撤权、旧上下文或过期令牌：不保存，要求重新核对。
- 4b 他人已登记同一编码：本次不覆盖，提示查询既有记录。
- 4c 同一成功操作重试：先核对当前权限与确认期限，再返回原结果；不重复保存。
- 4d 保存或审计失败：目录与审计一起回滚。回执未知时先查询原编码，不断言前次失败。

**成功后置条件：** 新增一条所选目录记录和相应事件；没有自动新增账号、角色、出诊、预约或账单。

**最低保证：** 失败不留下半次登记；既有资料和历史单据保持原值。只读实例不执行保存。

**字段列表：**
- 诊所：clinic_code、name、postal_address、supervisor_name、phone、email、area_sqm。
- 牙医：employee_no、name、date_of_birth、home_address、phone、email。
- 资格类别：code、name。
- 控制字段：固定登记依据、操作者密码（不保存）、明确确认、受签名保护的当前上下文/操作编号/期限。

**设计约束：** 本轮不提供既有身份信息纠错、目录编辑/删除/停用。新目录默认可用，仅表示当前基础记录，不等于完成入职认证；主管联络姓名也不构成账号授权。列表隐藏个人联系地址/出生日期，技术详情受限可读。本课程仅使用合成数据。

**追踪：** BR-D01/02/03/05/06；AT-D01/02/04/05/06/07/08；目录字段来自既有registry模型。真实HTTP/PG验证待执行。

## SU-28 维护牙医资格关联记录

**主执行者：** 当前技术维护人员。

**涉众利益：** 运营人员希望准确记录牙医的多项资格类别；牙医希望误关联能够纠正且历史不被删除；患者希望不能以目录操作自动决定诊疗安全或撤销已有安排。

**触发：** 维护人员请求新增关联、撤回误关联或恢复原关联。

**前置条件：** 当前技术身份有效；牙医与资格类别存在。是否可关联、是否停用和是否重复由本用例核验。

**基本路径：**
1. 技术维护人员指定牙医和资格类别，说明拟登记、撤回或恢复，并提交相应依据。
2. 系统核对当前记录及有效标志，反馈当前关联、拟进行动作和影响，生成状态预览；不保存。
3. 技术维护人员核对员工编号、资格类别和动作，提供技术密码并明确确认。
4. 系统再次核验权限、上下文、期限和关联快照；同步更新关联记录及审计。
5. 系统反馈该牙医的当前关联列表，不替维护人员办理账号或接诊变更。

**扩展路径：**
- 2a 已有有效关联：拒绝重复登记。
- 2b 已有撤回记录：使用恢复依据，保留同一关联编号，不新建第二条关系。
- 2c 牙医或资格类别已停用：拒绝新增/恢复；撤回现有误关联仍可按本用例核对。
- 2d 关联不存在或已经撤回：拒绝再次撤回，不删除记录。
- 4a 预览后任一相关状态已变化：拒绝旧预览；即使值改回原值，审计游标改变仍使旧预览失效。
- 4b 密码、权限、签名、期限或只读模式不符：拒绝，不改变原关系。
- 4c 同一成功操作重复确认：返回原操作的关联对象，不撤销其后的合法变更。
- 4d 审计/保存失败：本次关系变化回滚；无法核对回执时反馈未知并指向查询入口。

**成功后置条件：** 仅新增或改变所选DentistQualification当前有效标志，历史编号、原notes和原事件保留。

**最低保证：** 不改变Patient、UserAccount、RoleAssignment、AvailabilitySlot、Visit、治疗或Invoice；不执行专业许可认证；不将缺失关联解释为无资格。

**字段列表：** dentist_id、qualification_id、attach/withdraw、依据类别、关联状态快照、操作编号、当前上下文及其修订、操作者密码和明确确认。

**设计约束：** 模型没有资格有效期、核验机构、执业地点或医学适配规则。撤回“误关联”不同于撤销行政资格，也不同于安全封禁；账号封禁和业务交接仍使用各自受控流程。

**追踪：** BR-D01/03/04/05/06；AT-D03—08；真实HTTP/PG与两连接竞争待执行。

## 业务规则及状态表

|编号|规则|
|---|---|
|BR-D01|当前有效技术角色+当前上下文；超级用户标志、另一角色或直接URL均不能替代授权。|
|BR-D02|固定三类登记字段、唯一编码、正面积及有效日期；不以新编号绕过实体查重。|
|BR-D03|预览不是保存；15分钟确认期、操作者密码再验证、明确确认；签名防篡改而不加密。|
|BR-D04|资格关联稳定编号；有效→撤回→恢复不删除历史；状态快照包含最近关联审计游标。|
|BR-D05|目录/关联与审计同事务；同次成功确认的有效重放不重复写；无隐式账号/排程/账单操作。|
|BR-D06|只读实例拒绝业务写；审计不复制原始地址、生日、电话、邮箱或密码。|

|当前关系|请求|结果|
|---|---|---|
|未关联；牙医/资格均可用|登记|新建有效关联|
|有效登记|登记|拒绝重复|
|有效登记|撤回误关联|原行标为撤回|
|已撤回；两端可用|恢复|原行标为有效，编号不变|
|未关联/已撤回|撤回|拒绝|
|任一端停用|新增/恢复|拒绝|
|预览后修改→恢复原值|旧确认|拒绝（审计游标变化）|

## 验收组

AT-D01：三类合法/非法字段与无副作用预览。
AT-D02：唯一编码、停用重名、并发同码只有一条。
AT-D03：新增/撤回/恢复关联及保留编号、notes、账单。
AT-D04：当前角色、直接URL、撤权、停用、上下文、CSRF。
AT-D05：密码、显式确认、过期/篡改、重复操作及ABA。
AT-D06：审计失败回滚、个人字段不入审计、回执未知处理。
AT-D07：只读实例、无GET写入口、未生成账号和出诊。
AT-D08：真实模板/移动端/键盘路径与原业务主链回归。

验收组是检查目标，不是八项已经通过的真实验收。
