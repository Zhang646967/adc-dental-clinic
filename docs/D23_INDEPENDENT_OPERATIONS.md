# D2.3 独立运行

服务恢复 → 监测确认 → 加密备份回读 → 独立恢复。

## 隔离演练

| 场景 | 结果 |
| --- | --- |
| 服务停止并重新启动 | 网关停机状态可识别，恢复后 HTTPS 和监测通过，164 组记录一致 |
| 通知进程停止 | 监测识别为严重故障，重启后恢复健康 |
| 本地证书换发演练 | HTTP-01 路径可读，证书与私钥不匹配时拒绝重载，合格证书经重载后实际对外提供 |
| 加密备份及回读 | 使用模拟对象存储传输实际密文，完整回读校验。模拟上传失败时保留此前验证的恢复点 |
| 独立空库恢复 | 167 张表、25,172 条记录比对一致 |
| 小程序 AppSecret 文件 | UID 10001 的 Web 容器读取合成密钥，文件只读挂载且专供 Web。通知和维护容器使用原有运行配置 |

演练沿用 D2.2 已验收的应用镜像，D2.3 准备工具负责生成密钥挂载配置。证书演练使用本机证书。服务器端证书自动续期、真实对象存储、SSH 发布和 24 小时运行观察在目标环境验收。

## 配置小程序 AppSecret

首次准备直接 HTTPS 的课程部署时，在原有准备命令增加以下参数。使用配套的 D2.3 源码和部署包，服务器侧控制器也需要识别 Web 专用挂载。

```sh
--wechat-mini-app-id YOUR_APP_ID --wechat-mini-secret-file /PRIVATE/wechat-secret.txt
```

原始文件使用仅所有者可读的权限，值为一行 AppSecret。准备工具将副本放入部署私有目录并以只读文件挂载至 Web。服务器的部署目录须维持仅所有者可访问。备份恢复后，操作员从单独保管的原始密钥重新配置。实际微信登录及平台验收使用真实 AppID 和对应域名另行执行。

思维导图：独立运行 → {HTTPS、通知与监测、Web 密钥} → 加密备份 → 回读 → 独立恢复 → 目标机持续验证。
