# 小程序业务追踪

| 问题与岗位 | 可观察行为及约束 | 已执行证据与后续 |
|---|---|---|
| 教师需要原生患者渠道 | 导入原生工程，课程账号进入本人工作台；员工身份不混入患者会话 | 32项真实接口／并发、原生源代码及Page联调；微信工具编译待执行 |
| 网站和小程序争用排班 | 候选不占位，确认复核椅位、设备和医师；只产生唯一预约 | `test_native_and_website_compete_for_same_chair`、`test_http_resource_race_between_two_patients` |
| 患者普通改期与取消 | 明确确认原新安排；失败保留原约，成功保留前身和后继，取消单独留原因 | 五店客户端与网站结果、48项数据库事实；候补邀约仍由网站或前台办理 |
| 重试与会话失效 | 登录旋转CSRF，撤权／密码变化拒绝旧会话；预约重试返回同一结果 | PostgreSQL接口及59项源代码／传输检查；不自动重试业务POST |
| 财务和临床边界 | 预约不制造治疗、账单或收付款 | 原合成资金预期不变，新业务记录无账单 |
| 最终教师远程试用 | 员工网站和患者小程序共用独立云端数据，课程账号受限 | 本地实现；AppID、微信平台、域名、服务器及云端验收待完成 |

小程序是SU-04、SU-05和SU-40的渠道扩展，不另凑业务用例。六幅ER继续描述同一69表结构，本阶段无新增实体。正式报告将实现范围与平台试用状态分开。
