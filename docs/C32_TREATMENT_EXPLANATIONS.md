# C3.2A：具体治疗说明与方案版本

医师逐项准备 → 明确预览确认 → 本人查阅准确版本 → 变化后复核 → 保留旧说明。

本批交付具体病例的治疗说明准备与双端查阅，复用既有治疗方案、草稿、版本和权限。医疗同意决定、医疗代理资格核验、治疗前同意门槛及病案归档属于后续 C3.2B/C 与 C3.3，不能将本批的“准备完成”或既有“认可方案”当作这些事项已完成。

## 业务规则与岗位

- 当前接诊的授权医师按具体步骤填写目的、风险、其他选择与暂缓影响、麻醉、材料、费用变化、术后与异常联系，以及沟通问题。勾选“准备完成”前，前七项须明确；不涉及的内容由医师说明。
- 保存说明仅更新工作草稿。医师沿用方案预览与明确确认后，患者才能读取该版本准备完成的说明。未完成文字不进入患者投影；旧版本缺失保持“尚未提供”，不补造历史。
- 方案步骤、摘要、准确检查来源或目录定义变化后，原准备依据失效，须医师重新保存复核。确认版本、当时说明、实际记录人和时间一并保留；新修订不覆盖旧版。
- 患者仅查看本人已发布方案。预约代办关系不授予临床阅读权；前台、主管、总部及其他患者不继承权限。前台继续排班，主管不取得临床审核权。
- 保存和确认复用既有工作范围、专业授权、锁序、版号和操作号。旧预览、撤权、并发编辑和重复提交按原规则处理；不新增治疗、收费、收退款或预约事实。

## 数据与接口

追加 `clinical/0008_plan_disclosures`：`adc_plan_version.disclosures` 为 JSONB，数据库默认空对象，旧版本保留空值语义。共 66 份迁移，原 65 份不改。没有新增表、外键、岗位、对外 API 或同意决定状态。

JSON 按已有稳定步骤 UUID 保存说明及服务端记录的作者、时间和准备范围摘要；内部对应关系不伪装为 SQL 外键。不可变版本仍受原触发器保护；已有说明时逆迁移拒绝删列。患者网站和现有小程序方案接口读取同一受限投影；小程序仅增添只读说明区。

## 需求—验收追踪

| 业务问题 | 责任岗位与可见行为 | 不变量及失败处理 | 验收 |
|---|---|---|---|
| 说明与具体治疗脱节 | 医师在对应步骤准备八项内容 | 步骤 UUID、检查来源、摘要及目录绑定；变化需复核 | 新专项的步骤、目录、来源变化测试 |
| 草稿误作已告知 | 保存与发布分开，本人仅见准确发布版 | 部分草稿不公开；缺失不补造 | 草稿隐藏、历史缺失、双端投影测试 |
| 多端编辑覆盖已核对内容 | 原页保留输入，提示核对当前版本 | 同版并发仅一方保存；旧预览拒绝 | 两个真实 PostgreSQL 连接、重放及旧预览测试 |
| 授权扩大或伪造同意 | 按现有医师／本人范围操作 | 代约不读病历；不写同意、实际处置及资金 | 撤权、越权、无资金效果测试 |
| 更正丢失旧说明 | 另建版本、历史选择查看 | 旧版不可改；数据库恢复包含 JSON | 版本保留、数据库触发器及加密独立恢复 |

专项代码见 `tests/test_treatment_disclosures.py`。执行状态分别归档于 `evidence_c32a/`；源码／真实后端／浏览器／WorkBuddy 工具／真实手机必须分开记录。手机与第二真实微信、固定 HTTPS、体验资格保持待条件，不解绑既有身份。
