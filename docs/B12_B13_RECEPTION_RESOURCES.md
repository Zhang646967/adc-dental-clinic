# 电话接待与统一诊疗资源

来电咨询 → 完整建档 → 服务与资源协商 → 患者同意 → 唯一成约 → 接诊或故障协调。

## 岗位办理

| 岗位 | 入口与工作 | 边界 |
|---|---|---|
| 前台 | `/reception/`：接待、核实、追加沟通、责任期限、候选、转候补、明确成约；预约详情进入资源协调 | 仅当前本店个案；咨询联系人不授予病历权限 |
| 本店主管 | `/scheduling/resources/`：科室、开放时间、诊室、服务、医师适配、资产排程位置与临时停用；维护原承诺映射 | 资源配置先预览确认；服务与收费项目分开 |
| 主管／总部 | `/scheduling/resources/summary/`：本店／全链数量、逾期与协调汇总 | 不含咨询联系人、患者姓名或临床文字 |
| 患者 | `/portal/`：选择诊所、服务、日期及医师；查看可行安排并确认、取消或接受候补邀约 | 仅本人绑定档案；不选择设备编号 |
| 医生、财务、技术管理 | 沿用各自授权工作台 | 新接待单不扩大病历范围，技术账号无业务绕过权限 |

## 电话接待

接待单独立于患者档案与预约。来电者、关系、待核实联系方式、服务和日期／医师偏好、当前负责人及下次期限分别保存。咨询阶段不占位、不按手机号合并患者；正式成约前核对原有完整建档要求，过敏仍可未知并由接诊复核。

办理状态：待核对、待联系、待患者确认、候补等待、已成约、未成约、已撤回。沟通与责任变更追加历史及快照；修改咨询联系人不修改患者联系方式。待联系、待确认及候补必须有责任与期限，负责人失效后明确重新分配。未成约保留无资源、拒绝方案、联系未果或其他原因。

候选查询不保留资源。确认页复述诊所、服务、医师、起止时间和患者同意；预约、资源占用与接待关联同一事务提交。重复确认返回已保存结果。候补已接受时关联同一个成功预约，不能再新建。已成约状态保留成约事实，后续取消和改期在原预约办理，并衔接取消原因跟进。

## 资源规则与启用

每店维护科室每周开放区间、诊室、椅位及固定／共享设备、服务时长、可接收医师和必要设备数量。服务总时长15—240分钟、15分钟步长，准备与周转计入总时长。牙椅沿用设备资产，不重复建账；同房多椅可并行，独占诊室只配置一椅。固定设备服务所属诊室，共享设备限同店调配；维修、退役及排程停用均影响可用性。

按店从“配置核对中”启用。核对期间暂停新增成约及邀约，原承诺保持；现有未来预约、在诊和有效邀约须逐项核实映射，未映射或有未解决影响时拒绝启用。旧历史的科室、设备与来源不补造。

电话、前台、网站、改期、候补发布与接受共用资源合同。保持出诊、患者、医师锁序，再按稳定主键锁物理资源；PostgreSQL排斥约束和事务重检共同阻止重叠。失败不会留下部分占用。邀约有独立暂占、期限、转正及释放记录；到期物理占用不持续阻挡新约，候补请求状态回收仍为明确操作。

预约／邀约保留当时服务时长与资源快照，目录修改不重写历史。资源模式按候补登记先后、可行时间和稳定资源顺序生成有界建议，发布逐项重检，不宣称全局最优。原固定30分钟匹配保留未启用资源控制的历史适用边界。网站和候补保留未来十四天；前台依已发布出诊办理。

## 故障与接诊

送修或停用立即影响新增可约性，并为受影响原预约／邀约生成协调事项。原承诺不自动取消，明确联系责任与期限。前台只能直接确认同店、同医师、同时间的兼容替换；改变医师或时间须经患者同意走改期。联系未果或拒绝改期保留原约及待办，取消另记发起方与原因。

到诊再次核对设备、排程位置和实际使用。上一位仍在诊时，即使计划结束时间已过也不能重复使用同椅或必要设备；页面提供明确协调入口。维修恢复沿用不同账号独立验收；恢复后仍需明确核对原约资源。治疗中故障由医护人工处置并留痕，不自动搬迁、顺延或改变治疗状态。

预约服务不是治疗或收费事实；资源、接待和候补记录不会产生治疗、账单或资金。
