# 电话接待与诊疗资源协同

电话咨询与正式预约分别记录。接待单管理沟通、完整建档核对、联系责任和办理结果；排班模块负责服务时长、科室开放、医师、椅位及必要设备。接诊、治疗、收费和独立财务审核继续由原模块确认。

## 业务办理

1. 前台在“电话接待与联系”登记来电者、与患者关系、待核实联系方式、服务与日期偏好。查询候选不占位。
2. 老患者按完整业务编号核对；新患者从接待单进入完整建档。手机号不合并档案，过敏未知继续保留未知。
3. 核对服务、医师、时间、诊室和设备，复述并取得患者同意。确认后同一事务保存唯一预约、资源占用与接待关联；重复提交返回原结果。
4. 无适合安排时记录候补或未成约原因。待联系、待回复及候补等待均有负责人和期限；负责人失效可明确交接。候补接受后关联原成功预约，不能另建预约。
5. 原接待“已成约”保留成功事实，取消和改期到原预约办理，并衔接取消原因跟进。

## 资源目录与启用

主管从“诊疗资源目录”开始本店核对，此后暂停新增成约和邀约，保留旧承诺。维护科室、按星期的开放区间、诊室、服务时长与接收医师、必要设备、固定／共享设备位置和停用区间。椅位复用设备台账中的牙椅；独占诊室配置一个椅位。服务时长为15—240分钟、15分钟步长，计入准备与周转，整段占用。

有效原预约与邀约须从核对清单逐项验证资源，不能补造原来源；启用条件在确认时重检。未开始资源准备的历史诊所仍保留旧规则，界面不称其已完成资源核对。课程配置由 `scripts/course_resources.py` 通过正式目录及设备命令登记，成本未知，不产生采购支出。

## 一致性与模块合同

- 接待模块拥有接待单和追加式沟通历史。排班模块拥有目录、候选、资源方案版本和占用；设备模块拥有送修、退役、维护及独立验收；运营模块提供受限汇总。
- 原出诊锁及患者／医师锁先获取，物理设备按主键排序锁定。诊所资源配置与选择以同一事务锁协调；设备送修使用同一设备行锁。
- PostgreSQL排斥约束拒绝重叠的有效物理资源占用。邀约暂占和正式占用分别保留；接受邀约原子转正；到期暂占在新确认时释放，不依赖手工回收页面。
- 网站、前台、电话、改期及候补均使用相同资源核验。当前授权、目录版本和预览资源重新核对；失败回滚全部成约变更。旧固定30分钟预览不能绕过已启用的资源规则。
- 服务目录修改不重写预约／邀约快照。替换追加新方案并释放原占用，保留原方案及依据。仅同店、同医师、同时间的兼容替换可直接办理。
- 新资源候补采用登记先后、最早可行时间及稳定资源顺序的有界建议，不保证全局最优；历史固定30分钟最大匹配仍保留其原适用范围。

## 资源故障处置

送修、退役或排程停用阻止新占用，生成原承诺协调事项。前台选择兼容替换并预览确认；需要改医师或时间则取得患者同意后走原改期流程。联系未果保留原约和待办，不自动取消。到诊再次核对设备、位置和停用，上一患者仍在使用椅位或设备时不能重复登记；可明确登记协调责任。治疗中故障由医护人工处置和留痕，不自动搬迁或改变治疗状态。恢复设备继续采用原独立验收。
