# 账号与本人申请需求追踪

问题 → 岗位 → 可观察规则 → 失败后继续 → 实际验证。

| 业务问题 | 岗位与规则 | 失败后继续 | 验证来源 |
|---|---|---|---|
| 访客需要逐步建立就诊身份 | 患者通道首次账号没有患者或员工权；服务意向不是授权 | 保留账号并申请核验 | `PatientAccountIdentityTests`、HTTP首次登录和实际网站／原生旅程；SU-83 |
| 手机可能共用或更换 | 当前账号专属凭证、显式来源；不改患者或自动合并 | 不授权仍可找店和人工核验 | 手机用途、所有者、共享及版本测试；SU-84 |
| 新患者不能由不可信输入直接成为正式档案 | 本人预览后提交，独立本店前台核验后原子建档 | 待补充、拒绝或撤回保留历史 | 新档完整性、HTTP申请及事务并发；SU-85／86 |
| 旧档不能被手机号或编号冒领 | 只有有职责前台选择本店可见原档案，记录依据 | 申请人不获得其他档案检索信息 | 旧档范围、独立审批、跨店及撤权测试；SU-85／86 |
| 暂停后需要可办理的恢复 | 只复核同一原患者、恢复同一PatientAccess行 | 安全停用先技术恢复；不能换绑或审核自己 | 原行恢复、本人审核拒绝、旧预览失效；真实后端原生处理器旅程 |
| 重复提交或网络中断 | 服务器签名预览、事务锁和唯一操作编号 | 同次重试返回原结果，字段冻结 | PostgreSQL并发、HTTP回执；真实后端模拟丢失成功响应 |
| 账号开通不能制造业务事实 | 批准后显式进入，原预约／改期／候补仍独立确认 | 撤权后阻止读取及确认 | 全量回归及跨端旅程；资金／治疗事实另从数据库核对 |
| 窄屏长账号影响办理 | 可换行、键盘可达、大字表单 | 可读错误并继续原表单 | 390px浏览器检查、修复前后截图与19页离线编译 |

源码与执行环境：`tests/test_patient_account_identity.py`、`tests/test_patient_account_http.py`、更新的`LoginShortcutTests`及`scripts/verify_native_accounts.cjs`；原始数据库、凭证、逐案身份和日志放在私有证据区。准确Git与安装记录在最终发布资料中追加，不能由本表推断完成外部平台验收。
