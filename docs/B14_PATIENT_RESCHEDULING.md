# B1.4 患者自助改期

本人预约 → 可行替代 → 明确确认 → 唯一后继 → 资源、候补与取消衔接。

患者从网站待就诊清单进入原预约，选择日期及医师，核对原新安排后填写原因并确认。无需选择设备编号。没有合适时段可查询自己的候补、查看原诊所联系信息；页面不会自动打电话、发短信或接受邀约。

## 业务规则与模块责任

| 事项 | 办理规则 | 实现与验证 |
|---|---|---|
| 本人范围 | 账号须绑定本人、激活患者身份；原约尚未开始且为已预约 | `portal/rescheduling.py`；撤权、停用、他人及非患者角色测试 |
| 普通改期 | 原诊所、同一服务、未来十四天；当前服务时长决定结束时间并提示时长变化 | `scheduling/reschedule_selectors.py`、`resource_candidates.py`；旧模式保留原时长及30分钟开始格 |
| 原约保护 | 查询不占位；原资源释放、原约已改期、唯一后继及回执同事务完成 | `scheduling/services.py:reschedule_visit_locked`；冲突与回滚测试 |
| 本人邀约 | 本人同店同服务的有效保留，可选择“用这条邀约改期”；保留原承诺时长 | `coordination/reschedule_offer.py`；重检到期、修订及当前设备 |
| 接待关联 | 候补接受后关联同一成功结果；接待、原邀约及后续改期各自保留历史 | `reception/services.py`既有合同；测试含等待接待单原子成约 |
| 重复及断网重试 | 十五分钟内原签名和操作号对应一张回执；返回保存结果的当前状态，不复活后来的取消 | 复用`BookingReceipt`；并发重复与后续状态测试 |
| 取消跟进 | 改期前身不计真正取消；后继实际取消才进入原原因跟进 | `operations/cancellation_views.py`；旧另约依据不重写，展示合法直接后继 |
| 到诊与结算 | 改期不制造治疗、账单或资金；到诊另核当前椅位使用，治疗和独立收款审核沿用原流程 | 两店真实浏览器链与数据库金额核对 |

前台继续负责日常出诊、接收控制及候补发布，患者操作不会改变排班权限。锁序沿用出诊排序、患者／医师和物理资源；有接待单的邀约先按原候补流程锁接待单。不同入口争用资源仍由事务重检及数据库排斥约束处理。

## 页面与数据设计

- `/portal/appointments/`默认待就诊，另有历史和全部；避免大量已改期记录遮住当前预约。
- `/portal/visits/<id>/reschedule/`提供候选、原新对照、原因、明确确认与失效后的继续办理入口。
- 现有候补详情明确区分替换原约与新增一条预约；本人原新记录可以互查。
- 原39份迁移逐字节保留，不增加表或字段。`Visit.replaces_visit`和`BookingReceipt`保证唯一后继与请求回执；第六幅[实际ER](database/README.md)说明与账号、邀约及取消跟进的关系。

## 负载复现接口

`scripts/portal_reschedule_load.py`只接受独立标记的本地演练实例，拒绝本机业务端口18000。私有`.rc/private/portal-reschedule-actors.json`须设为600，含`project`、20条`actors`及每店的`cases`。每位患者包含`username/password/role=PATIENT/clinic/patient_id/visit/current_day/starts`；`starts`为两个未来日期、同服务完整时段的ISO开始时间，`current_day`为0或1。`cases`提供`clinic/doctor_id`。先在合成空库通过正常预约命令准备两天不冲突的资源与本人绑定，再运行：

```sh
python scripts/portal_reschedule_load.py --root /path/to/isolated-demo \
  --project adc_rc1_0123456789ab --port 18140 --name patient-30m \
  --seconds 1800 --rps 5 --docker /path/to/docker
```

40秒用于完整预览／确认周期预检，1800秒用于正式测量；上一次成功改期后要用结果文件的`final_states`更新各患者当前预约和`current_day`，保留原结果。HTTP成功需结合独立数据库核算及资源采样，不能单凭脚本退出码宣布验收完成。账号与私有结果不上传仓库。

思维导图：患者决定 → {普通候选、本人保留邀约} → 授权与资源重检 → 唯一改期 → {原新历史、接待结果、真正取消跟进、到诊治疗与结算}。
