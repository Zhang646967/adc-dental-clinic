# R2.4 本地运行保障与验收计划

恢复闭环 → 主机可观测性 → 故障处置 → 等价容量 → 连续观察 → 安全差距复核。R2.3已完成本地工具验证；R2.4尚未执行，不能据此宣布完整R2或商业部署就绪。

## 当前基线

- 业务运行仍为R2.2 `02a9dbc`，恢复主机工具为R2.3第二批 `20961ba`；两者各自的准确CI和交付记录见[R2.3证据](evidence_r23/README.md)。
- 本轮完整回归为1,016项规则及1,152项真实PostgreSQL/HTTP/并发测试；真实age/PG恢复成功与拒绝检查24项。独立空库比对51表、29,144行，恢复、比对及启动15.868秒。
- 五诊所、二十账号、三十分钟容量仍是2026-10-15的R1历史结果；没有新的24小时连续运行证明。服务器尚未购买，公网验收另列R2.5。

## 分批实施

| 顺序 | 业务问题与行为 | 完成条件 |
|---|---|---|
| R2.4.1 主机事件与处置 | 应用失效时能区分worker停止、collector失效、容器重启、OOM和备份失效。读取明确实例的有界Docker元数据，保留枚举事件、身份和时间；不给主管或公开接口暴露主机细节。 | 停止、重启、OOM及采集失败分别可识别；历史事件不因恢复而丢失；异常时间与监测不可用保持UNKNOWN，不清空旧故障来显示健康。 |
| R2.4.2 故障演练与手册 | 在新建隔离环境注入worker、监测、数据库和网关故障，确认影响、责任人、诊断与恢复步骤。 | 每类故障留有触发、观察、恢复和独立业务核对证据；原Mac不注入故障，不自动重做通知或业务。 |
| R2.4.3 等价容量 | 重复五诊所、二十账号、三十分钟代表性读写负载，并加入有界财务导入/复核。记录采样计划、合法写入分母、权限作用域与队列积压。 | 零意外失败、重复业务效果或OOM；正常请求p95≤5秒；独立核算收退款、设备支出及匹配覆盖，且通知积压可解释。保留失败结果，不缩小负载来替代等价验证。 |
| R2.4.4 连续观察与安全复核 | 在实际可持续运行的本地实例观察24小时，检查心跳、积压、监测自身、备份时点与已恢复版本。复核已有ASVS差距清单。 | 记录真实起止、缺口、Mac睡眠/断网及事故；不把补采样算作连续监测。每项安全差距有证据、负责人/后续任务及边界；不宣称通过完整ASVS。 |

详细主机读取权限、事件合同和异常场景应在R2.4.1编码前确定。继续采用模块化单体，不新增业务角色、业务schema、公开监测地址或外部通知；若设计需要改变这些边界，另行明确业务合同。

## 保护与交付

在全新项目、数据卷和本地端口演练，所有数据合成、AI禁用。测试先于准确提交CI，Mac更新前验证加密保护备份，随后比较48项持久业务摘要、70份私有配置、原卷和RC标签。仅主机工具/报告变化不重启业务；应用或监测身份变化必须保留旧观测并按已定义程序切换。

报告首页和仓库入口保持[当前课程报告](../课程报告/README.md)的稳定姓名/学号文件名。将需求、不变量、失败响应、直接测试和执行证据连接起来；历史容量、当前工具、原Mac保护、云端运行及Windows数据恢复分别说明。

R2.5仍需服务器与固定域名，执行真实HTTPS、国内无代理访问、Mac离线运行、服务器/worker重启、证书续期和云端独立恢复。Mac离线时异地恢复点仅为最后一次已验证下载。之后按既定顺序细化R3连续诊疗、R4资源协调、R5二十诊所代表性扩展。
