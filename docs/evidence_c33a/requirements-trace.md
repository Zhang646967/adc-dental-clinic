# C3.3A需求与验收追踪

| 业务问题／用例 | 岗位、规则及失败结果 | 实现与验证 |
|---|---|---|
| AR-01/SU-134：未付清时保存病历 | 负责医师提交准确来源；不以欠费拒绝合格归档，不新增资金 | `archives.py`；`test_unpaid_valid_treatment_can_archive_without_financial_side_effects` |
| AR-02/SU-134：无治疗结果 | 如实保存无治疗及未知病史，不制造治疗或签署 | `archive_sources.py`；完整归档与新确认责任测试 |
| AR-03/SU-137：缺项处理 | 列明责任和继续入口；只保全现有资料时明确不完整 | 缺文书、草稿、疑问未答、事前材料缺口测试 |
| AR-04/SU-135：医务独立性 | 专项职责默认关闭；本店及服务读取范围有效；不能自审 | `archive_policies.py`；跨店、默认职责、七角色及撤权测试 |
| AR-05/SU-136：旧预览与并发 | 来源、职责及原包重检，冲突保留已保存事实 | 并发提交、并发审核、并发生成真实PostgreSQL测试 |
| AR-06/SU-136：生成故障 | 无部分文件或假归档；保留原任务、明确重试 | `archive_generation.py`；生成故障、重试、来源变化测试 |
| AR-07/SU-136：保护原包 | 原字节和原快照不覆盖；不从当前目录或余额重绘 | 不可改写触发器；目录更名、固定镜像文件字节对比 |
| AR-08/SU-138—139：追加补正 | 准确差异先获独立批准，再由负责医师确认；旧入口不能绕过 | `archive_corrections.py`及延迟约束；旧入口、改草稿、撤权、重放与真实浏览器补正 |
| AR-09：加密恢复 | 同版本迁移建空库，核对文件、清单、审核、补正及原业务 | 独立合成库160组记录恢复，更新前／后原系统恢复另列 |
| SU-140：归档协调 | 前台只看本店业务编号、责任及期限；主管／总部只看汇总 | `archive_selectors.py`；正文拒绝、汇总不含临床文字及浏览器隔离 |

病例、具体问答、金额、查询编号和截图保持在本机私有证据目录。公开文档只给规则、方法与汇总。C3.3B患者受控复制、真实专业制度与可靠签名不由上述软件验证代替。
