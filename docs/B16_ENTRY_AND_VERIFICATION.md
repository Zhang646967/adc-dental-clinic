# B1.6 系统入口与本人核验

明确入口 → 选择岗位 → 六条业务路线 → 核对异常与结果 → 反馈后修复。

本页记录B1.6原设计与当时的执行状态。商业C0已将`/start/`与根入口改为患者服务首页；原六条核验路线仅保留为工程交付文件，普通患者界面不再导向该清单。参见[C0当前状态](C0_SERVICE_RELEASE.md)。

## 本阶段结果

替换仍指向旧Windows隔离验收的`START_HERE.html`，提供可直接打开的本机入口；同时加入`/start/`页面与员工、患者登录和工作台的返回链接。两种入口使用同一份业务目录生成，避免交付说明与系统页面分别维护。原有根路径、登录后的岗位激活、诊所选择和所有业务授权保持原行为。

入口提供患者服务与员工工作台、已有身份返回、岗位筛选、步骤展开和个人核对记录下载。六条路线为：预约改期取消、候补邀约、电话接待成约、到诊治疗账单、收款退款复核、设备维护协调。每条都有原业务入口、应看到的结果和一个异常核对。

核对记录默认全部“尚未核验”，由本人选择。筛选不删除其他路线的观察；下载包含全部六条。刷新清空，不存储账号或业务明细，不自动读写预约、治疗、资金、权限或工作身份。个人选择不能作为自动化测试通过、正式验收或服务可用性证明。

## 开发与验证边界

本阶段只增加公开说明与导航，不新增业务表、迁移、授权或后台任务。公开入口的服务端视图不运行工作台/患者上下文处理器，不创建工作身份，不保存指南进度；业务链接仍由原目标重新鉴权。站内响应遵循现有CSP，使用本地外部样式与脚本。独立文件自带相同资源，固定连接`127.0.0.1:18000`。

本地已执行1,060项源码/规则检查，含8项新增入口边界检查；JavaScript语法检查通过。新增5项Django HTTP检查覆盖匿名无数据库、HEAD、POST拒绝、已登录上下文不变和无外部重定向，本地未运行，CI上传因自动审批无法核实目标仓库授权而被拒绝，尚未运行本阶段CI。所有39份既有迁移保持不变。

当前会话不能连接Docker，也不能绑定本地预览端口；浏览器不允许打开本地文件。因此没有把本阶段源码部署到原Mac运行实例，也没有宣称新页面完成浏览器验收。原系统的员工登录页面已在实际浏览器打开；这是原运行版本的可达性观察，不是业务全链验证。框架、数据库和端到端结果只按实际CI或目标环境执行记录更新。

## 本人核验顺序

1. 在运行ADC的Mac打开`START_HERE.html`，或进入已有员工地址`http://127.0.0.1:18000/accounts/login/`、患者地址`http://127.0.0.1:18000/portal/login/`。使用原分配账号，密码仅在本机私密凭据文件中查看。
2. 先走“预约、改期与取消”和“候补与限时邀约”，记录同一预约/候补的结果；再按岗位走接待、接诊、资金和设备路线。跨岗位先退出或选择已有授权身份，同店交接核对诊所。
3. 对每项反馈路线、操作、预期和实际结果；不要提交密码或真实患者资料。仅查看页面不等于完成业务核验。

`/start/`需要本阶段源码完成目标环境回归和更新后才可访问。原运行版本的入口目前仍可使用。网站更新不等于原生微信IDE、真机、体验版或云端已经通过。

优先依据本人反馈修复流程和提示；随后在允许访问Docker的目标环境完成本阶段HTTP/数据库回归、原资料保护、镜像更新、手机布局及键盘核对。微信平台继续等待已注册AppID及实际IDE/真机验证；教师HTTPS云端交付继续等待实际服务器、域名与配置。原真实24小时观察、安全评估与Windows历史数据恢复仍分别保留未完成状态。
