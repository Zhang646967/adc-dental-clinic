# C4.1 门诊处方与独立审方验收

确认病历 → 医师提交 → 药师退回 → 医师追加版本 → 独立通过 → 查阅历史。

| 验证项 | 实际结果 |
|---|---|
| 员工正常办理 | Chrome 使用医生、药师和前台账号登录。第一版含两项，经药师退回后移除一项，提交第二版并通过审核。旧版、原条目和退回决定可查。390 宽的审方详情无横向溢出。 |
| 权限与状态 | 11 项 PostgreSQL 定向用例通过，覆盖跨店、前台直达、独立审核、职责撤销和重发、旧工作区、过期、用药自述更新、并发决定、历史不可覆盖及有处方时拒绝回退。两条旧版接诊和任务迁移回退各自通过。 |
| 业务事实 | 一张处方、两个版本、两个决定；各版本的审核账号与开方账号分离。账单、收付款和实际治疗记录新增均为零。 |
| 迁移与关系 | 84 份应用迁移在独立 PostgreSQL 17 实际应用，新增 5 张表。172 张 SQL 表、171 张 ORM 表、501 条外键、144 项业务触发器。 |
| 已有数据升级 | 从包含既有就诊和账单的 80 份迁移合成库升级至 84 份。164 张原表、67 行数据的摘要一致，新增处方业务表为空。 |
| 加密恢复 | 同版本迁移创建独立空库后从加密备份回放数据。172 张表、1,052 行的摘要及结构元数据一致，两个版本与决定均可核对。直接用逻辑备份生成结构的初次恢复，行摘要一致，严格结构摘要有差异。 |
| 现有小程序 | 第二批正常操作单独归档，包括 390 宽、预约回查及跨账号拒绝。C4.1 使用员工工作台。 |
