# v1.0启动范围与剩余工作清单（alpha.10之后）

## 1. “启动v1.0”必须区分的三个节点

- **v1.0.0-rc.1：功能冻结、开始用户本机集中验收。** 不等于正式发布。
- **v1.0课程演示版：在Windows上实际通过核心业务、权限、并发、升级和恢复验证，可稳定演示。**
- **公网课程演示部署：目标主机、HTTPS、数据库网络边界、worker、密钥、日志、限流和恢复额外验收。** 仅使用合成资料；不宣称生产医疗服务或临床软件认证。

用户已选择本机集中验证留到1.0；中途不要求安装各alpha，开发检查继续。最后确认运行基线Windows v0.7；Mac迁移暂停。报告R4.4冻结，后续报告将在冻结版本上合并增量。

## 2. 本轮后的结论

按下面收敛范围，**到rc.1还剩两个开发/整合批次；到可用课程演示版还要完成集中实机验收；上公网再单独部署验收**。两个批次是工作分组，不是两条聊天消息或固定工期保证。当前大量真实数据库测试从未执行，不能用测试定义数量推算完成百分比，也不能承诺两次回复后无缺陷上线。

### 批次A：运营核对与交互收尾（尚未完成）

A1 固定业务数据集及独立核算表：金额逐行舍入、取消/爽约/待核实分母、成本缺失与确认零、成本但无收入牙医、账单更正后当前版本、标准价变更后的历史价、跨季度边界。以独立预期对原查询而非拷贝同一算法自证。
A2 两条可重现全链路演示：新资料/账号/出诊到建档→预约→到诊→治疗→结算→更正→季度重算；暂停新增→创建任务→前台受理/协调→站内通知→独立复核→出诊维护/恢复。
A3 当前全角色导航、空/错/未知状态、大字与键盘、术语和帮助入口统一。现有静态截图不替代真实端到端。

交付标准：预期数据文件、对应自动化/端到端脚本定义、演示路线和业务差异修复。外部AI可选、手动目录必可用；任务结果核对仅承诺已实现范围，不顺带制造通用任务恢复。

### 批次B：v1.0发布候选整合（尚未完成）

B1 统一源码/依赖/数据库16份及后续必要迁移、配置和版本清单；能够实际解析安装的依赖集合必须在实机验证，不能凭未解析requirements称为锁定。
B2 将web+数据库+通知worker合为明确可启停的开发/课程演示启动方案；待迁移完成后再启动worker，只读模式不写。
B3 v0.7带数据累计升级、停写、私密备份、失败停止、恢复/回退操作说明；不并行使用旧应用写新模式。
B4 合并SU-26至SU-38等增量、更新课程图/规约/追踪、实际证据索引与最终课程演示说明。R4.4不是此时已完成的最终版。

交付标准：`1.0.0-rc.1`完整包、用户集中验收入口、待验证项目表。阻断缺陷未关闭时保持RC，不用版本号伪装完成。

## 3. 此轮后必须保留在v1.0的功能

多身份/诊所工作台、账号治理与安全封禁、基础目录及资格记录关联、患者建档/联络更正、预约/到诊/实际治疗/版本化结算/有限数字更正、季度与运营核对、患者门户、候补与有限最大匹配及原有效邀约、页面手动引导和选定候补结果核对、出诊替代/停用、暂停新增/恢复、责任协调任务、当前店站内通知与有限重试。

这些大部分有候选代码，不代表已通过所有实机验收。专业资格认证、税务发票和收款均不在上述术语内。

## 4. 不阻塞v1.0，明确推迟

多资源椅位/设备/清洁维护联合占用和CP-SAT；跨店通勤优化；SMS/Email/移动推送；完整专业资格审核；跨院跨地业务交接；通用AI代理和自动操作；病历影像、医保税务/真实支付；Mac迁移。当前最大匹配保留本来的固定30分钟有限枚举边界。

本轮通知仅面向协调任务，不声称覆盖患者邀约、账单、全应用事件或外部渠道。需要这类覆盖时另写需求和收件权限，不在最后阶段无限拓展。
