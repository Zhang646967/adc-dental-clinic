# D2.2 追加迁移本机验收

旧库 → 加密检查点 → 追加迁移 → 失败后继续 → 独立恢复。

**本机演练通过，修正版准确提交的完整 CI 尚在运行。** 目标提交为 `4e135e91c372d3d5140156eaa4ec44d9a0d3d3e7`。本机 1,168 项源检查通过；[完整 CI](https://github.com/Zhang646967/adc-dental-clinic/actions/runs/41581164502) 独立记录，以结束结论为准。

| 实测 | 结果 |
| --- | --- |
| 迁移前备份输入无效 | 旧镜像恢复服务，保留 77 份迁移 |
| 完成 PostgreSQL 77→80 后注入候选启动故障 | 只保留数据库运行，未重启旧镜像或恢复旧库 |
| 用同一目标包和检查点继续 | 同一卷，163 张原表及 25,147 条原行保留；专项职责默认关闭，新复制表为空 |
| 再次发布和尝试旧版回退 | 拒绝并发、错误的期望提交和降级，授权建档的新记录保留 |
| 独立恢复 | 升级前的密文备份恢复到另一空库，163 表／25,147 行比对一致，65.417 秒 |

真实演练发现维护设置拒绝临时脚本，已改用明确许可的数据库 owner 管理命令，未放宽权限。保留既有 80 份迁移、小程序、PDF 与 ER，未更改现有业务实例。部署控制器用法见[操作说明](../D22_ADDITIVE_UPGRADE.md)，早期控制器不会自动支持新参数。云端 SSH、续期、容量和连续运行未验收。
