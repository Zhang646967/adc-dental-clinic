# 统一系统与服务器上线计划

同一产品 → 固定版本 → 独立服务器 → GitHub访问说明 → 持续业务完善。

## 发布方向

2026-11-02用户取消单独的“教师上线版”。后续维护同一套ADC系统，部署到正式服务器，教师通过普通患者或分配的员工身份使用相应功能。GitHub首页提供固定访问地址、患者网站、小程序和独立员工入口，以及登录和账号获取说明。

不再新增教师专用产品、功能分支或专用上线实例。开发及预发布环境继续用于隔离验证，不构成另一个产品版本。原有实例、账号、数据、RC标签和历史验收记录保留；本次方向调整不执行停机、删除数据或重置账号。

当前业务资料继续采用明确标注的合成资料。取消教师版不改变真实诊所专业、隐私、签署和运营验收要求，也不将合成记录转为真实病历。

## GitHub访问说明

首页使用同一套系统的标准入口：

- 首页：匿名找店、选医和了解服务；部署验收后填写真实HTTPS地址。
- 患者网站：`/portal/login/`，按部署时实际启用的微信或原账号方式登录；不把未开通短信写成可用功能。
- 员工网站：`/accounts/login/`，使用分配的岗位账号，按权限进入岗位和诊所。
- 微信小程序：公布实际可用的体验或正式入口，标明平台状态；不将本地开发工程称为已上线小程序。

教师无需专门角色，按要查看的业务使用对应体验账号。公开仓库说明账号获取和使用步骤；账号密码单独提供，AppSecret、服务器密钥、私有配置和真实患者资料不进入GitHub或报告。网站患者入口不混入员工登录导航。

## 职责及保留事项

主系统维护方负责后端、业务、数据库、发布、运维及版本记录。WorkBuddy继续仅负责小程序导入部署和患者侧工具／真机回归，收到可用HTTPS及平台条件后办理。教师作为系统使用者，访问同一套功能。

现有`course-20`、`course-writable`等命令名属于已实现工具的兼容参数，不表示继续维护教师版；新服务器目标采用直接HTTPS模式。原教师临时隧道相关工具和记录保留历史，不据此再创建教师专用部署。清理旧实例需明确列出目标、数据保留及迁移安排，另行执行。

C4处方与药事、C5耗材追溯继续按真实业务职责推进。上线验收和临床商用验收分别记录。课程报告仍仅更新PDF，历史Word保留不更新。

思维导图：统一ADC产品 → {患者小程序、患者网站、员工网站} → 独立服务器 → GitHub登录说明 → {业务完善、监测备份、真实机构验收}。
