# 微信服务端密钥文件化

私有输入 → 只读文件 → 后端读取 → 密文备份 → 独立恢复核对。

本批处理WorkBuddy报告的P3容器环境变量暴露面。实现／实际更新结果以[evidence_wb_p4](evidence_wb_p4/README.md)为准；代码存在不提前标为本机或云端验收通过。

## 配置与访问

后端增加`ADC_WECHAT_MINI_APP_SECRET_FILE`。配置后从指定单值UTF-8文件读取，不把内容写回`os.environ`；文件缺失、不可读、空值或明显格式错误拒绝启动，不悄悄采用旧环境值。未启用文件模式的历史配置仍可读取原变量，供有证据的迁移使用。

本机RC的规范入口：

```sh
python3 scripts/wx1_platform.py apply-rc --private-config /PRIVATE/WX1私有配置.env --project-root /PRIVATE/adc
```

这一步只更新私有文件，不调用微信、不重启、不改数据库或微信绑定。输出不含密钥；现有AppID和原AppSecret继续使用，不为迁移重新注册或轮换身份。

应用私有配置的结果：

- `RC_WECHAT_MINI_APP_SECRET`为空；`RC_WECHAT_MINI_APP_SECRET_FILE=/run/adc-wechat/mini-app-secret`只含路径。
- 主机`.rc/private`为0700；专用子目录`wechat`为0755，单值文件为0444，使容器中非root应用可以读取。其他主机用户不能穿过0700的私有父目录。
- 只有Web把这个专用目录只读挂载到`/run/adc-wechat`，不会挂载包含其他账号或备份的完整私有目录。通知、监测和迁移进程不获得该挂载。
- Canonical启动脚本清除环境中同名RC变量干扰，再使用私有配置文件。旧明文环境值退出当前应用容器，原账号、患者及业务金额保持。

这采用文件注入及文件权限控制，不宣称为Swarm加密secret存储。Docker说明文件挂载能减少环境变量带来的意外暴露；Docker管理权限仍按管理员权限管理，不能声称阻止拥有该权限的人读取应用文件或内存。[Compose secrets官方说明](https://docs.docker.com/compose/how-tos/use-secrets/)。

## 备份、更新与恢复

更新前加密保护原数据库、私有环境和既有配置；更新后备份必须包含`.rc/private/wechat/mini-app-secret`以及声明文件模式的环境文件。明文文件不进入Git、镜像、客户端、报告或回传。

恢复先在受控私有目录解密并校验内容，再按上述父目录／挂载权限重建。独立恢复过程核对数据库事实、原密码、微信绑定与密钥摘要；密钥值不打印。恢复后的未完成认证挑战按原流程失效，原成功绑定继续保留。

回退应用时必须使用该版本配套的私有配置。旧镜像不认识`_FILE`，不能只替换镜像并继续使用空的旧环境值；需要从更新前加密配置恢复其原有认证配置，再核对登录能力。本轮没有数据库迁移，应用回退不恢复旧数据库、更不重置后续业务记录。已保存的原镜像和更新前密文配置用于这条人工回退路径。

验收须实际核对当前Web／通知／监测等应用容器的环境中没有非空AppSecret值、Web只读文件可由非root用户读取、原凭据预检及登录能力正确、加密配置可恢复。替换应用容器后核对停止的旧应用容器，避免把它们仍保留的旧环境误当成已清除；清理只涉及已归档的旧应用容器，不删除数据库卷或业务历史。

当前没有购买云服务器。云端仍需在实际目标上配置独立只读挂载、权限、备份及重启验收；本机通过不替代这些目标环境结果。

思维导图：服务端私有资料 → {文件模式、Web专用只读挂载、非root读取} → {原身份不变、密文备份、独立恢复} → {容器检查、本机验证、云端另验}。
