# OPS-01：开发环境可迁移与恢复验证合同

类型：工程运维／质量与设计约束，不是新增患者业务用例；不改变R4.4中原SU编号。

## 涉众与目的

项目维护者需要换机后保留可运行成果和未提交修改；演示数据主体需要避免备份泄露；课程评审者需要分清模型、代码、运行与验证证据所指的版本。

## 前置条件

只能操作自己管理、来源可信的本地ADC开发实例。宿主机Python 3.11+用于迁移工具；Docker可访问本地Linux引擎，数据库沿用17。实际源容器和源目录必须由维护者明确指定。

## 基本路径

1. 维护者请求环境与源码盘点。工具反馈架构、引擎可用性、声明版本、修改计数及清单外文件计数；不读取业务数据库。
2. 维护者备份完整私密工作目录，确认归档包含敏感数据，选择实际ADC源容器及新的私密输出位置。
3. 工具验证源容器标签、连接标识和数据库结构；持有只读可重复读快照，生成逻辑归档和同快照比较信息。
4. 工具按原字节打包已声明源码，记录本地修改与未纳入文件；只在全部文件校验通过时生成完整清单，反馈“导出完成、尚未验证恢复”。
5. 维护者安全转移目录，在目标环境请求离线校验，再请求可信归档的隔离恢复演练。
6. 工具新建无网络、无对外端口和原数据挂载的临时PG17容器，单事务恢复并比较范围内的数据和结构，清理自身临时容器，输出绑定归档指纹的结果。
7. 维护者另行完成应用回归与正式停写交接；本工具不自动接管新环境。

## 异常与最低保证

- 源ID不明确、Docker远程、错误引擎、错误数据库、PG主版本不符：拒绝，不猜测替代目标。
- 路径越界、大小写/Unicode重名、源符号链接、声明文件缺失：拒绝并保留原工作区。
- 归档损坏、清单异常或INCOMPLETE存在：不进入恢复。
- 导出失败：没有“已完成恢复”的声明；保留失败文件供本机处理，不删除源数据。
- 恢复失败：只清理本工具新建且拥有者标签吻合的容器，不删除源或其他项目资源；清理失败单独报告。
- 模拟测试、文件摘要、一次读数或一次网页打开都不能单独证明迁移成功。
- 正式交接必须停写、重新导出；不能用演练期间较早的快照覆盖已有新数据。

## 责任分配

- 薄入口脚本：Shell/CMD差异和宿主机依赖提示。
- migration_core：文件合同、路径边界、清单和差异判定。
- migration_tool：本地Docker适配、事务快照、二进制流、生命周期和证据。
- PostgreSQL：逻辑归档及恢复、约束和事务机制。
- 维护者：源选择、来源可信度、密钥保管、全体写入者冻结、应用验收及最终放行。

## 本轮没有证明的性质

真实Windows/Mac执行、ARM依赖可用性、生产权限迁移、数据库运行性能、全部数据库对象一致、序列计数器的同快照性质、业务端到端与实际回退。只比较本合同枚举范围，不将其称为完整安全认证。
