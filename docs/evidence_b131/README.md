容量核验分别证明900个唯一患者及正确诊所、900次草稿修订和最终内容、原500份账单与收款金额，以及两笔浏览器新增金额；没有声称负载开始前全部旧行的完整指纹比较。原本机行与配置另按交付前后摘要核验。[需求至测试](traceability.md)。

三十分钟实测代码与交付的命令、查询、权限、模型、迁移和静态路径一致；之后修正了四处岗位或“尚未保存”提示，最终提示另以准确版本浏览器核验。[逐文件比较与范围](capacity_equivalence.json)。不把该比对称作第二次完整二进制负载测试。

两个临床场景的前17项实际办理均已成功；首次资金续办脚本使用错误前缀导致404，修正为跟随页面实际链接后续办，未重复诊疗或制造账单。浏览器脚本另修正日期控件分段Tab、导航等待时点以及同名action字段读取；原私有失败记录保留。上述脚本错误不归为产品修复，也不计入负载的零失败结果。

发现并修复的应用问题包括：权限及菜单责任不一致、维修协调页依赖旧维护权限、非整点结束后的候选向前取整，以及缺少调班期限和跨表归属、来源区间约束。

独立恢复采用同版本迁移建库后装入数据路径，并比较实际触发器；既有自动恢复工具对等价SQL结构表达的比较限制保留。测试只针对Mac上受限容器和合成数据，不证明独立公网、24小时连续服务或二十店商业容量；Windows原数据恢复仍未解决。

## 准确版本与本机交付

最终应用`2c45d6d`的[66项真实浏览器核对](exact_browser.json)验证四处最终提示、五店前台入口及主管限制；[再次加密独立恢复](exact_recovery.json)核对69表、32384行和42项触发器，空库就绪后4.074秒。新增会话和工作范围解释其相对首份备份的行数变化，两份快照分别保留。

原本机[九账号七角色读取](mac_browser.json)通过233项；[实际结构核对](mac_schema.json)逐项对应ER结构快照。更新前后加密备份均核验，66组原记录逐行摘要、70份私有配置、原数据库容器／卷和RC标签保留；没有向原库注入业务测试。应用、worker、监测器和网关计划重启，旧观察与主机日志加密留存，新身份六项观察及主机采集健康；更新前旧监测器已退出，其未知观察区间保持为UNKNOWN_OBSERVER_UNAVAILABLE，不被新采样改写；不据此声称连续24小时通过。

首次GitHub验证在运行测试前发现应用清单误纳入镜像排除的历史运行文件（[失败记录](https://github.com/Zhang646967/adc-dental-clinic/actions/runs/39464373415)）；仅修正清单范围后重新完成准确提交全套CI，完整归档校验仍保留历史文件。
