# WorkBuddy 病历副本部署与患者侧工具回归

冻结工程导入 → 副本范围与版本 → 补充与申请 → 受控领取 → 隔离与回传。

## 版本和职责

只使用交接包`VERSION.json`明确列出的客户端、后端、镜像、准确CI及工程摘要；唯一业务测试环境为`http://127.0.0.1:18382`。本轮新增一个原生页面，共27页。使用原AppID、local模式和`urlCheck=false`；不上传平台、不设体验版、不新增公网暴露，保留所有旧工程。

WorkBuddy仅导入新工程、必要编译和患者侧操作。前台、医务审核、后端、数据库、服务器和课程报告由Codex负责。账号及个案预期在包外本机私有指南，按用户授权和正常敏感读取审批使用；不从其他文件重建凭据，不重置账号，密码不进入回传或截图。

## 按顺序操作

1. 校验包内`CHECKSUMS.sha256`并核对运行态版本。导入编译一次，记录工具、基础库、包体及27页；不重复既有医疗决定或费用业务。
2. 本人账号从“我的／就诊 → 病历副本申请与领取”进入。按私有清单查看已就绪申请，核对患者、门店、用途、领取人、资料类别、固定版本与期限。当前及历史来源分别核对，不把旧文书改为当前文书。
3. 打开待补充申请，阅读退回说明，填写本次补充办理说明，预览并明确提交。确认仍待材料核验，不能直接领取；再按正常患者入口撤回。记录新增事件和查询编号，不替前台或医师通过。
4. 本人新建一份申请，选择清单中的就诊与资料类别，预览核对后明确提交。重复确认或网络中断先重读清单；不得造成第二份相同处理中申请。按清单撤回本轮新申请，保留历史，不更改已冻结的就绪副本。
5. 对就绪申请预览领取并明确确认。核对文件实际传输、PDF打开、固定版本及所选内容；未申请的类别、核验材料编号及员工审核资料不出现。服务端文件响应不等于已阅读。工具若不支持`wx.openDocument`，分别报告传输结果和查看器未验收，不用网页截图代替原生PDF查看。
6. 换专项受托账号，只查看私有清单已核验的特定副本及领取。它不能据此查看完整病历、账单或办理患者预约。已撤销或已到期事项应显示不可领取；原文件与历史保留。不要另行撤销代理、改变核验依据或重交医疗决定。
7. 换负例账号访问前一账号的申请和领取入口，拒绝且不显示旧内容；退出后有链接也不能读取。客户端刷新失败时应清空旧详情并允许重新读取。仅按私有指南使用异常链接，不猜测其他患者编号。
8. 390宽检查范围清单、长用途、按钮、历史和返回。375／430、字体放大或原生选择手势无可靠工具能力时保留未验收，不再调用已知不支持的Emulation或修改样式伪造结论。

## 不重复与边界

本轮无需微信退出重登、解绑既有身份、重复旧医疗／收退款场景。新增下载使用既有会话；认证异常回传Codex，不擅自调整认证或密钥。手机、第二真实身份、固定HTTPS、平台主体、类目、备案和体验资格继续单独验收；local工程不证明实际手机或公众发布。

只在18382进行上述明确患者操作；不向18000及任何旧端口写入，不收款、退款、造治疗或改资料。不读取AppSecret或服务器密钥。因前台或医师处置阻塞时回传准确申请编号，由Codex办理；不补造结果。

回传每项PASS／未验收、版本、编译、查询编号、截图路径、实际新增申请及事件编号；区分文件传输与PDF查看器。密码、微信code、OpenID、Cookie、Token、领取凭据及密钥不回传。个案对账保留私有记录，公开仓库只保留汇总。

思维导图：冻结版本 → 本人／专项领取人 → {范围、版本、补充、明确申请} → {原会话领取、文件、历史} → {换账号、撤销、到期、只读边界} → 工具回传与设备另验。
