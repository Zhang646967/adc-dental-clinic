# 检查报告提醒与复诊接续

独立审核 → 医师发布 → 本人查阅 → 复诊预约 → 到诊核对 → 实际完成。

## 发布与接收

原就诊负责医师发布审核通过的准确版本时，选择仅查阅、按指示安排复诊或需门店联系。采用已有指示时核对原就诊、服务、日期和完成目标。调整安排追加决定，保留原发布版。门店联系由责任医师登记实际结果及下次期限，前台按本店办理范围查看进度。

发布、更正和撤回分别保存站内提醒。网页「报告与复诊」和小程序「就诊 → 报告与复诊」共享最新提醒、未读数和明确标记的已读时间。报告详情逐次校验本人和准确版本。历史已发布报告仍可从原就诊查阅当前可用版本。预约代办及医疗代理依原权限办理。

## 预约与接诊

复诊查号取医师建议日期与患者自助范围的交集。预览绑定本人、报告版本、复诊决定、指示版本及号源。确认成功将正式预约、回执和指示关联同事务提交。已有预约可从报告打开，改期后指向后继预约。窗口失效或报告撤回时原预约保留，患者可联系原门店核对。

负责医师在复诊的检查工作台核对原报告、指示和临床目标。治疗前核对保存准确报告发布事件，实际执行再次核对依据。报告换版或撤回后，旧核对须重新办理。实际检查或已完成步骤仍由既有就诊和治疗命令记录，归档、已发布账单和资金保持各自的事实来源。

## 接口与验证

| 入口 | 合同 |
|---|---|
| `GET /api/mini/v1/overview/` | `report_unread_count` 是非负整数时显示本人入口 |
| `GET /api/mini/v1/report-notices/` | 每张检查单的最新提醒，每页 20 条，撤回的 `revision` 为空 |
| `POST /api/mini/v1/report-notices/<id>/read/` | 明确点击后登记。重复请求返回原已读时间 |
| `GET /api/mini/v1/visits/<visit>/examinations/<order>/` | 精确版本读取，追加复诊动作。可约日期取 `first_day` 至 `last_day`，医师建议保留 `earliest_on` 和 `latest_on` |
| `GET candidates/` 和 `POST booking/preview/` | 复诊带 `followup_visit`、`followup_examination` 和 `followup_revision` |
| `POST booking/confirm/` | 用原签名预览确认，回执包含 `id` 和 `visit_no` |

合成库 PostgreSQL 回归覆盖读态共享、换版拒绝、重复提交、并发关联、改期回查与治疗执行重检。小程序工具验证和实际手机接收分别记录。站外微信订阅仍需单独联调。
