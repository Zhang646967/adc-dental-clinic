# B1.1 独立恢复方法与边界

已验证路径：持有共享只读快照取得数据库事实及加密转储 → 启动无宿主端口的独立空PostgreSQL 17 → 使用准确应用镜像的31份迁移建表 → 仅在新空环境清除自动生成的权限元数据 → 解密导入完整数据及序列 → 逐表比较54张表的行数、内容及结构指纹 → 删除本次临时容器。

54张表均纳入比较，包括账号、授予、临床、资金及新增取消办理历史。资金凭据有500条；本轮流水批次、流水行与匹配表为空，其非空原始字节及匹配历史的恢复仍引用既有R1证据，不宣称本次再次验证了非空流水。新环境准备好后2.924秒完成；该速度仅对应本次合成数据库，不能推断更大数据库的恢复速度。未覆盖或导入本机原库。

演练首先采用直接重建转储内DDL，行数据全部一致，但旧版结构摘要对PostgreSQL重解析等价的varchar数组到text数组类型转换敏感，报告结构不一致。因此本次改用准确版本原始迁移建表后导入数据，最终原结构和行摘要均相等，没有关闭核对或把结构差异当作通过。现有自动恢复工具继续严格检查；面对该类等价表达式差异会拒绝启动，不能把本次人工受控路径描述为自动工具已修复或所有历史归档均可直接通过。

私钥、加密备份、账号和详细日志仅保留在本机私有目录，仓库仅发布去敏摘要。后续运维应单独设计版本化的结构等价比较并保持旧备份兼容；不以宽松字符串替换消除差异。
