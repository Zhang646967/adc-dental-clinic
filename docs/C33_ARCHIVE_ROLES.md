# 归档岗位核对与教师演示路线

完成文书 → 明确提交 → 另一医师审核 → 文件就绪 → 准确补正 → 原包对照。

## 岗位合同

现有七类角色保持；负责医师和指定审核医师是同一医师角色下的不同责任，不增加患者或主管的医疗权限。

| 当前岗位／身份 | 本批可以办理 | 不能从本批取得 |
|---|---|---|
| 本次负责医师 | 本人负责就诊的准确归档、缺项保全、补正申请和获准后的临床追加 | 独立批准自己的记录或覆盖旧文件 |
| 指定独立医务审核医师 | 有专项委任及对应服务读取范围时，核对准确清单和补正差异 | 替负责医师直接确认临床版本；批准本人就诊 |
| 前台 | 本店业务编号、责任、期限及进度，联系协调 | 临床正文、固定包及医务批准 |
| 主管 | 本店归档数量与待办汇总 | 医疗正文或审批权 |
| 财务 | 沿用原收费、收退款和独立复核 | 因财务角色查看归档包或批准临床内容 |
| 总部 | 全链归档汇总 | 跨店临床包或临床写入 |
| 技术管理员 | 按机构委任登记默认关闭的专项职责，维护原账号 | 临床读取、独立医务批准或以技术身份自审 |
| 患者／预约代理／医疗代理 | 沿用原本人或指定事项业务 | 整份病历复制、归档包或额外账单权限 |

专项归档职责不代替机构专业委任，也不代替服务读取范围。无有效审核人时先完成机构职责及范围核对，不用主管身份代替。具体材料与专业资格仍按真实机构责任另验。

## 教师演示顺序

1. 从本机私有试用说明取得独立课程环境和专用账号；公开仓库不列密码或病例编号。原系统只追加结构，不批量补造历史归档。
2. 负责医师从“病历归档与独立审核待办”打开已结束接诊。查看完整性、确认文书及准确收费版本；付款结清状态独立，不要求为归档先收款。
3. 预览清单并明确提交。换另一名指定审核医师登录，核对冻结材料、职责和准确版本，再独立通过、退回或不通过。
4. 返回负责医师进度页。已通过先显示待生成；文件就绪后才提供固定PDF与清单。观察工作进程自动生成，不代医师批准。
5. 打开已准备的追加补正示例，比较原文和拟追加内容、审核意见与临床确认。第二包引用前一包，第一包文件保持；不得重收款或重新提交治疗来演示归档。
6. 前台查看协调状态，主管及总部查看汇总；患者、代理及非临床岗位不能使用医师的固定包链接。权限结果以本次执行证据为准。

只有资料保全时要明确读出“未完成归档”。医务复核不能把实际已经发生的事前缺口变成“事前通过”；新一次接诊不要求解锁旧病案。患者受控复制由C3.3B另行受理，本批没有可转交WorkBuddy的新患者页面。

思维导图：七类角色 → {负责医师、独立审核、前台协调、管理汇总} → 准确版本 → 固定包 → {原包保留、获准补正、范围隔离}。
