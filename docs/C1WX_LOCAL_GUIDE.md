# 本地账号流程试用

私有凭证 → 患者账号 → 本人申请 → 前台核验 → 明确进入 → 原预约／改期／候补。

**当前是未安装候选。** 通过准确CI、跨端与恢复、正式ER／报告及保护更新后启用，已运行版本仍见[C0.4交付](evidence_c04/README.md)。无需提供AppID或医保接口；本批不调用真实微信、短信、居民身份或医保系统。

## 签发本地替身凭证

在已更新并启用合成模式的本机项目目录中执行：

```sh
python3 scripts/patient_identity_demo.py login --subject course-patient-1
```

命令只打印私有JSON文件位置及有效期，不打印授权码。打开该文件，将其中code输入网站患者登录页的“本地授权体验”，或小程序登录页的同名入口。凭证五分钟有效且只能使用一次；重新签发同一subject仍进入同一绑定账号。首次体验留空账号密码；绑定旧患者账号时填写原账号和密码。

首次登录仅建立患者渠道账号。抄下“我的账号”中显示的ADC账号名；按“新患者建档／已有档案关联”提交本人资料。前台进入本店“本人档案开通核验”，核对本人及账号、内部依据后预览批准。未获本店核验职责的人员不能审批，旧档按明确患者编号选择，不按电话号码匹配。

患者刷新办理状态，明确点击“进入患者服务”才激活原患者上下文。选择本人或原有代约授权后，继续原预约、改期及候补；申请和手机绑定本身不创造预约、治疗或资金。

## 联络、密码与恢复

账号手机替身凭证使用准确的ADC账号名：

```sh
python3 scripts/patient_identity_demo.py phone --account patient_ACCOUNT_NAME --phone 00000000000
```

在“账号联络号码”输入私有文件中的code。页面显示“本地模拟核验”，不会验证真实号码或合并家人。患者档案原联络资料仍由原前台流程维护。

再次为同一subject签发登录凭证，可在“密码与账号恢复”核对当前身份后设置可用密码。密码不写入文件或日志。解绑需要核对密码，保留ADC账号、申请、患者关系和业务历史；之后可用账号密码登录，或以原账号密码重新绑定新授权凭证。原本人关联暂停后，账号可以登录查看恢复事项，选择“复核原本人关联”，由另一名本店核验前台确认原档案后恢复同一关联；不会另建或改绑患者。账号安全停用仍须先由技术人员恢复凭据，前台不能绕过。

小程序源码新增账号与建档两页。官方离线编译及实际Page处理器验证分别取证，均不等于微信开发者工具运行、真机或体验版上传。真实微信适配需要已注册应用和实际接口资格后另做验收。

思维导图：本地凭证来源 → 账号与联络 → {新档申请、旧档核验、原绑定恢复} → 明确激活 → 原患者权限与统一资源。
