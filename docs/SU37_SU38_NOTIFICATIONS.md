# SU-37/SU-38：站内任务通知规约

基线R4.4及SU-34/35/36；候选v0.9-alpha.10。本文件是项目新增需求，不宣称课件指定了角色、次数或期限。

## SU-37 查阅本人任务消息并标记已读

主执行者：当前本店前台或主管。无外部消息服务、AI或患者作为辅执行者。

涉众利益：前台希望知道新协调任务与退回；主管希望知道受理、声明和提交复核；患者希望通知不泄露个人/临床数据，不暗含其同意；原业务各方希望浏览通知不修改服务承诺。

触发：执行者查询站内收件箱，或对一条消息明确请求标记已读。

前置条件：有有效会话且激活相应身份和诊所。权限、消息归属、授权是否撤回由系统检查，不预设合法。

基本路径：
1. 执行者提交消息范围及页码，请求查阅本人当前工作范围的消息。
2. 系统核验账号、当前身份、诊所及原始收件授权与当前授权，反馈有界分页消息。
3. 系统区分事件发生时状态、派发时点、当前查询任务状态及已读标记，反馈原任务查询入口。
4. 执行者需要时另行请求对指定本人消息标记已读。
5. 系统重新核验当前权限、工作上下文和归属，保存首次已读时间，并反馈该标记不构成受理/同意/完成。

扩展：2a没有符合条件消息：反馈空结果，但不认定没有任务；2b查询失败：反馈未知并保留原任务入口；2c其他患者或岗位未纳入本版消息：不扩大角色；3a任务有后续变化：以当前任务页为准；4a用户只浏览：不写已读；5a旧上下文/撤权/其他账号消息/其他店：拒绝；5b重复标记：保留第一次时间；5c只读实例：不保存标记；5d保存失败：不伪称成功，不重做原任务。

成功后置：只读查询不改消息及业务；明确标记仅改变本人该条消息read_at。最低保证：任务、出诊、Visit、WaitOffer、治疗、Invoice保持原值，无自动受理或患者同意。

字段：mode(unread/all)、page、message_id、工作上下文令牌；查询返回task_id、slot_id、动作标题、历史状态/修订、当前状态/修订、发生/派发/首次标记时点。无姓名、电话、病例、自由文本或外部URL。

## SU-38 核对本店通知派发并请求重试

主执行者：当前本店主管；后台worker是内部实现机制，不是主管身份的替代者。

涉众利益：主管希望发现等待或失败，不因通知失败误判任务失败；维护人员需要受控重试和不泄露敏感数据的错误信息；其他使用者不希望重试重复生成消息或业务动作。

触发：主管查询当前店通知处理情况，必要时重排失败事件。

前置条件：有效主管工作上下文，具体事件权限、状态和轮次由系统检查。

基本路径：
1. 主管请求本店派发情况。
2. 系统反馈待派发、已生成、无符合条件收件人、失败状态及发生/处理时间；不暴露其他人的个人消息或明细收件名单。
3. 主管对一条失败事件核对原因，明确请求只重试通知。
4. 系统重新核验当前诊所、权限、只读策略和重试轮次，将原事件重排并保存审计。
5. 后台另行按原收件范围及当前授权有界重试，主管以后查询实际结果。

扩展：2a暂时读取失败：结果未知，不自动重发；3a空收件或失效授权：不通过重试创造新权限/新收件人；4a已处理/已经重排/旧轮次：拒绝第二次重置；4b其他店、前台身份、旧页面、未确认或只读：拒绝；4c审计失败：回滚重排；5a后台未运行：仍PENDING，不虚构成功；5b失败：退避到最多5次后FAILED；5c部分原授权失效：跳过并记录聚合数量，不向新授权补发。

成功后置：仅通知处理记录与审计变化。最低保证：重试不重新创建任务、取消/改期预约、接受邀约或释放资源；此前成功的消息行不重复。

字段：event_id、expected_round、明确确认及工作上下文令牌。事件和收件快照不可在本入口修改。

## 共享业务/质量规则

N01 任务+审计+Outbox同事务；提交前不得派发，事件保存失败则任务操作也失败。
N02 只有已提交事件可由worker处理；同一事件全部收件行和完成状态同事务。
N03 事件×原授权唯一；原目标、历史事件、消息所属账号/角色/诊所不可改写。
N04 原始收件资格和当前授权双核验；新绑定不补发，已投递同绑定恢复可重见历史。
N05 已读是显式声明，不是人已读懂、已受理、患者同意或完成。
N06 有界重试、等待时间和停止状态可观察；不保证外部必达/严格FIFO。
N07 历史事件排序与当前任务状态分开；消息不驱动任务状态迁移。
N08 只读模式、当前上下文、CSRF和目标授权分别有效；没有消息目录权限即可更改患者信息的关系。
N09 新消息从启用本版后的任务变化开始，不为旧审计盲目回放；超过500收件目标拒绝整次任务保存，不截断。

## 分析责任与追踪

边界：当前身份消息/派发查询、明确已读与重试输入。控制：权限与查询、有限重试组织。实体：CoordinationTask与AuditEvent是源事实；NotificationOutbox是派发意图与处理状态；InboxMessage是原始收件所有权和个人标记。任一消息状态不能替代任务、预约状态。

测试组AT-N01任务事务与回滚；AT-N02原始/当前权限；AT-N03后台重试/去重/独立连接；AT-N04显式已读；AT-N05重试权限/审计；AT-N06模型/迁移约束；AT-N07真实模板/静态手机大字界面与恢复路径。它们是验收目标，不是已执行事件。

实现路径与真实检查状态见RELEASE_v0.9a10.md、TEST_REPORT.md。本增量不重画/重排冻结的R4.4报告；最终报告再合入。
