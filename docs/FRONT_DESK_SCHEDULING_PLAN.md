# B1.3.1 前台排班与数据库关系优化

前台排班 → 日周安排与原承诺 → 调班责任及期限 → 独立复核 → 出诊维护 → 数据关系核对。

日常排班由前台负责。B1.3.1将菜单、页面、命令、表单签名及操作指引一并调整到当前店前台；主管继续管理资源目录和独立复核。正常出诊无需主管逐条代办。[执行证据](evidence_b131/README.md)与历史B1.2＋B1.3分开保存。

## 可办理的业务

| 工作 | 负责人 | 可见结果与边界 |
|---|---|---|
| 登记出诊 | 本店前台 | 先预览医师和完整时间，明确确认；重复确认同一结果，同医师跨店不能重叠。 |
| 调整、停用、暂停或恢复新增 | 本店前台 | 保护原约和有效邀约；空闲调整创建替代记录，不改写原时间。 |
| 日／周排班 | 本店前台 | 周一开始，按日期和医师筛选，28条出诊分页。区分正式预约、有效暂占、到期未回收、实际在诊与计划空档。 |
| 核对服务机会 | 本店前台 | 按完整服务时长、科室开放及医师适配核对椅位和必要设备；每条出诊按各空档展示首个可行组合，最多三项；查询不占位。 |
| 候补生成和发布 | 本店前台 | 逐项重检、限时邀约及明确接受；旧版未发布草案需重新生成，已发布结果和原承诺保留。 |
| 调班联系 | 本店前台 | 先明确暂停新增，发起、受理、进度均核对未来跟进期限。未联系上或拒绝时保留原约，改变医师或时间走原改期流程。 |
| 协调复核 | 不同账号主管 | 重读当前事实，有阻断不通过；复核本身不更改出诊，由前台另行维护。主管仍可提出协调交接、退回及撤销任务。 |
| 设备维修影响 | 主管核对供给，前台办理安排 | 主管只读查看占用影响并交接；前台核对兼容替换与到诊。治疗和资金由原岗位确认。 |

待跟进任务按责任期限显示逾期。历史期限未填写仍明确显示，不回填虚构时间。到期不自动取消预约或顺延排班。联系人、患者姓名和病历不进入日周排班的投影；患者业务编号只供前台定位原授权详情。

## 数据关系与迁移

保留原37份业务迁移，追加两份，共39份。数据库仍为69表、170条外键；新增协调期限、两项查询索引和四项跨表触发器，当前模型与真实列逐项核对。[六幅ER、完整字段和关系](database/README.md)说明主键、外键、可空与条件唯一。

| 问题 | 解决 | 反例 |
|---|---|---|
| 资产绑定或停用目标可能跨店 | 绑定和停用目标归店约束 | 同店主体引用外店诊室、科室或资产时拒绝。 |
| 同店资源方案混用科室 | 服务与诊室同科室 | 相同clinic仍不能跨科室拼接方案。 |
| 邀约转正与预约来源不一致 | 双来源六项事实相等 | 患者、店、医师、出诊及起止时间任一不符即拒绝。 |
| 资源只占部分原承诺时间 | 对照原预约／邀约完整区间 | 不用可修改的服务目录推算历史；15分钟假占用不能支撑30分钟承诺。 |
| 新视图随出诊行逐项查库 | 预载日历与适配、需求；增加范围索引 | 查询数不随2至26条出诊逐行增长，接受邀约不重复计数。 |

迁移先检查现有关系，发现不符需核实；不补造科室或历史。框架自动连接表主键的兼容性差异在独立空库复现并记录，保留实际bigint，不缩窄字段。资金与病历模型不变。

| 编号 | 可观察行为 | 主要验证 |
|---|---|---|
| SCHED-01 | 前台可维护出诊及发布候补，主管不继承日常排班权限 | 七角色、当前身份、撤权、跨店、旧签名、重复和并发确认。 |

| SCHED-04 | 日周视图区分不同占用及实际使用 | 日期与医师过滤、过期邀约、服务45分钟、停诊和维修；390px大字号与键盘。 |
| DATA-01 | 图、目录与真实结构对应 | 618列、169条ORM关系加1条复合外键；42项实际触发器。 |
| DATA-02 | 原记录、历史、临床与资金不被排班制造或重写 | PostgreSQL反例、完整回归、独立资金核算、加密独立恢复和本机前后摘要。 |

详细测试定位见[追踪表](evidence_b131/traceability.md)。容量按本阶段实际源码与结果归档；历史容量不代替新结果。课程数据及本机演练不证明公网、二十店商业容量或临床资质。
