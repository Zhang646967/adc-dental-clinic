# SU-34—SU-36：有责任的出诊协调任务

候选实现：v0.9.0-alpha.9。父版alpha.8；需求基线R4.4 + SU-26—33。本材料为开发增量，不重写已提交的中期报告。以下均为规范性需求与项目设计决定；验证状态单独记录。

## SU-34 发起与管理出诊协调任务

**主执行者：** 当前诊所主管。没有短信、外部AI等辅执行者。

**涉众利益：** 主管希望协调计划有明确记录且不重复派出；前台希望目标、来源出诊和责任边界清楚；患者与牙医希望任务不偷偷改变服务承诺；维护人员希望保留撤销、交接和复核历史。

**触发：** 主管对既有出诊提出时间调整或停用的协调需求。

**前置条件：** 主管会话及当前诊所已选择；授权、源状态、暂停标志和重复任务由系统核验，而非全部假定成立。

**基本路径：**
1. 主管指定原出诊，提交协调目标及固定类别依据，请求预览。
2. 系统核验当前角色/诊所、源出诊尚未开始且有效、已明确暂停新增、关联资料完整且没有另一未结束任务，反馈拟创建任务。已有预约或有效邀约不阻止发起，但必须保留。
3. 主管明确确认。
4. 系统在锁定源出诊后重新核验状态、授权、确认期限和当前事实，同事务创建待受理任务与审计。
5. 系统反馈任务编号；任务不会自动受理或触发任何患者业务。

**扩展：**
- 2a 原出诊未暂停：提示先通过SU-32办理，不隐式暂停。
- 2b 源已开始/停用、存在关联异常、超过完整上限：不创建普通任务，交由受控流程处理。
- 2c 已有未结束任务：提示查询原任务，不以新编号绕过。
- 3a 放弃预览：不创建。
- 4a 旧上下文、摘要变化、过期/篡改、撤权、只读模式：不写入。
- 4b 并发重复发起：源行锁与部分唯一约束保护一条活动任务；失败不覆盖原任务。
- 4c 相同成功确认重放：重新核验当前权限后返回原任务当前状态，不重开或重复创建。
- 4d 保存/审计异常：本次同事务回滚；回执未知先按原出诊查任务。
- 管理分支：主管可对处理中/待复核任务说明退回依据，将其重置为待受理并清除当前受理/提交标记；旧办理事件保留。不能代另一个账号受理。
- 撤销分支：主管可撤销未结束任务，保留历史，不暂停/恢复出诊、不取消患者业务。源已失效时仍可核对并撤销任务，但不能借此宣称正常维护完成。

**成功后置条件：** 一条待受理任务存在；或一次明确的退回/撤销及相应事件已保存。既有源出诊、预约、邀约、临床与财务事实不改变。

**最低保证：** 失败不留半次任务变更；原记录、原承诺和暂停标志保持；旧成功请求不撤销后续合法状态。

**字段：** source slot ID；目的DEACTIVATE/REPLACE；固定依据；签名状态/确认；当前上下文；操作编号；明确确认。没有任意受理人ID、患者资料或自由文本。

## SU-35 受理并记录出诊协调办理

**主执行者：** 当前诊所前台。

**涉众利益：** 前台希望明确谁负责当前跟进，能够必要交接；患者希望自身意思仍通过原业务流程确认；主管希望区分联络声明和已保存业务事实。

**触发：** 前台选择待受理任务，或继续本人已受理任务。

**基本路径：**
1. 前台查询本店任务，选择准确原出诊。
2. 系统核对任务尚未受理，反馈由当前账号受理的影响。
3. 前台明确确认；系统再次核对任务修订并保存本人受理责任及审计。
4. 前台通过SU-31定位关联记录，另在原预约/邀约用例办理；任务服务不代办这些动作。
5. 前台指定本出诊的一条预约/邀约，选择尝试联络、等待患者决定、转原流程办理等有限声明，请求预览并明确确认。需要主管协助可以不指定个人对象。
6. 系统核对当前受理人、对象属于该出诊、快照及期限，保存声明事件并推进任务修订，不改变预约状态。
7. 前台认为可提交时发起复核请求；系统重新核对完整有界关联无阻断、源仍未来有效且暂停，再经明确确认将任务转为待主管复核并记录当时的业务事实摘要。

**扩展：**
- 别的前台已受理：不能覆盖；只允许当前受理人记录、退回或提交。
- 无法继续：受理人可明确退回待受理队列；账号停用/撤权后不得自行继续，主管仍可按SU-34退回任务，其他合法前台自行受理。
- 声明对象无关/不存在，或关联异常/超限：不附加声明；错误反馈不透露另一患者存在与否。
- 声明类别不是患者同意或办理成功证明：系统不据此清除实际阻断。
- 有受保护预约/接诊或有效邀约：不能提交复核。旧邀约到期后未回收不再占位，但仍保留历史；接受后的预约按真实预约事实核对。
- 原出诊恢复接收/开始/停用：不能提交普通维护复核，主管需再核对或转其他流程。
- 旧页、ABA、并发受理、重复确认、只读、审计异常：遵循签名/修订/锁/事务规则，不产生第二受理人或半次状态。

**成功后置条件：** 当前受理人明确；或有一条附明确对象的操作者声明；或任务转为待复核且提交人/时点/摘要一致。上述不等于患者已同意，也不证明某次原业务已经成功。

**最低保证：** 失败不改变责任；不自动处置预约/邀约、不通知患者，不开放其他角色权限。

**字段：** 任务/出诊ID；操作依据枚举；声明对象类别与记录ID（不得填姓名电话）；状态/确认令牌；操作编号；当前上下文与明确确认。

## SU-36 复核出诊协调结果

**主执行者：** 当前诊所主管，必须与本次提交复核的前台为不同账号。

**涉众利益：** 主管希望根据真实结果而非勾选进度判断；前台希望结果可追踪；患者希望已有承诺和临床记录不为结案被错误删除；系统维护人员希望失败可以恢复且不自批。

**基本路径：**
1. 主管查询待复核任务，核对原出诊、目标、受理人和提交时点。
2. 系统核对独立账号、当前源状态和完整有界关联；确认原出诊仍未来有效且暂停，没有保护业务/有效邀约/异常/截断，且相关事实摘要仍与前台提交时一致。
3. 系统反馈本次可通过的依据，明确不自动维护出诊。
4. 主管明确确认。
5. 系统重新锁定、核验状态/权限/快照/时间条件，同事务将任务标为协调核对通过并保存独立复核人、时点和审计。
6. 系统提供回到原主管出诊的入口；SU-29/30维护或SU-33恢复由主管另行独立办理并重验。

**扩展：**
- 未由前台提交或同账号切身份自批：拒绝。
- 提交后关联记录、接收修订或源维护历史变化：拒绝通过，主管退回重新核对；即使又变回同样状态也不能复活旧结果。
- 查到受保护接诊或源已开始：不得为结案虚假取消、爽约或删除，转专门受控流程。
- 条件不满足：主管按SU-34退回或撤销；不能跳过检查强制通过。
- 保存/审计失败：任务仍为原状态；重复成功确认不反复结案或取消后续合法维护。

**成功后置条件：** 协调任务结束，保留复核责任与历史，不新增预约、不改邀约、不改出诊接收标志。

**最低保证：** 未满足真实条件不得写成功标记；任务结束不是对以后状态的永久保证，也不是停诊指令或临床许可。

## 规则及状态

|编号|规范|
|---|---|
|BR-T01|当前角色、诊所、对象独立核验；一条源出诊最多一条活动任务。|
|BR-T02|任务与患者承诺、暂停标志分离；新建任务不自动暂停，取消任务不自动恢复。|
|BR-T03|前台自行受理；仅受理人办理；无效账号由主管退回队列，不能代签。|
|BR-T04|声明是操作者报告；固定枚举、受限对象、不含个人/临床自由文本。|
|BR-T05|提交/复核均检查完整有界业务事实；当前页面数量不作为清空依据。|
|BR-T06|复核人与本次提交人为不同账号；摘要变化后须重新办理。|
|BR-T07|签名绑定主体/上下文/对象、900秒有效；修订防ABA；重复请求不重复写。|
|BR-T08|任务与审计同事务，所有任务命令遵守源出诊行锁；数据库有唯一/状态/历史保护。|
|BR-T09|只读模式禁止任务写入；查询失败不等于前次办理失败；无自动重发。|

OPEN → IN_PROGRESS（前台受理）→ READY（事实无阻断并提交）→ CLOSED（另一账号主管重验）。
IN_PROGRESS → OPEN（本人交接或主管退回）；READY → OPEN（主管退回）。
OPEN/IN_PROGRESS/READY → CANCELLED（主管撤销）；CLOSED/CANCELLED不重开/删除。

## 分析与实现合同

- 边界：task_views/forms接收目的、依据、声明对象和确认，过滤错误，不在模板授权。
- 控制：task_services维护身份/上下文、预览/确认、锁定、状态迁移、幂等和审计。
- 核心事实：CoordinationTask（源、目的、受理/提交/复核、修订）；AvailabilitySlot/Visit/WaitOffer仍拥有各自业务状态；AuditEvent保留责任事件。
- 纯规则：task_rules不导入Django/网络，不将声明变成业务事实。
- 证据投影：task_facts只读必要关系字段；主管得到聚合；前台按需定位原记录。
- 最终维护与任务写命令不互相调用；共享的是源锁与事实核验规则，不复制取消逻辑。

## 验收组（不是已执行结果）

AT-T01：新建/重复/同源唯一；暂停前拒绝；保留旧有效承诺。
AT-T02：本人受理、另一前台冲突、被停用受理人的交接；跨角色/跨店/旧页/CSRF。
AT-T03：声明对象归属、无患者数据泄漏、不改预约、声明不能放行结案。
AT-T04：真实阻断/过期/接诊保护/上限/开始时刻/摘要变化/独立账号复核。
AT-T05：失败回滚、成功重放与后续状态保护、任务身份/终态/删除约束。
AT-T06：空表升级保留既有资料；有任务时拒绝直接反向删表；带数据升级与恢复另验。
AT-T07：真实双连接同源发起、同任务受理竞争；源锁协议与既有入口交互。
AT-T08：真实页面、移动端、大字、键盘与原业务回跳。当前静态页面检查不能替代这一项。
