# C3.1 初复诊病历文书业务合同

实际接诊 → 检查与处置来源 → 完整文书草稿 → 医师确认 → 历史对比与追加更正 → 责任待办。

本合同覆盖C3.1，使用课程合成临床资料。当前交付状态以[evidence_c31](evidence_c31/README.md)为准；C3.2治疗知情同意、可靠电子签名验证、专项上级复核和C3.3病案归档不因此完成。[完整路线](C3_RECORD_CONSENT_ARCHIVE_PLAN.md)。

## 1. 岗位和正常流程

只有本次负责医师且具有当前诊所、服务及操作专业范围的账号，才能整理、确认和更正文书；查阅也检查当前专业范围。前台继续负责排班，不因办理预约获取完整病历；患者、代约人、主管、总部、财务和技术角色均不增加临床全文权限。

1. 新检查开始时，在同一事务建立一份文书责任待办，原检查记录、实际执行和结算命令保持原职责。旧接诊不批量补造文书、确认或签署。
2. 医师选择初诊或复诊。填写诊断／判断及依据、辅助检查与来源、离诊医嘱、复诊及异常联系建议。复诊可引用本人有权查阅的本店既往准确文书，或记录院外／纸质资料及本次变化，不自动照抄正常结论。
3. 文书引用确认检查、指定自述、牙位观察、本次方案及实际执行／接诊处置。未知继续未知，估算不成为实际处置，文书不添加治疗和金额。
4. 可以在接诊中保存草稿；按原临床流程结束接诊后，再确认包含实际处置和离诊医嘱的完整文书。文书草稿不进入原接诊关闭阻断条件，不延长椅位占用、不阻塞原结算。
5. 医师预览服务器保存的准确内容和来源，明确确认；发生、录入、确认时间分别保留。账号确认和纸质原件引用分别标识，内容摘要只用于完整性核对，不标作可靠电子签名。

## 2. 历史、更正和异常

- 已确认版本、来源快照、当时患者／诊所／医师显示信息及办理事件保留，数据库触发器拒绝覆盖或删除。后续姓名、介绍和目录变化不重绘原文。
- 更正须说明依据，基于当前确认版本建立新草稿；确认形成前版链接及新版本，原版继续可读。放弃草稿必须说明依据，不删除已确认内容。
- 比较页逐项展示诊断、医嘱、复诊安排、检查／病史、方案和实际处置来源；打印只读取所选确认版本，不伪造印章或归档回执。
- 确认会重新检查工作身份、授权、草稿版本、患者、既往来源、实际接诊状态及来源摘要；旧预览不能确认改变后的资料。
- 并发确认只产生一个新有效版本；原成功操作重试返回已保存结果。相同操作编号但内容变化不谎报保存成功。撤权后原预览与重试不能绕过授权。
- 保存冲突保留本页输入并展示当前已保存内容；“比较最新文书并保留本页填写”只更新办理依据，不自动保存，仍需明确提交。
- 当前检查、已采用接诊版本或患者自述发生变化，文书工作台标记来源待复核；原确认文书不被自动替换。新自述未复核时不能确认新文书。
- 文书更正不改账单、治疗行、医保、收款退款或经营金额。发现实际费用问题，继续走原财务更正和独立审核。

## 3. 待办和期限

入口：`/clinical/documents/`。本人按待完善／待确认、超期、已确认和全部筛选。每项显示责任账号、原／本次期限、下次办理时间，并链接具体文书。

新文书默认从建立起24小时为课程工作台办理目标，可通过`ADC_CLINICAL_DOCUMENT_DUE_HOURS`机构设置调整；**不是所有门诊的法定归档期限**。追加更正单独建立办理期限；原首次期限继续保留。跟进仅追加进展和下次期限，不消除超期，不自行确认文书。迟记须说明依据，不能修改实际确认时间倒签。

本批不自动给其他医师交接病例权限，不增加主管全文入口；责任人授权失效须按既有机构职责核对接续，不能通过改变文书负责人冒名签署。归档、医务批准和专项交接职责在C3后续批次实施。

## 4. 数据与接口

保留原64份应用迁移的字节，新增`clinical/0007_outpatient_documents`。实际PostgreSQL观察：146张表、402条SQL外键、114项业务触发器；65份应用迁移，另含框架迁移。

四个新增表：文书入口及责任期限、可继续编辑的文书草稿、不可变确认版本、追加办理事件。检查、实际执行及财务版本保持原所有权。来源JSON中的计划和执行编号为逻辑追踪，只有实际FK列画为SQL外键。

员工网页使用现有Cookie、CSRF、工作上下文与服务端预览；不新增外部业务API、不向患者小程序开放临床文书写入。新增页面：

| 路径 | 用途 |
|---|---|
| `/clinical/documents/` | 本人文书与责任待办 |
| `/clinical/encounters/<visit>/document/` | 草稿、确认历史、更正与跟进 |
| `.../document/preview/` | 完整文书及准确来源预览 |
| `/clinical/documents/confirm/` | 明确确认，事务重检 |
| `.../document/compare/?left=1&right=2` | 同文书历史比较 |
| `.../document/print/?revision=1` | 受权限控制的准确版本打印 |

敏感读取审计覆盖新增入口，运行日志不记录临床正文或证件值。业务操作ID、上下文和原锁序沿用既有合同。

| 规划场景 | 实际测试入口 |
|---|---|
| A01—A03 初诊、复诊、无治疗 | `test_clinical_documents`：完整投影、准确既往来源、未知保留、处置与金额独立 |
| A04 缺项与冲突 | `test_clinical_document_http`：输入保留、当前内容比较、明确继续；完整性不足不确认 |
