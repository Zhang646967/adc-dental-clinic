# D2.1 统一系统最新版部署包

准确源码 → amd64镜像 → 空库初始化 → 重复执行核对 → 可验证的部署状态。

本批沿用统一ADC产品和现有部署接口，不新增教师版，不新增数据库表或迁移。保持全部80份应用迁移及原业务权限；服务器、域名尚未提供，当前目标是隔离演练和可交付构建产物，不提前标记公网或临床商用验收。

## 本批范围

- `build.json`增加从Git归档源码计算的发布清单：迁移数量与摘要、依赖清单摘要、原生客户端源码树及页数、患者和员工入口。清单不读取私有配置，也不代表小程序已编译或平台验收。
- `course_release_status`读取实际迁移名称集合，报告缺失／额外迁移及源码一致性；保留旧的数量和摘要字段。仅数量相同不能证明数据库与当前源码一致。
- 部署状态在数据库版本未知、源码提交不同或迁移不一致时显示降级，避免仅容器正常就显示原站就绪。原有镜像和HTTPS核对继续执行。
- 访问回执使用统一系统说明，不再引向教师专用产品。旧命令及私有回执文件名保留兼容。
- 浏览器演练按当前患者页面展开备用账号表单，使用正常登录；390宽检查不再依赖已移除的模式按钮。微信未配置时不再引导用户使用可能同样未开通的手机号方式。

本批不改微信换码、短信发送、会话或医疗权限，不要求WorkBuddy重复微信重登或已通过的副本流程。

## 安装与数据核对

从确定提交构建linux/amd64镜像，记录不可变摘要和实际依赖。使用新私有目录、独立网络、数据库卷和仅本机端口安装；不能把原`.rc`、数据库或私有微信配置复制进新环境。

空库运行全部80份迁移及正常初始化命令，准备二十店、每店四类基础服务、医师画像、资源和未来十四天出诊。基础初始化不制造诊疗、账单或资金事实。账号只输出至私有文件。重复初始化和部署应返回原完成记录，密码、旧行及私有凭据文件保持；有部分进度时保留现场，不隐式重置。

通过真实HTTPS浏览器核对七角色、患者与员工分流和必要的业务读写；演练产生的合成记录单列。核对通知／监测进程、数据库owner与runtime分离、原生源码和80份迁移保留。加密恢复使用匹配镜像及同版本迁移建库路径，保留已有一般等价结构比较限制。

## 验收边界

当前构建、初始化、浏览器、状态和恢复结果见[本批证据](evidence_d21/README.md)。旧D1的64份迁移、139组记录和142张表不能替代本批最新版结果。原系统和WorkBuddy已验收环境保持，实际服务器容量、重启、证书续期、独立存储、24小时观察、小程序设备／真机及平台继续另验。

D2.2仍负责含追加迁移的跨业务版本升级；本批不把现有同结构换镜像描述为数据库升级能力。D2.3继续验证实际云端独立运行与异地备份。

思维导图：统一发布 → {源码、镜像、迁移、原生客户端} → 空库安装 → {账号与目录、真实浏览器、状态核对} → 重复执行与恢复 → 实际服务器验收。
