# R2.4.2 业务依赖故障演练与处置

业务受影响 → 区分依赖 → 认领责任 → 恢复目标服务 → 核对业务事实 → 关闭事件。

## 演练合同

使用独立的五诊所合成实例，含实际账单、已审核收款和设备台账。原 Mac、其他演示实例及历史数据卷不注入故障。四种故障分别留下触发、观察、恢复、资金和接诊事实核对记录。主机事件、应用状态和业务结果分别判断；没有自动业务修复。

| 依赖 | 业务影响与判断 | 运维责任及恢复顺序 | 业务恢复核对 |
|---|---|---|---|
| 通知 worker | 新协调任务已提交，消息暂未送达；任务仍保留。主机显示进程停止，应用 worker 条件随后 CRITICAL。 | 平台运维检查数据库和目标进程，再启动原 worker；不重做协调任务。 | 原事件送达一次，收件人各一条，任务版本不变；资金、接诊和授权事实不变。 |
| 应用 observer | 当前业务仍可运行；观察记录超过90秒后，独立读取 UNKNOWN。主机立即显示监测进程停止。 | 运维认领监测故障，检查私有文件及身份；正常停机重启原进程，不删除状态。 | 停机时通知仍可送达；恢复须新的成功采样；旧事件仍保留。 |
| PostgreSQL | 健康检查503；队列积压未知，不能解释成0。部分业务请求可能已经提交，必须先核对持久结果。 | 运维先恢复原数据库及就绪状态，再启动因数据库故障退出的 worker；确认 observer 正在采样。 | 独立计算账内金额、核对账单及临床摘要、任务版本和消息唯一性；不创建平衡款、不盲目再次收退款。 |
| 网关 | 浏览器入口不可达，内部应用及 worker 可继续正常工作。内部健康不能证明用户入口可用。 | 运维检查端口与目标网关，再启动网关；检查实际浏览器入口。 | 停机期间通知继续送达；恢复后入口正常，账内金额和诊疗事实未改变。 |

平台运维仅获得技术处置能力；前台、诊所主管、牙医及不同账号的财务复核继续使用既有授权流程。请求中断后先查原申请/版本/状态，结果不明则交负责人核查，不能凭错误页面再次办理收款、退款或治疗完成。

## 执行工具

`scripts/dependency_drill.py` 仅用于演练，不提供日常生产故障注入入口。它要求显式本地 Docker context、RC 项目、已识别源码、私有演练标记及运行容器的 `ADC_DEPENDENCY_DRILL=项目名`；普通 Mac 实例缺少该标记，会在任何故障操作前拒绝。

准备全新 RC 演练根目录，使用既有 `scripts/rc_config.py` 和 `scripts/multiclinic_seed.py` 建立五诊所合成数据。独立 Compose override 为三个应用服务设置上述演练环境变量，文件位置为 `.rc/private/rehearsal-compose.json`。在同一私有目录生成 `dependency-drill.json`，包含本实例 project、40位 source 和回环 port。禁止给原 Mac 实例增加演练标记。

```sh
python3 scripts/dependency_drill.py --root /absolute/synthetic-rehearsal \
  --output /absolute/private-evidence --context desktop-linux \
  --docker /absolute/path/to/docker --confirm-synthetic-faults
```

工具按明示步骤停止/启动四类依赖，保留私有技术状态和结果。监测过期使用真实时间；不把时间跳跃或修改阈值当成持续故障演练。默认采样周期30秒、过期阈值90秒保持不变。失败时保留结果及测试实例供定位，修复后明确重跑相关场景，不把失败记录覆盖成通过。

恢复后先用现有应用状态核对六项条件，再检查主机记录、实际入口、数据库事实和金额。事件认领不能清除故障；记录处置、新采样验证后才能关闭。临时容器和网络可清理，测试卷保留；不用删除卷的方式“恢复”故障。

## 时钟或身份异常的额外处置

若 observer 因时钟不连续退出，先保留并验证加密观测历史，停止旧采集，再使用既有 `operations_reset --confirm-reset-observations` 显式归档、开始 UNKNOWN，重启同一已识别版本。主机事件簿记录该过程。不能把恢复后的新采样补成遗漏期间的健康。

应用版本更新时同样先保留旧身份观察；切换版本后建立新身份观察。这个流程不恢复业务数据库，也不改变财务或诊疗事实。

本轮完成情况见[执行证据](evidence_r242/README.md)。30分钟等价容量、真实24小时、安全评估和独立公网仍是后续门槛。
