# 患者收退款总额与逐笔查询

本单账单 → 已记账收款与退款 → 当前净额 → 逐笔核对 → 原门店办理。

本增量补齐患者网站和小程序的费用解释：分别展示已记账收款、退款、净收款、待付与应退，逐笔列明业务日期、记账时间、金额及状态。它只读取现有CashEntry，不改变原收退款申请、独立审核或账单发布规则，不产生支付交易。

## 业务规则

- 只有POSTED的本单患者收款和退款进入总额及明细。PENDING请求继续提示待复核，REJECTED不作为资金；设备费用及冲回不进入患者账单。
- 净收款＝已记账收款－已记账退款。患者现金责任、医保等非现金承担、实际现金记录继续分别计算。
- 查看历史账单时保留原收费版本，但收退款及余额对应当前账单，页面明确说明其不是历史时点余额。重新读取或打印不记账。
- 无已记账记录时显示零总额与明确空态。明细按稳定记录编号倒序，每页20笔；翻页保留所选账单版本，总额始终覆盖全部已记账记录。
- 患者本人及有效PatientAccess才能读取；预约代理、限定医疗代理、其他患者及撤权后账号不因此获得费用权限。翻页和重读仍由原入口重新核权。
- 只读投影白名单为种类、金额、币种、业务日期、记账时间、状态和界面稳定键；不包含员工备注、审核原因、收款渠道账号、资金凭据引用或员工身份。

## 模块与读取

财务模块`finance/patient_cash.py`拥有患者可见的已记账投影；`care/invoice_queries.py`在授权后的同一报表快照中组合已发布账单、余额与明细。网站和既有小程序结算接口共用该投影，新增`cash_page`查询参数；未指定时读取第一页。原接口字段兼容，不增加写入接口。

小程序保留原生结算页，增加总额、逐笔列表、翻页和失败后重新读取。网站采用本人费用区域，员工仍在原财务办理页工作。浏览器版本切换及原生翻页均保留准确来源和当前权限。

数据库保留全部75份迁移，无新增表、列、外键或权限。ER中的Invoice—CashEntry关系保持原结构，本次仅补充读取说明，不把界面投影画成持久实体。

## 验证与交接

新增PostgreSQL场景核对零记录、收退款、待审与拒绝排除、白名单、分页、查询数量、日期、历史版本、撤权及跨患者拒绝；原本人账单与医疗代理隔离继续回归。页面处理测试不代替官方工具或真机验收。

交付前完成准确源提交完整CI、真实浏览器与原生处理函数接真实后端读取、加密备份及独立恢复、原业务保护更新。独立新环境用于WorkBuddy费用只读回归，保留上一批冻结环境和全部医疗决定历史。费用展示不改变认证链路，不要求重复微信登录或解绑。

本增量不新增30分钟容量结果；以每页上限、固定查询数量和实际读取延迟核对该只读变化，不沿用旧容量作为新云端证明。手机、设备矩阵、平台和云端继续按原条件分别验收。

思维导图：本人权限 → 当前账单及发布历史 → {已记账收款、已记账退款、净额} → {日期、状态、分页、空态} → 费用核对 → 原门店办理。
