# v0.9.0-alpha.1：所选候补结果核对

## 这是哪个版本
候选分支承接v0.8.0-alpha.2。运行基线仍为用户的v0.7。版本号按本轮要求进入v0.9，但没有声称v0.8剩余的资源、后台、求解与生产工作已完成。

## 实际新增
患者“我的候补”和本店前台候补列表，在指定记录上新增“核对这条候补是否已转预约”。邀约确认页也提供结果未知时的核对入口。手动提交核对请求（POST携带CSRF及现有工作上下文令牌），不执行接受、退出或创建预约。

规则显示：等待安排、可接受窗口结束、仍需确认、确认期已过、已转预约、已到诊、已结束、后来取消/改期/爽约，以及关联需要核对。先核对接受历史，再判断尚未接受机会的期限。只对本条候补沿直接关联返回正确预约；不按“最近预约”猜测。

入口路由名：guide_result_wait；实际URL由guidance/urls.py与根路由组合。只允许PATIENT/FRONT_DESK，本店主管不因能看匿名候补而获得个人预约核对结果。链接只进入既有业务页；正式操作再次授权。

## 数据与接口
- 没有新表、字段、迁移、服务进程或依赖。
- `result_rules.py`：独立纯规则，只接收必要事实；冻结dataclass。
- `result_selectors.py`：先使用既有授权范围，单条关系查询装配所选请求、相关邀约及对应预约。
- `result_views.py`：当前角色/范围/签名与返回前重验，no-store响应，数据库读取异常时通用反馈。
- 不发送患者姓名、电话、过敏、主诉、治疗、DOM、密码或API Key给外部模型；核对不调用模型。
