# 真实微信联调：配置与部署修复

私有输入核对 → 官方凭据预检 → Web出站与启动校验修复 → 账号映射验收。

本批修复两个实际部署问题：RC Web仅在内部网络而无法调用微信；启动校验不接受WX1应用工具写入的认证配置。Web复用已有网关网络提供出站连接，不开放数据库或Web端口；live模式继续禁止演示短信及本地身份替身。患者、预约、临床、财务及全部64份迁移不变。

后续真实服务联调确认：微信返回`image/jpeg`小程序码，原实现只接受PNG并固定发送PNG响应头，导致网站不能展示登录码。新增JPEG／PNG格式识别，保留原始图片字节，并按实际格式返回；保留1MiB上限、错误响应拒绝及原浏览器私有绑定。格式兼容与数据库／HTTP交付测试独立于真实平台结果。

2026-10-29的私有输入已修正字段位置。一次真实微信官方`stable_token`调用成功，未记录返回令牌、密钥或用户身份；这只证明该次服务连接和应用凭据被接受，尚不能证明用户微信登录或教师体验。后续真实登录和网站确认已执行，见下方最终分项记录。

WorkBuddy回传的24页工具检查及上传探针属于接收方执行记录。准确客户端提交`c6d1e15e86cc04f538010fe8542d25b97f4f05b7`的[完整CI](https://github.com/Zhang646967/adc-dental-clinic/actions/runs/40804150312)已成功；原有自动化超时记录保留其发生时的范围。

小程序部署仍由WorkBuddy负责。主系统维护方负责后端凭据、会话和权限；本机联调与固定HTTPS教师体验分别验收。没有免费真实短信条件时保持关闭；云服务器与域名未购买。

首次启用因本机Docker默认地址池耗尽而停止在服务重建阶段，数据库未停止；随后改为复用现有网关网络。未清理其他项目、网络或数据卷。首次候选CI与最终修订版分别记录。
