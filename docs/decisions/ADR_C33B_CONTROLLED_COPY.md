# C3.3B 逐申请核验与受控电子副本

状态：已实现，准确发布和执行范围以`docs/evidence_c33b/`为准。

采用现有Django、PostgreSQL、账号通道和通知工作进程。新增申请、范围项、固定文件、追加事件四个实体；不新增通用授权服务、对象存储、公开下载链接或证件附件库。复制资格限定到本申请的患者、门店、用途、版本、资料类别、领取账号及期限，不建设额外长期全病历代理权限。

患者模块继续拥有本人关联、代约和医疗代理，既有权限不扩大。申请人通过账号通道办理自己的副本；本人新申请仍要求本人档案权限，专项代理申请由有职责前台登记并核验本用途原件。没有完整病历权限的注册账号也能领取特定获准副本。患者、员工和小程序共用复制命令，不改原预约、治疗或财务命令。

前台职责与医务副本审核职责分别默认关闭。医务审核须由另一名获委任医师办理，还须对应服务读取范围；不能由主管、技术身份、申请人、原负责医师或材料核验人替代。核验及审核的每次结果追加事件，准确来源通过实际外键引用归档包。空来源仅能在待材料核对阶段补齐；已有来源、原申请身份与用途、发布文件及事件受SQL保护。

复制从明确选择的固定快照生成患者投影，保留临床确认来源与版本，不复制内部身份材料和员工审批正文。生成在事务外排版，提交时锁定领取账号及申请，重核准确范围、身份和审核适用性。既有工作进程有界处理，无独立队列基础设施；失败明确重试，不发布部分文件。

短时领取凭据使用已有签名工具，绑定登录账号、工作区版本、申请修订及文件摘要。领取接口始终需要实际会话并重新核权，不把凭据当通用访问权。文件存入数据库并随现有加密备份恢复；不暴露静态文件路径。一次领取确认可在有效时间内重试相同文件响应，响应事件去重；网络响应、阅读、机构证明印记及可靠电子签名分别表述。

来源和限制：规定要求指定受理人员核对本人及代理材料，并允许先行复制已完成部分；后来的条例涵盖门诊病历、医疗费用等资料。[病历管理规定第17—22条](https://www.fxtp.gov.cn/content/2023/797639.html)、[条例第16条](https://www.beijing.gov.cn/zhengce/gwywj/201905/t20190522_61432.html)。本批在线处理已结束接诊的固定电子材料；其他资料及实际证明印记按机构另行受理。独立审核、在线凭据、七日默认及三十日上限属于ADC设计选择，软件测试不代替真实机构制度和专业审定。
