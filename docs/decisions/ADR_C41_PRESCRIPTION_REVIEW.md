# C4.1 门诊处方与独立审方

确认就诊记录 → 开方预览与提交 → 本店药师审核 → 保留决定或重新提交。

## 范围与岗位

采用单店合成门诊验证 C4.1，目录条目和授权依据均为合成资料。功能需要同时启用合成环境和处方演练开关。真实目录、专业资质、签署和用药知识来源需要合作诊所验收。C4.2 承接划价、收费、调配、部分发药及退药。

| 岗位 | 可办理事项 | 范围 |
|---|---|---|
| 负责医师 | 查看本次处方，填写、预览、提交，撤回待审版本，按退回意见重新提交 | 本人负责、已到诊、有当前确认病历，具备服务级记录授权和本店开方职责 |
| 药师 | 看待审与历史，预览并确认通过、退回或拒绝 | 当前诊所、有效药师身份及独立审方职责。不同账号办理开方与审方 |
| 其他岗位 | 原工作台业务 | 处方的读取及办理分别验证角色和对象范围 |
| 演练维护人员 | 在隔离库配置合成目录和有期限的职责，登记撤销 | 仅限明确启用的合成实例 |

## 状态与归属

~~~mermaid
stateDiagram-v2
    [*] --> Draft
    Draft --> Pending: 医师确认提交
    Pending --> Approved: 药师通过
    Pending --> Returned: 药师退回
    Pending --> Rejected: 药师拒绝
    Pending --> Withdrawn: 医师撤回
    Returned --> Draft: 按意见起草新版本
    Withdrawn --> Draft: 重新核对后起草新版本
~~~

首轮每次就诊建立一张处方，允许最多五个受控目录条目。拟稿留在本次表单和签名预览，确认时保存版本。每个版本固定患者所对应的就诊、病历版本、开方职责、临床依据、目录条目快照、剂量单位、途径、频次、疗程和数量。药师只读取审方所需的患者标识、临床依据、引用版本中的用药与过敏自述及处方内容。

处方版本和决定分别追加。一个版本只接受一个最终决定，包括医师撤回。退回或撤回后的再次提交关联同一处方，旧版本、审核意见和账号留痕可查。一次确认绑定一个操作编号，重复确认读取原结果。重要条件在事务内复核，包括账号、工作范围、职责有效期、当前版本、病历来源和目录。病历或自述在待审期间更新时，原版本可退回或撤回供医师复核。通过决定是 C4.2 的输入事实，收费和调配由各自模块另行办理。

采用可执行需求和模块间的信息隐藏。处方模块拥有版本和审方决定，读取临床模块的确认病历与有效专业授权。既有 [商业路线图](../COMMERCIAL_V2_MASTER_PLAN.md) 与 [医疗机构处方审核规范](https://www.cnjx.gov.cn/OpennessContent/show/1143862.html) 分别给出工程依赖和审方前置要求。

## 需求与证据

| 编号 | 可执行验收 |
|---|---|
| RX41-01 | 负责医师从确认病历打开表单，提交后药师队列读到同一版本。非法目录、剂量或缺失必填值返回明确错误。 |
| RX41-02 | 药师退回，医师追加版本，药师通过。查看首版、决定与新版，三类记录相互关联。 |
| RX41-03 | 前台、其他诊所药师及仅有一般医生身份的账号不能通过直达链接读取或办理处方。双身份账号不能审核自己提交的版本。 |
| RX41-04 | 撤销、到期或切换工作范围后，旧确认凭据不能写入。病历更新后的旧处方不得通过。 |
| RX41-05 | 两个独立连接对同一版本提交不同决定，只落一条。重放同一确认得到原结果。 |
| RX41-06 | 在真实 PostgreSQL 核对追加迁移、原业务表和账单记录，检查版本与决定不可覆盖。另库恢复后复查处方链。 |

按源码、隔离库、浏览器操作、独立恢复及合作诊所验收分别记录结果。
