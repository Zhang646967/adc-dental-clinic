# 检查结果审核与患者发布

开具申请 → 登记实际执行 → 追加报告版本 → 独立审核 → 负责医师发布 → 患者回查。

## 业务合同

| 办理 | 岗位 | 规则 |
|---|---|---|
| 开具 | 本次负责医师 | 在已到诊且检查记录已确认的就诊中，选择匹配本店预约服务的检查项目。申请固定关联当时确认的检查记录版本。 |
| 执行与登记 | 本店、本项目授权医师 | 记录实际检查时间和依据编号。就诊已经结束时，仍可登记原就诊期间实际发生的检查及随后取得的结果。 |
| 审核 | 另一名具备本店专业审核任命及项目职责的医师 | 审核准确版本。申请人、执行人和该版登记人均不能审核该版。退回需留理由，完善内容形成新版本。 |
| 发布与撤回 | 原就诊负责医师 | 审核通过后另行确认发布。更新期间原发布版仍可查阅。新版本发布后旧链接失效。撤回需留原因，后续再次发布使用经审核的新版本。 |
| 回查 | 患者本人、本店前台、已关联复诊的负责医师 | 本人查看进度和当前发布版，前台仅查看本店进度，复诊医师通过有效复诊关联及专业范围读取当前发布版。 |

本批在可写合成实例按一个门店、一个文本检查项目配置。项目职责通过 `configure_examination_rehearsal` 登记，继续复用医师身份、专业范围和独立审核任命。检查申请、结果版本、办理事件与既有账单、文书和归档各自留存。报告晚到时，在原就诊继续办理。已归档文件按其原快照保存。

## 患者端接口

- 原 `GET /api/mini/v1/visits/<visit_id>/` 追加 `data.examinations` 数组。每项包含 `id`、`number`、`project`、`requested_at`、`state`、`label`、`revision`、`released_at`。时间为 ISO 8601，页面显示北京时间。
- `PROCESSING` 显示「检查办理中」，`WITHDRAWN` 显示「报告已撤回，请联系门店」。这两种情况的 `revision` 和 `released_at` 均为 `null`，无报告入口。代约人的数组为空。
- `PUBLISHED` 允许打开 `GET /api/mini/v1/visits/<visit_id>/examinations/<id>/?revision=<revision>`。响应 `data` 包含 `id`、`number`、`project`、`visit_id`、`visit_no`、`performed_at`、`revision`、`released_at`、`body`。从清单打开时传准确版本。无版本参数时读取当前版。正文按纯文本呈现。
- 网页从「我的预约 → 就诊详情 → 检查与报告」查阅同一投影。旧版、撤回、未发布、他人和错配就诊编号的报告详情统一返回 404。有效代约身份请求报告正文返回 403。就诊人或会话失效继续走原错误契约。页面重新进入时重新读取，失败后清除旧正文。

## 可执行验收

`tests/test_examination_reports.py` 覆盖网页预览和确认、审核后仍未发布、退回与更正历史、撤回和旧链接、已归档后登记、原账和归档原件对比、复诊准确关联、跨店／跨患者／代约、职责撤销、重复确认和 PostgreSQL 并发。本机浏览器与小程序接口联调各自记录。小程序页面和工具回归由 WorkBuddy 在冻结合成环境接续。
