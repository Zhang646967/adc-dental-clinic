# 患者服务体验与跨端候补衔接

清楚入口 → 当前安排 → 候补协调 → 明确决定 → 两端同一结果。

本阶段实施B1.5.3渠道补全，并改善患者页面的专业感与实用性；原B1.5.2微信平台试用继续等待AppID及实际平台验证。课程展示范围保持不变。

## 患者需要解决的问题

患者不能只看到“没有时段”而无后续入口，也不应在网站和小程序分别登记。网站及原生首页现在集中展示下一次就诊、待确认邀约、候补数量与历史，统一使用浅色背景、绿色主操作、明确状态文字与大字阅读。人工协助与指南直接可达，助手保留为可选入口。

小程序新增候补登记、候补进展和邀约详情，沿用原服务、日期及诊所偏好进入候补；候选查询仍不占位。可接受范围按北京时间核对未来十四天及完整服务时长，每位患者同时一条有效需求。前台继续负责网站排班、生成建议及明确发布，主管不接管日常排班。

## 业务决定与结果

| 操作 | 保存结果 | 原有安排 |
|---|---|---|
| 登记候补 | 等待前台协调，尚未成约 | 继续保留 |
| 接受并新增预约 | 邀约转为一条正式预约 | 其他预约保留 |
| 用邀约替换指定原约 | 原约已改期、唯一后继、原邀约接受历史 | 失败时原约与有效承诺保留 |
| 拒绝本次邀约 | 释放暂占，需求继续等待 | 继续保留 |
| 退出候补 | 需求退出，未确认邀约撤回 | 已有正式预约保留 |

页面要求先选择邀约用途，再预览并明确确认。拒绝与退出有各自的确认说明；不会将两者误认为取消预约。已接受邀约展示正式预约的当前状态，资源目录改名不重写原预约或邀约的服务名称。

## 共用业务与权限

受控接口在`/api/mini/v1/`增加服务概览、本人候补、登记／退出预览确认、本人邀约及接受／拒绝预览确认。患者仅能访问绑定本人；前台发布继续经过原网站。原CSRF、工作身份签名、事务授权及患者／出诊／设备锁继续有效，客户端传入的患者或诊所字段不授予权限。

登记确认在原患者锁内保存候补及追加式审计回执。相同签名请求重试返回已保存记录的当前状态；稍后退出后重试也不恢复旧登记。退出与邀约处置重检候补版本，失效、撤权或并发冲突要求核对当前结果。邀约改期复用既有唯一后继和BookingReceipt；未增加数据库表或迁移。

会话过期会清除客户端暂存核对内容，登录后重新办理；密码、会话和核对令牌不持久保存。不自动重试写请求，也不推测断网是否成功。课程没有真实电话、短信、微信推送、在线诊断或实际付款。

## 已执行验证与边界

完整本地回归1,052项规则、1,402项数据库／HTTP／并发；新增25项针对候补与邀约。五诊所由实际小程序Page逻辑连接HTTP／PostgreSQL，真实Chrome前台发布并由患者网站核对，258项联调及48项独立数据库事实检查通过。九页WXML及WXSS通过官方离线编译；390px大字号与键盘操作另有页面检查。

实际微信渲染、手机、体验版及云服务器尚未验收；官方离线语法编译不能替代它们。既有三十分钟容量证据保留原版本和工作负载，本阶段未另做容量声明。所有演练使用独立合成资料，不写入原本机业务。
