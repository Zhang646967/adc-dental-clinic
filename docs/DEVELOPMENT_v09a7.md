# v0.9.0-alpha.7：前台出诊协调与原流程回跳

**父版本：v0.9.0-alpha.6（累计替代记录版）；课程报告：R4.4，保持冻结。**
最后确认运行实例仍为Windows上的v0.7；Mac迁移继续暂停。本轮没有连接或操作用户实例。

## 1. 问题与有限目标

alpha.6只允许主管维护无受保护业务占用的未来出诊。存在预约或有效邀约时，系统会拒绝，但前台此前只能在较大的预约/候补列表中逐个寻找对应记录。

本轮SU-31以一个明确出诊编号为入口，集中展示精确关联的预约和邀约，解释当前阻断因素，并进入原有办理流程。返回后再次查询当前事实。它是一份**按出诊核对的只读关联视图**，不是已下达的停诊指令、协调工单、患者通知或受理承诺。

原SU-29/30没有变更：时间调整仍是保留旧时间并停用旧记录，再新建同店同牙医替代记录。没有恢复旧出诊或原地覆盖历史时间的新入口。

## 2. 两个岗位如何衔接

1. 主管在“出诊安排→查看安排与影响”核对确有调整需求，将**出诊编号**和业务意图通过现有人工沟通方式告知本店前台。本轮没有自动派单/通知。
2. 前台进入自己的工作台，选择本店，打开**出诊协调**。输入出诊编号可精确查找（包括历史），也可浏览未来/进行中的关联出诊。
3. 前台核对诊所、牙医、时间、查询时点；查看本出诊的预约/接诊及邀约两类关联记录。列表不是取消清单，不能为“清空排班”而机械处理每行。
4. 前台先按原制度核对患者身份和真实意思，再逐条进入**原预约详情/改期页面或有效邀约处理页面**。本协调页没有接受、取消、改期、回收、批量提交等写入按钮。
5. 原操作成功后，可沿已验证的回跳入口返回同一出诊。原预约详情新增同患者/同诊所的直接前驱和后继预约链接，便于核对改期结果。
6. 查询没有发现维护阻断，只显示“当前未发现维护阻断，可请主管重新核对”。主管另在自己的工作台重新读取并提交维护。

### 典型状态解释

|事实|解释与入口|
|---|---|
|已预约，计划开始尚未到|先核对患者意思；可打开原详情或原改期。改到同一原出诊内仍未释放该出诊。|
|已预约，但计划开始已到|不从时间自动推断爽约；先核对实际到诊，再按原规则办理。|
|已到诊、治疗完成、无治疗关闭|受保护接诊，不为维护排班取消、改期或删除；不显示快捷改期。|
|PENDING且确认期未过|仍有有效保留；进入原邀约核对，不代替患者作决定。|
|PENDING但确认期已过|已不占位，标明“状态尚未回收”；本页不回收、不提供首次接受入口。|
|ACCEPTED且关联一致|实际处理对象是其直接关联预约；不把原邀约再计为第二份保留。|
|已取消/已改期等历史|保留，不重复办理；在原预约详情核对直接后继。|
|来源已停用/已开始|按历史/现场业务核对，不显示可维护结论。|
|关系异常/超过完整核对上限|不展示可能越界的患者编号及深链，不把局部结果认定为空闲。|
|读取失败|反馈本次结果未知；不意味着前次改期或取消失败，不自动重发。|

## 3. 权限、查询和导航边界

- 只允许当前激活FRONT_DESK且选择并获授权的诊所。主管、牙医、总部、技术管理不能因另有角色或超级用户标记而读取这一前台视图。
- 先验证当前范围，再读取具体出诊；返回前再次核对上下文/授权。临床信息、姓名、电话、邮箱不会投影到新列表；仅用患者业务编号辅助定位，不把编号当身份认证凭证。必要联络资料在原获授权详情中核对。
- 列表每页20项；预约和邀约分别每页20项。是否有阻断由分页前的完整有界关系集合判断，而不是当前可见一页。继承每类1000条的核对上限，超过则停止给出清空结论。
- 单条出诊读取在短事务内使用现有源出诊行锁；页面返回就结束。这不是冻结接收新约。后续写命令仍独立核验，其他用户可以在查询后产生新预约。
- 全部新页面为GET且设置no-store；只读实例允许授权查询，不增加业务写入例外。原写服务完全不变。
- `coord_slot`只能是受约束的出诊整数编号，不接受任意URL。回跳核对当前对象及直接前驱与来源出诊的同诊所/同患者关系。非法来源忽略，不增加访问权；目标页面仍独立授权。
- 新显示状态是派生解释，不写入新的数据库任务状态。没有“已联系患者”或“协调完成”按钮，不能以阅读/点击推断业务事实。

依赖下载失败、环境故障或测试错误都要保留；不以SQLite、跳过安全断言或删除旧卷绕过。本轮生成环境未运行真实DB，不将随包静态图片当作本机演示。

### 在合成数据副本中的人工验收

|编号|操作|应观察的事实|
|---|---|---|
|FC-01|主管提供一个有预约出诊编号，前台输入查询|精确同店原出诊；主管不能直接进入前台详情|
|FC-02|前台由列表进入原预约并完成一次有效改期|旧记录仍保留，真实新预约存在；有同源回跳及直接前后继链接|
|FC-03|返回原出诊|结果重新计算；不是把点击原操作当完成|
|FC-04|保留一条未处理预约，其他记录多到分页|仍显示阻断，不能因当前页只含历史而判清空|
|FC-05|有效邀约等待、过期、接受后三个状态|保留/到期/正式预约分别解释；已接受不再算第二份邀约占位|
|FC-06|有已到诊或完成记录|明确保护，不鼓励为了清空而取消；原业务规则不变|
|FC-07|读取后另一人创建新预约|刷新显示新阻断；主管旧维护不能绕过后端复核|
|FC-08|只读模式、跨店URL、换身份、任意coord_slot链接|授权读取允许；无业务写入，越权拒绝，不开放任意跳转|
|FC-09|临时读取失败|结果未知，不宣称原操作失败，不自动重提|

真正升级仍需保存私密备份、带数据副本核对；累计更新包只是文件差异，不证明数据升级成功。`UPGRADE_V09_WINDOWS.cmd --after-isolated-pass`的参数只是显式确认，不是测试证明。
