# WorkBuddy 第二批小程序运行验收

校验工程 → 读取双账号样本 → 查号与一次提交 → 结果回查 → 设备证据。

## 本机开始条件

- 打开下载目录中的 `ADC系统试用/WorkBuddy_第二批运行验收_18476` 或解压同名 ZIP。在工程根目录运行 `python3 检查环境.py`，并使用包内 `VERSION.json` 和 `CHECKSUMS.sha256` 核对工程、后端提交与镜像。
- 导入包内 `微信小程序`。唯一联调地址为 `http://127.0.0.1:18476`，连接独立二十店合成库。
- 固定私有指南位于 `/Users/zhang/Downloads/ADC系统试用/第二批运行验收_私有试用/账号指南.txt`。内有 A、B 两名患者、本人和他单编号、服务与查询步骤。按工具的敏感读取流程使用。指南保存在 ZIP 外。
- 如环境检查失败，先启动 Docker Desktop，再按包内就绪说明仅启动列出的既有隔离服务。仍失败或私有指南读取未获批准时，单列缺项，完成能执行的编译与设备查看，一次回传具体失败步骤。

## 一次完成的操作

| 编号 | 正常操作 | 预期 |
|---|---|---|
| WB2-01 | 校验包、导入、编译，按指南使用原账号密码登录 A | 27 页可编译，首页及就诊人正确，基础库版本与模拟设备可记录 |
| WB2-02 | 选指南指定门店与服务，查询未来可约日期。用普通点击查看号源、确认页、返回及重新选择 | 门店、服务、日期和选择一致。无号或已占用时有明确下一步 |
| WB2-03 | 在隔离库确认一笔合成预约，保存回执编号，从「就诊」刷新并打开同一记录 | 回执、清单与详情编号一致，同一提交只有一笔预约。结果不明先查询清单，保留原始现象供 Codex 对账 |
| WB2-04 | 用 A 和 B 分别读自己的既有预约，再用 B 打开 A 的已知编号。退出后检查页面 | 本人可读，他单显示通用拒绝，无预约内容及旧账号残留。既有样本保持只读 |
| WB2-05 | 在当前可用模拟设备检查长门店名、查号与核对页。分别用可选的 375、390、430 宽设备检查字体放大、键盘遮挡、日期选择与返回 | 逐项记录设备、实际设置、点击路径及是否完成。工具缺少能力的项目标待实机 |

WB2-03 只允许新增一笔。请保留预约给 Codex 对账。其余场景使用已准备样本，无需等待实时占位、取消、撤权或新增账号。平台和真机条件就绪后，以固定 HTTPS 和合法请求域名另跑真实微信登录、找店、查号、一次预约及回查。按机型分别记录，开发者工具和手机结果各列一栏。

## 回传

使用版本、设备与业务三栏。版本栏记包内客户端、实测后端、镜像、校验和、基础库。设备栏记模拟或真机、尺寸、字体、键盘与原生手势。业务栏逐项给 PASS、发现问题或待条件，记录新增预约编号及查询编号。截图放私有指南指定目录，公开回传使用必要的状态与汇总。账户密码、会话凭据、患者内容留在私有环境。

WorkBuddy 负责导入及小程序回归，Codex 负责监测、后端、数据与发布。发现明确阻碍患者办理的问题时，附最小复现和相关页面位置。
