# 当前数据库设计与ER图

业务事实 → 真实表与主外键 → 分模块ER → 一致性规则 → 下一阶段优化。

本目录补充当前系统的数据库设计。领域图解释业务概念和责任，ER图解释实际关系表、键和基数；状态图另行解释生命周期。[课程报告](../../课程报告/README.md)第4.13节采用以下四幅ER，第6.2节以[前台排班与数据库设计](../FRONT_DESK_SCHEDULING_PLAN.md)作为下一阶段重点。

## 结构基线与阅读方式

2026-10-20对当前已运行应用进行只读结构核对：69张表，其中68张由ORM描述（含框架及连接表），另1张为`django_migrations`；169条ORM单列关系全部对应真实外键，实际SQL另有1条账单同次就诊复合外键，共170条。运行应用提交为`63c27333f29fec386bc360bbb185680d41ea6e4d`，文档源码基线为`59740f579f6990496f201b9940aed1eb831b2d8a`。

只提取表结构元数据，未导出业务行、凭据、配置值或字段默认值。结构证据见[schema_snapshot.json](schema_snapshot.json)，这不是全库数据质量、岗位迁移、并发或容量的新验收。

字段类型、可空和单列唯一键也已与实际结构逐列核对。一项差异留待设计修正：框架连接表`auth_group_permissions.id`在模型中为integer，实际数据库为bigint；当前字段目录和DBML按实际bigint记录。不为统一图表缩窄已有字段，下一阶段先核对框架迁移来源和正确的模型声明，见[设计优化计划](../FRONT_DESK_SCHEDULING_PLAN.md)。

先按下面的业务问题查看分图，再检索[完整字段目录](FIELD_CATALOG.md)和[170条SQL外键](RELATIONSHIPS.md)。[完整DBML](schema.dbml)便于继续建模；条件唯一、检查、排斥约束的精确定义以结构快照为准，DBML没有替代触发器和业务命令。

## 图例

- 表头为真实表名；PK为主键，FK为外键，UK为单列唯一，`?`为可空列。
- 使用乌鸦脚记法：双竖线表示恰好一个，圆圈加竖线表示零或一个，圆圈加三叉表示零到多个。连线两端表示该关系的基数。
- 选取关键列和关系以便打印；未展开的操作者、诊所及历史引用等仍在完整目录中。颜色仅辅助区分表头，黑白打印仍可阅读。
- 条件唯一不标成永久一对一：资源方案、凭据和对账均能保留多次历史。必需关系或有效占用的状态条件另由实际约束及命令校验。

## 预约与电话接待

![预约与电话接待数据库ER图](er_booking.svg)

接待单的患者和预约引用可空；成约后引用真实预约。沟通记录以`case_id,sequence`唯一排序。诊所、医师和出诊分别建模；前台的岗位权限调整列入下一阶段，不从ER连线推断授权。

## 排班服务与医师适配

![排班服务与医师适配数据库ER图](er_catalogue.svg)

科室属于诊所，诊室和服务属于科室；每周开放区间与医师出诊分别保存。服务—医师多对多由`adc_booking_service_dentists`连接表实现，配对有真实唯一约束。预约服务不作为收费项目。

## 设备位置与资源占用

![设备位置与资源占用数据库ER图](er_resource_claims.svg)

设备资产复用原台账，排程位置是独立一对一绑定。资源方案至少引用预约或邀约之一，接受邀约后允许同时引用二者；不是XOR。替换方案追加历史，每个来源至多一个当前方案；有效资源区间另受`physical_resource_no_overlap`排斥约束。

## 诊疗结算与资金凭据

![诊疗结算与资金凭据数据库ER图](er_finance.svg)

每次就诊至多一个逻辑账单。`invoice_same_visit_fk`用`current_record_version_id,visit_id`共同引用记录版本，保证属于同次就诊；图中两条普通外键不能单独表达这个约束。收退款是多次资金事实，凭据有版本，匹配的活动唯一性按状态限定，不把历史强行压成一对一。设备资金的可选来源、原CSV批次及其他未展开关系见目录。

## 复现与优化

使用文档运行环境执行`python docs/database/build_schema_docs.py`，从保留的结构快照重建DOT、DBML、字段和外键目录；再执行`node docs/database/render_er.cjs`，需要`@viz-js/viz`、Playwright及本地Chrome，导出SVG／PNG。生成器先核对模型关系与实际SQL外键，渲染器再核对每幅图的表、列和连线数量。它们不连接数据库，也不读取私有配置。

当前ER用于排班事实、诊所归属、可空状态、条件唯一、版本链和查询索引的下一轮评审。新增结构须先解释业务问题，再追加迁移及反例测试。原v0.3[物理设计](../PHYSICAL_DESIGN.md)和[字段目录](../FIELD_CATALOG.md)作为历史来源保留，当前设计入口统一指向本目录。
