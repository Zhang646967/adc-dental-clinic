## 当前环境与尝试

本轮实际探测：Linux x86_64、Python3.13.5，缺少Docker、psql/postgres、Django和psycopg。按原依赖下载尝试失败；pypi.org和files.pythonhosted.org域名解析分别失败。

`scripts/verify_isolated.py`已实际尝试，在寻找Docker阶段停止，输出executed=false、all_gates_passed=false。没有连接真实业务数据库，也没有以SQLite替代PostgreSQL验收。

## 本轮审查和修正

- 初次新增基础检查中的两个测试适配错误已修正：只读策略的模块/函数名误写；对包含既有ALL变量的整个路由字典使用literal_eval。改为调用真实策略函数，逐一核对新路由的MANAGER集合，未删减被测断言。
- 手工源码审查发现0/超大出诊编号可能变成未处理的ValueError；已改为与范围外对象一致的拒绝反馈，编写对应框架测试。该HTTP行为仍待真实测试。
- 新分钟提示补充最大年份和零年份边界，避免生成无效的下一分钟字符串；不会静默修改用户填写的结束时间。
- 两次批量浏览器命令受工具执行时限中断；拆为独立执行后完整完成。最终396条结果另有完整日志，不以中断日志当作成功。
- 静态页面图实际查看了桌面出诊详情和390px受阻页面。其余页面经过自动布局/必需元素/转义检查；不是声称全部页面都经过人工用户测试。

## 关键待验证业务性质

1. 与普通预约共用源时段行锁：出诊停用与新预约不能都成功而留下一条引用停用时段的有效新预约。
2. 发布邀约与停用竞争：二者至多有一方按原快照成功。
3. 同源两次替换只有一条新结果；新时段与另一并发新增时段冲突时，原时段停用一并回滚。
4. 所有有效占用、旧快照、越权、只读、过期或异常关联拒绝，不提供患者私密详情。
5. 审计失败、重复确认、历史取消及已接受但后来取消等分支不改写旧预约和账单。
6. 本功能不回收过期邀约，不自动改排或通知；旧草案发布必须重新判断并拒绝无效源时段。

以上是规约与已编写测试目标，不是本轮真实数据库通过结论。

## 复现入口

```text
python -m unittest discover -s checks -v
node checks/test_wait_window_node.cjs
node checks/test_availability_node.cjs
python scripts/check_availability_browser.py
VERIFY_ISOLATED_WINDOWS.cmd
```

浏览器脚本依赖Playwright、Jinja2和Chromium；其运行方法不替代Django。Windows验证入口只依赖Docker，并使用隔离临时库；不读取原业务.env或原卷。

本目录`evidence_v09a6`保存最终unit_final.log、browser_debug.log、Node日志、旧页面回归日志、environment.json、isolated_attempt.log、model_migration_hashes.json。validation_scope.json按层次记录可复查状态。

文件重组和SHA-256校验是包完整性证据，不是作者数字签名，不是数据库升级成功证明。测试定义数量、断言数量不能相加当成通过的业务场景数或需求覆盖率。
